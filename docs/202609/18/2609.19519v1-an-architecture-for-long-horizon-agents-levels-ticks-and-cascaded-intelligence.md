## 摘要
语言模型智能体正越来越多地被要求执行跨越数天或数周的工作，例如运营修复或研究计划。这类任务的生命周期超过了任何上下文窗口、任何进程以及任何人能够值守的时间间隔。在本文中，我们认为，长时程智能体必须先能够持续运行而不遗忘，然后才能持续学习。这种能力存在于模型外围的运行框架中，而不是模型本身。我们从长时程设定中推导出七个瓶颈，并用一个由三部分组成的层级架构来应对：(i) 按时间尺度索引的层级，每一层维护一个大小受限的文件，用于总结其下一层；(ii) 以时钟节拍作为自主行动的单位；(iii) 级联智能，即只有在评审未通过后，工作才被升级给能力更强的模型。我们报告了一项为期十天的实验活动：一个基于该架构构建的智能体在人类每天仅查看一次的情况下，复现了一项已发表的强化学习结果，并表明：(1) 该智能体在实验活动的每一次上下文重置和会话边界中都保持了任务线索；(2) 早期写入的操作知识改变了后续行为，而模型权重没有发生变化；(3) 学习组件将进入此类系统的位置。总体而言，我们的经验表明，这类智能体的持续学习需要一个比任何上下文和进程都更持久的基底，而运行框架已经执行的检查正是学习器应当所在之处。

## Abstract
Language-model agents are increasingly asked to carry out work spanning days or weeks, such as an operations remediation or a research programme. Such a task outlives any context window, any process and any interval at which a person can attend. In this paper, we argue that a long-horizon agent must run continually without forgetting before it can learn continually. This ability lies in the harness around the model rather than in the model itself. We derive seven bottlenecks from the long-horizon setting and answer them with a hierarchical architecture of three parts: (i) levels indexed by time scale, each keeping a bounded file summarising the level below; (ii) a clocked tick as the unit of autonomous action; and (iii) cascaded intelligence, where work is escalated to a more capable model only after failing review. We report on a ten-day campaign in which an agent built on this architecture reproduced a published reinforcement-learning result with a human attending once a day, and show (1) the agent kept the thread across every context reset and session boundary of the campaign, (2) operating knowledge written early changed later behaviour with no change to model weights, and (3) where learned components would enter such a system. Overall, our experience suggests continual learning for these agents needs a substrate outliving every context and process, and the checks the harness already runs are where a learner belongs.

## 1. 核心问题与研究动机

- **背景**：语言模型智能体已被用于软件工程、研究与运维等多步任务，可维持的任务时程在两年内从分钟级扩展到小时级。但现有部署仍以"回合（episode）"为单位运作：一个上下文窗口用完即停，主动性、跨回合记忆与下一次启动都交还给人类。
- **矛盾**：企业级工作并非这种形状——运维修复会跨越值班班次，合规调查持续一周，研究计划持续数月。更长的上下文与更强的模型只是把回合边界向外推，并未消除它：
  - 上下文压缩（compaction）会**静默擦除**状态与约束；
  - 随任务时程增长，智能体会**偏离目标**；
  - 无论上下文多长，"整个任务（campaign）"总是更长。
- **核心命题**：长时程智能体必须先能**持续运行而不遗忘**（continual operation without forgetting），然后才谈得上持续学习（continual learning）。这一属性属于模型外围的 **harness（运行框架）**，而非模型本身。
- **前置工作不足**：记忆架构决定跨会话记住什么；层级智能体做子目标分解；模型级联按出错代价路由到更强模型；自主研究智能体端到端跑完整活动；持久化执行（durable execution）能比进程更长寿但没有"该保留什么"的概念。**没有任何一项回答：当上下文、进程与注意力同时终结时，什么必须存活下来。** 这是一个架构层面的空白。
- **七大约束（bottlenecks）**：在前提 C, P, A, F ≪ H（上下文窗口、进程寿命、人类关注间隔、组件失效间隔都远小于任务时程）且高自主性、预算 B 有限的设定下：
  - 由四个阈值而来：**Autonomy**（A ≪ H）、**Horizon**（C ≪ H）、**State**（P ≪ H）、**Resilience**（F ≪ H）；
  - 由规模而来：**Delegation**（工作量超出单一进程）；
  - 由两个轴共同而来：**Correctness**（无人逐步检查，错误累积且证据被压缩掉）、**Cost**（顶层模型开销正比于 H，受预算 B 封顶）。

## 2. 方法论：核心思想与关键技术细节

### 2.1 四个抽象及其关系

- **Level（层级）**：按行动的时间尺度索引的层，每层保留一份**有界状态文件**总结其下一层，并向下一层发出**稀疏指令（directives）**。
- **Tick（时钟节拍）**：判断力所在层级的自主行动单位——驱动者（driver，运行循环的判断层会话）从读状态到写回状态的一次唤醒。
- **Protocol（协议）**：具有指定**写入者、读取者、节奏（cadence）与检查方式**的命名文件；每条通道与每一份持久状态都是一个协议。
- **Tier（智能层级）**：三层智能——判断（judgment）、劳动（labor，分 routine/strong，其会话称 worker）、确定性进程。**层级越高，tier 越高。**

### 2.2 七层时间层级（图 2）

| 层级 | 角色 | 时间尺度 | 保留的有界状态 |
|---|---|---|---|
| L0 | tool call | 秒 | 原始日志、trace、指标 |
| L1 | labor turn | 分钟 | 会话日志、每次试验的进展 |
| L2 | steering | 30–60 分钟 | 指令：评估、下一次试验 |
| L3 | tick | ~1 小时 | checkpoint（≤8k 字符）、journal |
| L4 | gate review | 5 ticks / gate | 评审备忘、gate 裁决 |
| L5 | human day | 1 天 | 日报（≤1,500 字符） |
| L6 | goal | 1 周 | 目标、规格说明、预算 |

- **向下通道**传递 *steering*（发送者节奏的稀疏指令）；**向上通道**传递 *back-pressure*（压缩状态 + 升级行、监控器提出的待关注项、以及 **kill verdict 终止裁决**——唯一不压缩跨边界传递的消息，因为压缩恰恰会把它藏起来）。

### 2.3 七类机制族（对应七个瓶颈）

- **Autonomy**：主动性必须被"制造"出来。时钟启动新的 driver 会话并在其退出前所写的间隔处休眠；tick 读取状态、应用所有**预注册规则**、决策、行动、写回状态；**hook 拒绝在 checkpoint 写回前结束会话**；主责人（principal）的回答作为 **standing decisions** 在每次唤醒时被读取，使智能体能在人类缺席时继续推进。
- **Horizon**：用按时间尺度索引的抽象处理数天级时程；driver 从不读原始输出。硬规则：**任何日志或源码最多读 40 行**，其余委托并摘要。
- **State**：任何东西都不能只活在上下文中。每层状态是文件，大小受限以便上层读得起，**原地重写**以描述当下，每个数字都标注来源文件。**resume 协议**在每次会话开始与每次 driver 上下文压缩后运行：先 checkpoint，再 standing decisions、plan、open unknowns、active experiment cards；**若追加式 journal 比 checkpoint 新，则以 journal 为准**。
- **Delegation**：工作以**契约（brief）**下行、以**证据**返回；决策上行直至主责人。brief 是一个文件：任务、目标、tier、要读的文件、约束、返回什么。开放式工作加入两个文件：worker 写 **PROGRESS**（试验前写计划、试验后写实测结果），driver 按 steering 节奏写 **DIRECTIVE**（数据支持哪个假设、下一步试什么），worker 每次行动前重读。决策沿**阶梯**上行，每级有明确触发条件：routine labor → driver 自评 → strong-tier 会话 → 主责人（仅限列明类别的决策）。
- **Correctness**：验证必须**预注册、被测量、且放在结果不会丢失的位置**。每个实验卡片含假设、成功判据、早停规则、资源上限与随机种子，driver 每个 tick 应用该规则，因此 **kill verdict 就是一个摘要里的比特位**。只有当**regime 条件是被测量而非被请求**时（如实测 staleness），运行才算可比。**对抗式评审员（adversarial reviewer）**是一个无对话历史的判断层会话，在每个 gate（消耗算力前或提出结论前的预注册检查）读取计划与证据：哪些混杂因素未闭合、代理指标是否真的度量了主张、该杀什么。
- **Resilience**：每个组件在数天中至少失败一次，**包括智能体自己的会话**，因此恢复不能依赖注意力。每层有上一层的检测器与**无需判断力的恢复**：停滞 worker 重新 brief，死掉的 driver 由 watchdog 从 checkpoint 恢复（多次重启后停机）；探针（probe）作为**所观测作业的步骤**运行，绝不作为登录。
- **Cost**：最强模型只接触最压缩的状态；tier 迁移规则是 **review-and-escalate**（图 3）：在**最低可行 tier** 上做工作 → 由**上一层 tier 评审** → 失败则以反馈返回重试 → **再次失败才升一级**，直至主责人。strong tier 的分配依据是**出错的代价**而非任务规模；阶梯是对称的——一旦 strong tier 找到配方（recipe），后继者在 routine tier 带配方执行。会话每隔若干 tick 轮换，使新会话只读短 checkpoint；**确定性 pre-tick digest** 在无事可做时跳过唤醒。

### 2.4 两个弱于"学习"的性质

- **不遗忘（no forgetting）**：智能体所需的一切都不在上下文中；driver 因压缩、轮换或 watchdog 被重置数十次，每次都从文件恢复。
- **累积（accumulation）**：某一层写下的运行知识会在余下活动中改变下层行为——主责人的回答变成 standing decisions，评审发现变成后续卡片上的预注册规则，strong tier 找到的配方下发到 routine brief，反复出现的 worker 失败先成为每条 brief 的规则、再成为 harness 的守卫。

## 3. 实验设计

- **任务场景**：复现一项已发表的异步强化学习结果（Hou et al., 2026）——在陈旧 rollout（从旧策略采样）上训练的策略会**越过 staleness 阈值后崩溃**，而**解耦的重要性采样修正**能保持稳定，需在**两个模型规模**上验证。
- **任务被选中的理由**：具备企业级活动难以处理的特性——可验证的结果、共享基础设施、固定预算、每天只关注一次的主责人、以及**不会自我宣告的失效模式**。
- **五个带 gate 的阶段**：① 环境 bring-up；② 小规模下跨种子的 stability pair（未修正 vs 修正）；③ 在 steered labor 下找到大模型单节点配方，并做该规模的 stability pair；④ 移植到第二套框架，以**实测而非请求的 staleness** 验证，并优化到用**一半训练硬件**复现同一结果；⑤ effectiveness 对比（完整方法 vs 对照），在经四个评审 gate 重新设计的标定环境上进行。
- **Benchmark 性质**：**本文没有使用标准 benchmark，也没有与其他智能体架构做对照实验。** 评价对象是一个为期十天的单次真实活动（existence proof，存在性证明），而非受控基准。
- **对比方法**：仅有复现实验内部的**方法 vs 对照（control）**两个实验臂，以及未修正/修正策略的对比；**没有**与记忆架构、层级智能体、模型级联等架构类工作的横向比较。
- **三个说明性案例（vignette）**：
  - *Steered labor*：大模型需在单节点训练，三个无 steering 的 worker 会话都止步于 958 秒/步且无诊断；driver 写下六个带预测与守卫的排序假设，并以 30 分钟节奏写 directive，一个受限会话内步时降至 180 秒且配方在未用 strong tier 的情况下保持稳定。
  - *评审员*：effectiveness 对比饱和时，driver 委托构建更难的 task mix，评审员先读到它，发现了一条**无需真正解题即可满足验证器**的路径与两类模型可走的捷径，mix 被重建；后来评审员又发现某计划中的停止规则会把一个实验臂与其对照的**瞬态下探**相比，规则在结果被记录前被改写。
  - *累积*：监视运行中作业的 worker 不得在作业结束前结束自己的回合，否则节点会空转到下一个 tick。第一次该规则写进每条 worker brief；第二次它变成 harness 的 **stop guard**，拒绝结束拥有活跃运行的 worker，该失效未再出现。

## 6. 主要结论与发现

- **架构可行**：基于 level / tick / protocol / tier 的 harness 能让智能体在人类每天只看一次的条件下自主运行十天，复现已发表的 RL 结果——两个规模上未修正策略越过 staleness 阈值崩溃、修正策略保持稳定，完整方法在标定环境上先于对照达到上限。
- **跨重置保持主线**：智能体在活动中的**每一次上下文重置（47 次）与会话边界后都保持了任务线索**，所有关键信息存在于文件而非上下文中。

- **累积而非重新学习**：某一层写下的运行知识会改变下层后续行为，形成"规则化"路径——worker 反复出现的失效先被写进每条 brief，再被固化为 harness 守卫；strong tier 找到的配方下发给 routine brief 后，routine 会话即可稳定复现。这使系统在数十次会话轮换后仍表现为**同一条主线在推进**，而不是每次从零开始。
- **判断力可以放在无历史的会话里**：对抗式评审员不带对话历史、只读计划与证据，却在 gate 处发现了"无需真正解题即可满足验证器"的路径、模型可走的捷径，以及会把实验臂与其对照的瞬态下探相比较的停止规则。说明**预注册 + 独立评审**能在一定程度上替代人类逐步检查。
- **失效模式不会自我宣告**：任务选择本身就把"不自我宣告的失效"作为考察对象；三个 vignette 表明，若没有预注册判据、实测 regime 条件与 kill verdict 这类机制，此类失效很可能被压缩掉或不被察觉。
- **总体定位**：作者将其结论限定为**存在性证明（existence proof）**——在给定前提与预算下，这套 harness 结构可以让长时程活动持续运行、跨重置保持线索、并在受控环节内保持方法学严谨；但**不足以证明该架构在一般情形下优于其他架构**。

## 7. 局限与开放问题

- **外部效度有限**：
  - 单一任务域（异步 RL 复现）、单次部署、10 天日历跨度，与论文自身主张的"数周—数月"仍有数量级差距。
  - 任务具备可验证结果与明确成功判据；对**成功判据本身模糊**的开放域任务（如战略研究、合规调查），预注册与 gate 的可操作性未被检验。
- **缺少因果归因**：无消融实验，因此无法判断七个瓶颈中哪一个（或哪几个）是决定性的；也无法区分收益来自架构设计、来自预注册纪律、还是来自主责人的高质量输入。
- **缺少横向基线**：未与记忆架构、层级智能体、模型级联、持久化执行框架，或"长上下文 + 压缩"的朴素方案比较，因此"架构层面的空白"这一论断未被实验证伪。
- **人类依赖仍重**：standing decisions 需要主责人预先给出；9 项决策仅主责人可做；预注册规则、预算与成功判据仍由人类设定。**主动性被"制造"出来的同时，也被人类的缺席预设所约束。**
- **统计与偏差**：三个 vignette 为挑选出的定性证据，存在选择偏差与幸存者偏差；没有重复运行、没有置信区间、没有失败活动的报告（例如未达到目标的活动如何收场）。
- **学习维度缺失**：论文明确只主张"不遗忘"与"累积"两个弱于学习的性质；**持续学习（更新模型或策略本身）不在范围内**，累积目前只发生在文件、规则与 harness 守卫层面。
- **成本模型未展开**：只给出 GPU-hours 上限与 routine/strong 配比，缺少对 tick 开销、会话重启开销、评审开销随任务时程如何伸缩的分析，因而"顶层模型开销正比于 H 但受 B 封顶"这一设计目标缺少实测曲线。
- **可复现性**：文中未说明 harness 是否开源、协议文件格式是否标准化；若不可复现，则 existence proof 的可检验性受限。
- **安全与治理**：kill verdict、watchdog 停机、stop guard 等机制是**工程性安全阀**，不构成对齐保证；当主责人每天只介入一次时，误判的代价与回滚路径未被讨论。

## 8. 可迁移的设计原则与启示

尽管证据强度有限，论文提供的几条设计原则对构建长时程智能体具有独立价值：

1. **状态外置优先于上下文延长**：上下文是缓存，不是存储。凡是必须存活的东西都应写成有界、有写入者/读取者/节奏/检查方式的**协议文件**；上下文压缩只应丢弃可重建之物。
2. **用时间尺度而非功能模块来分层**：L0–L6 的索引轴是"多久变一次"，这使得每层只需读下一层的**有界摘要**，从结构上避免"整个任务总比上下文长"的问题。
3. **向上压缩、向下稀疏**：back-pressure 传压缩状态与升级项，steering 传稀疏指令；**唯一不压缩的消息是 kill verdict**——因为它一旦被压缩就会被藏起来。这条"例外设计"值得单独记住。
4. **验证必须预注册，且放在结果不会丢失的位置**：假设、成功判据、早停规则、资源上限、随机种子在实验开始前写下，终止因此变成一个**摘要里的比特位**，而不是需要重新推理的判断。
5. **恢复不能依赖注意力**：每个组件在数天内都会失败，包括判断层自己的会话。恢复路径（重新 brief、从 checkpoint 重启、watchdog 停机）必须**无需判断力**即可执行。
6. **按出错的代价分配智能，而非按任务规模**：review-and-escalate 与"最低可行 tier"使昂贵模型只接触最压缩的状态；配方一旦找到就下沉到 routine tier，形成对称的阶梯。
7. **让知识固化成基础设施**：把反复出现的失效从"brief 里的一条规则"提升为"harness 的守卫"，是这套架构中**最接近学习**的机制，也是成本最低的改进路径。

**一句话评价**：论文的贡献不在于证明了这套架构更好，而在于**把"长时程"从一个模型能力问题重新表述为一个 harness 架构问题**，并给出了一个可运行的、带具体数字与失效案例的存在性证明；其最大不足是缺少消融、基线与重复实验，因而目前更像一份**设计宣言 + 工程日志**，而非可推广的实证结论。
