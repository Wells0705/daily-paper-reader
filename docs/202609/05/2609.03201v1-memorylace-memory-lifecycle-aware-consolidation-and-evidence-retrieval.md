## 摘要
长期大语言模型代理必须在交互中保留信息，同时区分重复证据、历史状态、更新和未解决的矛盾。现有的文本记忆系统能够高效检索语义相关的记忆，但往往使这些关系隐含化，而更丰富的结构化方法则通过全局图、层次抽象或反思来建模这些关系，但复杂度更高。我们提出了MemoryLACE（MemLACE），一种轻量级记忆框架，通过稀疏合并、取代和矛盾关系显式建模文本证据的生命周期，同时保留原子自然语言记忆及其来源。MemLACE并非独立检索记忆，而是重构关系感知的证据单元，暴露当前、历史、支持和冲突的证据以供下游推理使用。在BEAM和StructMemEval基准上，使用开放权重和专有LLM骨干，MemLACE在同骨干对比中取得最高整体性能，同时在BEAM上将端到端运行时间相对Hindsight（已报告的最强反思式记忆基线）减少66.6%。消融研究发现生命周期扩展和时间感知是这些增益的主要贡献因素。综合结果表明，显式建模文本证据的局部生命周期足以显著改善长期记忆推理，而无需全面的知识图谱或全局反思。

## Abstract
Long-term LLM agents must preserve information across interactions while distinguishing repeated evidence, historical states, updates, and unresolved contradictions. Existing textual memory systems retrieve semantically relevant memories efficiently but often leave these relationships implicit, whereas richer structured approaches model them through global graphs, hierarchical abstractions, or reflection at greater complexity. We introduce MemoryLACE (MemLACE), a lightweight memory framework that explicitly models the lifecycle of textual evidence through sparse merge, supersession, and contradiction relations while preserving atomic natural-language memories and their provenance. Rather than retrieving memories independently, MemLACE reconstructs relation-aware evidence units that expose current, historical, supporting, and conflicting evidence for downstream reasoning. Across BEAM and StructMemEval, using open-weight and proprietary LLM backbones, MemLACE achieves the highest overall performance in same-backbone comparisons while reducing end-to-end runtime on BEAM by 66.6% relative to Hindsight, the strongest reported reflective-memory baseline. Ablation studies identify lifecycle expansion and temporal awareness as the principal contributors to these gains. Together, the results demonstrate that explicitly modeling the local lifecycle of textual evidence is sufficient to substantially improve long-term memory reasoning without requiring comprehensive knowledge graphs or global reflection.

### 1. 核心问题与研究动机

- **背景**：大语言模型（LLM）智能体需要跨任务、跨会话地保持长期记忆，记住用户偏好、计划、修正、约束和既有事实。然而，新证据可能重复、取代或矛盾已有记忆，可靠的记忆系统不能只做语义相关的文本检索——它需要处理信息*关系*随时间的演化。
- **核心问题**：如何在不过度增加系统复杂度的前提下，让记忆系统显式区分并保留“重复证据”“历史状态”“已更新状态”与“未解决的矛盾”，使下游推理能同时看到当前证据与历史/冲突证据？
- **现状权衡**：平面文本记忆系统（如 SimpleMem、Mem0）存储和检索高效，但记忆之间的关系是隐式的；知识图谱、层次抽象、全局反思等方法能显式建模关系，但需要构建全面的全局结构，复杂度和成本高。
- **核心论点**：显式建模“证据的局部生命周期”（而非构建全局知识图谱或全局反思）就足以显著提升长期记忆推理效果。

### 2. 方法论

#### 2.1 总体框架
MemoryLACE 是一种轻量级中间方案，介于平面文本记忆与全局结构化记忆之间。其核心思路：**保留自然语言原子记忆及其来源，并通过稀疏的局部关系（合并、取代、矛盾）连接相关记忆**。系统分为两阶段：**记忆构建与整合**（写入路径）和**证据检索与上下文构建**（读取路径）。

#### 2.2 记忆表示
每个存储的记忆条目定义为元组：
**mi = (xi, τi, zi, pi, ai, Ri)**

| 字段 | 含义 |
|---|---|
| xi | 原子自然语言陈述（单条明确事实/偏好/计划等），可在脱离上下文情况下独立理解 |
| τi | 证据支撑的时间元数据（事件时间、有效期等） |
| zi | 轻量元数据（实体、关键词、主题、位置等） |
| pi | 来源（provenance），即支撑对话轮次标号 |
| ai | 是否活跃（active） |
| Ri | 生命周期关系引用集合（合并、取代、矛盾） |

整体存储构成稀疏关系图 **G = (M, E)**，其中 E 包含有向取代边和对称的合并/矛盾链接。与通用知识图谱不同，MEMLACE 只存储理解证据所需的局部关系。

#### 2.3 阶段一：记忆构建与整合
- **记忆构建**：使用 SimpleMem 的轻量滑动窗口方法，将重叠的对话窗口转换为独立的原子记忆；重复提取的重复项被折叠并合并来源，来自不同轮次的真正重复保留为可合并的不同条目。
- **候选与关系选择**：按时间顺序执行整合。对每个新记忆：语义相似搜索 + 同实体匹配 → 扩展至一跳生命周期邻居 → 交叉编码器重排序 → 整合模块选出唯一关系策略：
  ```
  R = {merge（合并）, update（取代）, contradict（矛盾）, no action（无操作）}
  g(mnew, C(mnew)) → (r, c*)
  ```
  单次只做单一关系决策使模型更可靠；遗漏的关系由后续批量演化步骤修复。
- **生命周期状态更新**：默认策略下：
  - **update**：旧记忆变为不活跃，新记忆成为“活跃链头”；新旧建立双向取代链接。
  - **contradict**：矛盾记忆保持活跃（矛盾未解），对称链接。
  - **merge**：默认“链式合并”保留原文与来源、加双向合并链接（信息不丢失）；备选“紧凑合并”则合成一条新记忆替代旧条目。
  - 被取代的记忆不参与常规活跃检索，但仍保留在存储中，可通过关系恢复。
- **局部批量演化**：每组新记忆加入后，联合审查其候选集，修复只在该组记忆中才显现的额外关系（不重写文本、不添加内容）。

#### 2.4 阶段二：证据检索与上下文构建
**流程**：
1. **混合活跃记忆检索**：对活跃记忆做语义、关键词、结构化模板、主题的相关性检索，使用**RRF（倒数排名融合）** 合并多路列表。只搜活跃记忆，避免被取代条目的干扰。
2. **生命周期扩展**：沿取代链追溯历史状态，沿矛盾链提取直接冲突证据，**仅做局部扩展，非全图遍历**。扩展定义为 Eq = Aq ∪ L(Aq)。
3. **证据单元构建**：在检索池内，以取代/矛盾/合并关系将记忆组织为证据组件；按取代链时间排序展示“早期→最新”；矛盾保留并存；先分组后重排序。
4. **链感知重排序与上下文打包**：以证据单元为单位进行重排序，按上下文预算选择最高分数单元；保留完整证据单元并维持更新链从旧到新的排列。
5. **证据基础答案生成**：上下文按生命周期顺序呈现，使模型明确区分当前、被取代、冲突的证据。

### 6. 主要结论与发现

1. **性能方面**：在同骨干比较下 MEMLACE 在 BEAM 整体平均上远超所有基线（4B：45.4% vs Hindsight 40.1%；9B：51.9% vs Hindsight 50.3%）；在 StructMemEval 整体上超 Mem-Agent 约 17 个百分点（52.08% vs 35.00%），其中状态追踪 100% vs 57%、树推理 100% vs 50%。
2. **效率方面**：相对最强反思式基线 Hindsight，端到端运行总时间降低 66.6%（约 3 倍加速），收益主要源于省去全局反思阶段，改用有界比较和局部批量修复。
3. **消融发现**：
   - **生命周期扩展（−5.16%）**：移除后知识更新（51.9→35.0）、多跳推理（55.3→42.3）、时间推理（26.3→13.8）受损最重，说明连通性决定“哪些记忆被一起检索”；
   - **时间感知（−4.97%）**：移除后矛盾消解（40.3→26.6）、偏好遵循（84.4→75.6）、时间推理（26.3→16.3）显著下降，说明时间定位决定“变化被解读为矛盾还是有序更新”；两者作用不可互换；
   - 合并策略的对比中，默认“链式合并”保留原文和来源，优于具有副作用（丢失多跳信息来源）的“紧凑合并”；
   - 组合移除后整体下降 8.55 个百分点，集中在更新/矛盾/多跳/时间推理上。
4. **核心结论**：长期记忆的关键瓶颈并非更丰富的全局结构，而是**保留证据随时间的演化方式**。显式建模局部证据生命周期即可恢复大部分由重型记忆架构实现的推理收益。

### 7. 优点与亮点

- **轻量且可解释**：利用稀疏的局部关系表达记忆演化，不引入全局归一化知识图谱或全局反思层，有较好的可解释性与可检查性。
- **保持原子记忆与来源**：不丢弃原始证据（默认策略），每个原子记忆可追溯对话轮次，支持关系连接与证据溯源；合并/取代不会覆盖原信息。
- **检索对生命周期感知**：检索到的不是孤立切片，而是“证据单元”（当前 + 历史 + 冲突 + 支持），这在多跳、偏好、事件排序、知识更新等需要相关记忆联合解释的任务上直接获益。
- **有界、增量式决策**：记忆整合中的单关系决策 + 批量局部修复的设计，兼顾可靠性（一次只处理一个重要决策）和完整性（组间关系可被修复）。
- **以效率为前提的设计**：将时间元数据写作显式领域，支持区分有序变化与真正的矛盾，低成本带来大增益。
- **清晰的消融实验设计**：逐一移除组件并联系到失效类别，说明了各组件的功能定位与互补性。

### 8. 不足与局限

- **Benchmark 覆盖范围有限**：主基准使用 BEAM 100K 子集（20 个对话、400 问），未覆盖该论文所称 BEAM 更大规模文本的情况；StructMemEval 使用 51 场景主集，验证场景总数偏少。未见跨任务的更长对话（>100K）场景。
- **对特定能力仍较薄弱**：在时间推理、摘要、信息提取方面，9B 骨干上落后 Hindsight 分别达 8.7、5.2、4.9 个百分点；在计数推理上二者均为 0 分且未通过（部分场景下推荐能力也远低于 Mem-Agent）；结构化和数学/聚合类推理能力缺乏聚合算子，导致推荐与计数任务表现不佳。提示系统需要专门的聚合、计算或代码执行工具。
- **可能存在的偏差风险**：同一 Judge（GPT-4o mini）在部分问题上的评价可受提示和骨干差异影响；未见 Human Evaluation；使用 Fixed Judge 且为长文本生成式回答打分时可能引入系统性偏差。
