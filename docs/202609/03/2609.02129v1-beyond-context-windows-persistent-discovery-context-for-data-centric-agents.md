## 摘要
数据中心的代理在规划或执行之前会重复执行一个发现步骤：识别与任务相关的数据对象。然而，成功的发现结果通常被丢弃而非复用。我们引入了持久发现上下文，一种轻量级记忆层，它存储先前的意图到对象的映射，并复用它来增强未来的检索。在三个结构化数据环境中，持久发现上下文始终优于基于元数据的搜索，即使在自动生成的记忆中也能保持有效性，并暴露出可复现的干扰失败模式。在词汇稀疏的领域，仅基于记忆的检索甚至可能优于基于元数据的检索。这些发现表明，发现结果构成了一种对数据中心代理有用的可复用上下文形式。

## Abstract
Data-centric agents repeatedly perform a discovery step before planning or execution: identifying the data objects relevant to a task. Yet successful discovery outcomes are typically discarded rather than reused. We introduce persistent discovery context, a lightweight memory layer that stores prior intent-to-object mappings and reuses them to augment future retrieval. Across three structured data environments, persistent discovery context consistently improves retrieval quality over metadata-only search, remains effective with automatically generated memories, and exposes a reproducible interference failure mode. In lexically sparse domains, memory-only retrieval can even outperform metadata-based retrieval. These findings suggest that discovery outcomes constitute a useful form of reusable context for data-centric agents.

## 1. 核心问题与整体含义

### 研究动机
- **数据为中心的代理（data-centric agents）** 在规划或执行之前必须完成一个关键步骤——**发现（discovery）**，即识别出与当前任务相关的数据对象（表、属性等）。
- 尽管不同任务常常需要相似的表格和属性，现有系统通常将发现视为**一次性操作**：成功识别出的对象被使用后即被丢弃，未能在多次任务之间复用。
- 已有代理记忆系统涵盖对话内容（如 MemGPT）、观察与反思（如 Generative Agents）、技能（如 Voyager）和工作流（如 Agent Workflow Memory），但**从未将“发现结果”视为需要持久化的记忆类型**。

### 整体含义
该论文提出一个核心问题：**成功的发现结果是否应该跨任务持续保留？** 这项工作探索了一条新的记忆维度——将**意图-到-对象（intent-to-object）映射**作为轻量、可复用的上下文加以维护，从而帮助数据代理在后续任务中更高效地定位相关数据。

### 背景定位
- 与 KAT-SQL 等知识增强的 Text-to-SQL 或 DataHub 等元数据目录不同，该研究方向并非关注模式链接、查询生成或元数据管理，而是关注**发现结果本身是否可以被作为第一级记忆对象被保存和复用**。
- 这一概念与信息检索中的**相关性反馈（relevance feedback）** 有概念上的联系，但区别在于：发现记忆使用代理生成的对象选择信号，而非用户交互信号；同时它跨任务传递，而非仅细化单个查询。

## 2. 方法论：核心技术要点

### 核心思想：持久发现上下文
论文提出**持久发现上下文**，本质是一种轻量级记忆层，逻辑上位于数据目录（registry）级别。

### 发现记忆（Discovery Memory）的定义
- 一条发现记忆定义为形如 **m = ⟨intent, objects⟩** 的映射：
  - `intent`：自然语言形式的任务描述。
  - `objects`：与该任务意图相关的数据对象集合。
- 记忆在目录层持久化，并在同一数据环境内随任务数量累积。
- 初始记忆来自人工标注的种子任务；后续跨任务检索时持续复用。

### 记忆增强检索（Memory-Augmented Retrieval）
给定一个查询 `q`：
1. 目录检索先产生每个候选对象的**基础相关性得分 r(q, oᵢ)**——可使用 TF-IDF、BM25 或神经网络编码器等文本检索器。
2. 检索**最相似的 K 条发现记忆**（K = 5）。
3. 通过融合公式生成**最终得分 score(q, oᵢ)**：

```
score(q, oᵢ) = r(q, oᵢ) + α · Σₘ∈top-K  sim(q, m.intent) · 1[oᵢ ∈ m.objects]
```

其中 α 是控制记忆影响力的权重，1[·] 为指示函数，判断对象是否出现在记忆的相关对象集合中。

### 关键设计特性
- **α = 0** 时，退化为标准目录检索（即 S1 条件）。
- **r(q, oᵢ) = 0** 时，得到纯记忆排序器（即 S2 条件）。
- 记忆相似度使用与目录检索相同的检索模型计算，不额外引入模型。
- 记忆融合是“软”加的平滑增强，而非直接注入式提升，以保护基础检索精度。

## 6. 主要结论与发现

1. **持久发现上下文一致提升检索质量**：
   - TF-IDF 下 S3 相对 S1 的提升：Finance +0.103、NYC +0.183、Northwind +0.082。
   - 神经检索下同样正向：Finance +0.167、Northwind +0.119、NYC +0.051。

2. **记忆极具竞争力，尤其在词汇稀疏场景**：
   - NYC 碰撞领域属性名复杂且词汇不透明（如 `contributing factor vehicle 1`），TF-IDF 下 S2 记忆单独检索（0.412）超过目录检索 S1（0.299）。
   - 神经检索下，Finance 和 Northwind 甚至出现 S2⋆ > S1⋆ 的反转。

3. **LLM 自动生成记忆仍有效**：
   - 对象级 F1 对齐指标为 0.698 / 0.762 / 0.735（Finance / NYC / Northwind）。
   - 仍有两个领域超过 S1 基线，三个领域都超过 S0 基线。

4. **记忆干扰是一个真实可复现的失败模式**：
   - 当错误语义族的内存被激活时，效果低于无记忆基线（如 Northwind 从 0.444 降至 0.000）。

5. **增益非均匀**：独特对象词汇、稳定的意图-对象关系家族增益大；对象跨类型重叠多的家族（如客户画像、产品目录）出现负增益。

6. **α 消融显示：** 两个检索器共同在 α = 0.25 峰值最优，权重过大会全面降低性能——证明记忆辅助而非取代基本检索是正确的策略。

7. **软融合优于直接注入**：S3 优于 S4，保留基础检索精度。

## 7. 优点

- **问题切入点新颖**：在普遍关注对话或经验记忆之外的文献浪潮中，识别并研究了“发现结果”作为记忆形态的重要性。
- **方法极简且优雅**：只用一条公式即可融合基础检索与记忆——轻量、即插即用、无训练成本，容易做工程落地。
- **术语和边界定义清晰**：意图、对象、发现记忆、α 调节、S2/S3 分离等概念定义明确。
- **结论表达克制且辩证**：不只报告正利润，还明确展示失败的干扰模式及负增益的任务族，给出真实边界条件。
- **鲁棒性考核较为全面**：同时考虑不同检索器、不同种子、自动生成内容错误等因素，而非只验证理想设定下的增益。
- **附录信息密度非常高**：将权重扫描、LM 生成结果、BM25、种子鲁棒性等关键细节全部完整收录，规范化程度好，便于复现。
- **下游可解释性演示加分**：通过一个真实规划对比展示检索上下文如何改变计划质量，做法直观、有启发性。

## 8. 不足与局限

### 实验覆盖方面的不足
- **规模偏小**：虽然跨了三个领域，但每个领域仅 5 个任务族，单个数据点波动对结论影响较大。
- **真实数据环境的多样性不够**：数据结构都是关系型目录，未覆盖 NoSQL、数据湖、图数据库，无法验证这类方法在更复杂数据类型上的普适性。
- **词汇稀疏的定性判断缺乏量化指标**：如文本属性的平均词汇重叠度、词频分布指标等尚缺。
- **LLM 记忆生成仅覆盖一种模型**（Claude Haiku），不同模型的推理质量差异尚未分析。
- **干涉实验只构建 3 个实例**，说服力有限。

### 方法与假设上的局限
- 记忆从“人工标注的种子”启动，未深入讨论冷启动问题和多数据环境的迁移策略。
- 假设一个任务对应一个已知记忆族；在真正开放的任务分布下相似度计算可能失效。
- α = 0.5 为固定默认，虽经消融证明鲁棒，却无自适应调节策略。
- 未比较更复杂的记忆构造方式（如 SQL 用户行为跟踪、人工反馈、模拟轨迹记忆等）在这一小任务上的收益差距。

### 偏差风险
- 描述生成与任务族定义都基于人工背景知识，同一批研究人员生成的不确定性是否对结果有倾向性影响是调研盲点。
- 评价局限于“检索指标”的自闭环测试，对代理真实执行任务（如生成 SQL 计划和执行成功与否）只有一例定性演示，尚缺乏系统端到端验证。
- 系统评估只使用检索质量指标（R@5 等），没有针对代理下游生成质量、执行准确率、时间成本进行定量比较。

### 应用限制
- 本文没有真正绑定到上下文窗口压缩与扩展的问题，虽符合工作坊主题，但如果面向真正“上下文窗口之外”的应用，需要进一步讨论记忆管理与窗口状态的有效融合策略。
- 同时，现实系统往往有权限治理、数据版本变化和对象删除等问题，发现结果对象的生命周期维护在此框架中尚未划分。

## 总体评价

该论文提出了一种轻量、可插拔的“发现记忆层”，将曾经一次性的数据对象发现升级为跨任务的持久上下文。方法设计聚焦且简单，评价相对客观（承认负例并逐一分析），实验完备度较高。虽然在规模、端到端验证和资源记录方面有进一步提升的空间，但其提出的**发现结果本身就是重要记忆资源**的核心论点，非常具有启发性和工程价值——为数据代理记忆系统的设计增加了一个有建设意义的新维度。
