## 摘要
长时运行的LLM智能体依赖外部记忆来存储和复用超出单一上下文窗口的信息，然而，交互轨迹的持续积累与有限的上下文容量之间存在根本性的矛盾。因此，智能体记忆的关键挑战不仅在于检索相关记录，还在于在给定预算下选择必要的证据，并以合适的模态进行组织。现有的记忆读出方法主要采用文本或视觉形式。文本保真度高，但其线性token表示使得不同重要性的内容以近乎均等的单位成本争夺有限的上下文。视觉读出将文本渲染为文档式图像，可利用二维布局展示结构并突出关键信息，但在渲染和压缩过程中可能会丢失细粒度细节。为解决这一问题，我们提出了MEMO，一种面向LLM智能体的多模态证据记忆组织方法。MEMO首先使用训练好的证据提取器选择相关记忆块，并形成带有来源信息和呈现要求的证据单元。一个训练好的查询条件记忆管理器将每个单元分配到文本、视觉或双通道载体，并选择与证据结构匹配的布局。然后，一个确定性的记忆构建模块生成文本包和视觉页面。记忆管理器通过离线阅读器的反馈进行训练，该阅读器衡量引导式记忆计划的有效性，从而使保留和呈现决策与下游使用保持一致。我们在HotpotQA、2WikiMultiHopQA、LoCoMo和ALFWorld四个基准上，使用多个阅读器后端评估MEMO。结果表明，MEMO能以更少的记忆令牌更高效地呈现记忆，提升下游任务性能，并在受限预算下构建更有效的工作记忆。

## Abstract
Long-running LLM agents rely on external memory to store and reuse information beyond a single context window, yet there is a fundamental tension between the continuous accumulation of interaction trajectories and the limited context capacity. The key challenge in agent memory is therefore not only to retrieve relevant records, but also to select necessary evidence under a given budget and organize it in an appropriate modality. Existing memory readout methods mainly use textual or visual forms. Text preserves high fidelity, but its linear token representation makes contents with different importance compete for the limited context at nearly uniform unit cost. Visual readout renders text into document-like images, which can use two-dimensional layouts to expose structure and emphasize key information, but it may lose fine-grained details during rendering and compression. To address this issue, we propose MEMO, a multimodal evidence memory organization method for LLM agents. MEMO first uses a trained evidence extractor to select relevant memory blocks and form evidence units with source information and presentation requirements. A trained query-conditioned memory manager assigns each unit to a textual, visual, or dual-channel carrier and selects a layout that matches the evidence structure. A deterministic memory construction module then generates the textual package and visual pages. The memory manager is trained with feedback from an offline reader that measures the utility of the guided memory plan, so that retention and presentation decisions align with downstream usage. We evaluate MEMO on four benchmarks, HotpotQA, 2WikiMultiHopQA, LoCoMo, and ALFWorld, with multiple reader backends. The results show that MEMO presents memory more efficiently with fewer memory tokens, improves downstream task performance, and builds more effective working memory under constrained budgets.

## 2. 方法论

### 核心思想

- 提出 **MEMO（Multimodal Evidence Memory Organization）**，一种查询条件化的记忆读出方法，将原始记忆转为**证据单元（evidence unit）**，再为每个单元选择呈现模态和视觉布局。
- 整体工作流程为：证据提取 → 单元物化 → 记忆管理（模态分配与布局选择）→ 工作记忆构建 → 送入多模态 reader。

### 关键技术细节

- **证据提取器（Evidence Extractor）**：以查询、候选记忆记录和预算为输入，筛选相关源块，并预测关键事实的字符级 span。公式化表达为：
  - (S, H) = Eφ(q, R, B)。S 为相关源标识集合，H 为各源上的关键 span 位置。
- **证据单元（Evidence Unit）**：定义为 ui = (id, xi, hi, si, ci)，其中 xi 是证据内容，hi 是关键 span，si 记录来源，ci 为保留优先级规则（如关键 span 必须文本保真、上下文可视觉化甚至可删除）。证据单元是保留、重排或丢弃的最小操作对象。
- **记忆管理器（Memory Manager）**：为每个单元在动作空间 M = {text, image, dual, drop} 中选择呈现方式；还会为视觉单元选择模板（如卡片、时间线、表格、清单、分栏等）。
  - **text**：保留精确文本锚点，放入文本包 T；
  - **image**：放入视觉页面 V，借助布局展现时间/表格/分组等关系；
  - **dual**：同时以文本和视觉呈现，兼顾语义精度与结构表达；
  - **drop**：从当前工作记忆中省去该单元以节省资源。
- **统一预算约束**：Ctext + Cvis ≤ B，文本和视觉共享同一资源上限。
- **训练方式**：
  - 证据提取器：用四个基准的训练集构建监督标签（各数据集原生证据标注或确定性弱标签），采用全参数 SFT，语言建模损失为 Lext(φ)。
  - 记忆管理器：对同一证据单元构造反事实候选（text/image/dual/drop），由冻结 reader 打分决定胜出标签，同时生成置信度和视觉模板偏好；训练目标是记忆管理计划的 SFT 损失 Lsft(θ)。
- **工作记忆构建**：是确定性模块，按记忆管理器的计划生成文本包（保留来源 id 和内容）、渲染视觉页面，并组装为最终的 reader 输入 a = (T, V)。

## 3. 实验设计

### 数据集与基准（4 个）

- **HotpotQA**：多跳文档问答。
- **2WikiMultiHopQA**：多跳文档问答（多关系推理）。
- **LoCoMo**：超长对话的记忆评测，考察长时间会话中信息的保持与引用。
- **ALFWorld**：具身智能体的交互轨迹记忆，MEMO 被用于预测专家下一动作。
- 统一将四类任务都转换为相同的 reader 输出格式（答题/动作预测），以便计算一致的 Overall 分。

### 对比方法

- **无记忆基线**：No memory。
- **直接控制**：Text-only、Visual-only（无学习式记忆构造）。
- **文本记忆基线**：BM25（词法检索）、Mem-α（强化学习记忆构建）、MemAgent（分段阅读并压缩文本记忆）。
- **视觉记忆基线**：AgentOCR（光学自压缩式历史图像）、MemOCR（布局感知视觉记忆）。

### Reader 与预算设置

- 三种冻结多模态 reader：InternVL3.5-8B、Qwen3-VL-32B、gpt-5.4-mini，覆盖不同规模和来源，以检验方法对 reader 后端的泛化性。
- 两种实验条件：
  - **严格 128-token 统一预算**：强制“文本 token + 视觉 token ≤ 128”，直接比较同等紧约束下的质量；
  - **无截断预算**：在 4096-token 执行窗口内不强制压缩源记忆，但仍然统计实际使用 token 量。
- 指标：归一化精确匹配（EM）和 token 级 F1。

## 6. 主要结论与发现

- **严格 128-token 预算下**，MEMO 在全部三个 reader 上均取得最好的 Overall EM 和 F1：
  - InternVL3.5-8B：比最强基线高 7.30 EM、7.22 F1；
  - Qwen3-VL-32B：比最强基线高 2.35 EM、1.84 F1；
  - gpt-5.4-mini：比最强基线高 2.47 EM、2.81 F1。
- **无汇总预算限制下**，MEMO 平均仅用 **83.93 个 token**，比文本全量（253.89）减少约 67%，比 MemAgent（约 170 个 token）减少约 50%，同时 Overall 指标在所有 reader 上保持第一或第二，并与最高分差距很小（最大 0.43 分）。
- **消融实验**验证两个模块互补：
  - 禁用两个模块：47.49 EM / 57.24 F1 / 126.22 tokens；
  - 仅启用证据提取器：53.56 EM / 66.09 F1 / 70.12 tokens；
  - 完整 MEMO：57.78 EM / 68.62 F1 / 81.07 tokens。
  - 结论：证据提取器贡献了最多的压缩和准确率提升，记忆管理器进一步以少量 token 换取更高的下游质量。
- 总体结论：MEMO 能在相同预算下装载更多有用信息，在宽裕预算下也不会浪费 token；优势跨 reader、跨任务、跨预算条件保持稳定，说明收益来自其记忆管理机制本身而非某个 reader 的偏好。

## 7. 优点

- 以“证据单元”作为记忆处理的最小语义对象，而不是以整段文本或图像为单位，粒度更细、更可控。
- 提出“文本 / 视觉 / 双通道 / 丢弃”的联合模态决策，并用统一预算约束文本与视觉资源，比单一模态方法更灵活。
- 引入 **离线冻结 reader 反馈** 来训练记忆管理器，将“保留与呈现决策”直接对齐到下游任务效用，而非仅优化压缩率。
- 双通道设计保留文本锚点，兼具视觉布局的结构表达力与文本的精确语义保真。
- 实验覆盖多跳问答、对话记忆、具身轨迹三类任务与三种规模/厂商的 reader，验证了跨模型、跨领域的鲁棒性。
- 在“无预算”条件下主动收敛到极小 token 用量，说明系统学会了资源自律而不是盲目最大化上下文占用。

## 8. 不足与局限

- **训练规模偏小**：两个可学习模块仅用 1.5B 模型（Qwen2.5-1.5B-Instruct）作为骨干，复杂记忆规划能力可能受限；大规模 backbone 上的表现未知。
- **LoCoMo 评估覆盖窄**：仅两个完整 held-out 对话，统计效力有限，难以证明长对话记忆上的优势具有普遍性。
- **ALFWorld 评估简化化**：只做“下一步动作预测”，不是端到端具身任务的成功率评测，无法真正反映长期交互中的记忆收益。
- **未报告波动性和显著性**：论文没有给出多次运行的方差或显著性检验，无法判断某些接近的分数差异是否可靠。
- **视觉渲染依赖未充分讨论**：视觉质量、渲染分辨率、OCR 误差对结果的下界影响没有被系统分析；“图像 token 往往被高估/低估”的问题也可能影响预算对齐的公平性。
- **基线公平性留疑**：文本、视觉类基线在 128-token 条件下是否都做了最优适配（如针对自己的模态压缩），文本和图像 token 之间的等价换算规则在不同系统中也未必完全一致，因此跨模态对比仍可能有残余偏差。
- **真实验证环境局限**：没有在真实长时间在线运行的多模态智能体（如网页操作、机器人导航等持续 RL 循环）中验证 MEMO，记忆组织方法在长期运行中的遗忘/迁移行为仍不清楚。
