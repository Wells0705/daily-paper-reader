## 摘要
长期记忆是个性化LLM代理的核心能力。为了支持这一能力，现有的记忆系统使用各种标准来组织信息，例如主题段落或摘要层次结构。然而，我们发现了这些设计的两个主要局限。首先，它们缺乏场景感知：来自无关生活场景的记忆共享同一个检索空间，这会扩大搜索空间并引入跨场景干扰。其次，它们从单一视角编码每条记忆，导致难以检索同一事件的互补视角。在本文中，我们提出了CreaMem架构，通过将记忆划分为多个生活场景记忆来实现场景感知的记忆组织，以减少检索时的跨场景干扰。为了超越单一视角并实现跨记忆协同，每个记忆中的条目从情景视角和特质视角进行双重编码。我们还设计了一种检索时的逐记忆平衡采样策略。在两个长期记忆基准上的大量实验表明，CreaMem在所有评估指标上均提高了问答准确率，尤其在多跳推理性能上提升巨大，验证了场景感知划分和跨记忆协同的有效性。为增强可复现性，我们在公共GitHub仓库中发布了代码。

## Abstract
Long-term memory is a core capability for personalized LLM agents. To support it, existing memory systems organize information using various criteria such as topic segments or summary hierarchies. However, we identify two major limitations in these designs. First, they lack scene awareness: memories from unrelated life scenes share the same retrieval space, which inflates the search space and introduces cross-scene interference. Second, they encode each memory from a single perspective, making it difficult to retrieve complementary views of the same event. In this paper, we propose the CreaMem architecture, which enables scene-aware memory organization by partitioning memory into several Life Scene Memories to reduce cross-scene interference at retrieval. To go beyond the single perspective and achieve cross-memory synergy, entries are dual-coded from both episodic and trait-based perspectives within each memory. We further devise a permemory balanced sampling strategy at retrieval time. Extensive experiments on two long-term memory benchmarks show that CreaMem improves QA accuracy across all evaluation metrics, with particularly large gains on multi-hop reasoning performance, validating scene-aware partitioning and cross-memory synergy. To enhance reproducibility, we release our code in a public GitHub repository.

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 核心思想

CreaMem 的核心主张是：**"记忆如何组织"比"提供多少上下文"更重要**。其设计基于两个认知原则：
1. 记忆沿用户的生活场景（Life/Work/Interest）进行分区；
2. 同一经验被编码两次——在情景记忆中存为时间线条目，在相关场景记忆中存为特质条目。

### 2.2 总体架构

架构由三大模块构成：
- **记忆组件（Memory Components）**
- **记忆存储（Memory Storage）**
- **记忆检索（Memory Retrieval）**

### 2.3 记忆组件

| 组件 | 功能与特点 |
|---|---|
| **Meta Memory Manager（元记忆管理器）** | 作为中心路由器，将每条输入消息分派到一个或多个相关记忆组件；采用"宽进入、严格过滤"策略，分类不确定时触发多个组件以防信息丢失 |
| **Planning LLM（规划器）** | 给定用户问题，选择要查询的记忆组件、输出检索关键词（3–6个）并生成最终回答 |
| **Core Memory（核心记忆）** | 维护跨场景的稳定用户画像（身份、属性、偏好、关键关系等），全文注入提示词；字符上限 2000，90% 容量时自动压缩 |
| **Episodic Memory（情景记忆）** | 存储有时间锚点的事件及其叙事细节；支持需要具体时间/事件锚定的查询 |
| **Life Scene Memories（生活场景记忆）** | 包含三个：Life（个人生活）、Work（工作/学业）、Interest（兴趣/休闲）；每条目为一条场景条件化的特质推断，记录用户在该场景下的行为和偏好。特质保留在场景内，因为用户偏好依赖于场景，跨场景混池会冲淡场景特有模式 |

### 2.4 记忆存储：三步流水线

1. **路由**：Meta Memory Manager 将消息 m 分类到相关组件子集 R(m) ⊆ {Core, Episodic, Life, Work, Interest}；
2. **提取**：每个选定组件 r 使用 LLM 提取器 f^r_LLM 从消息中产出候选条目；
3. **合并/插入**：经由嵌入检索找到最相似的现存条目，由 LLM 判定候选内容应合并入已有条目还是作为新条目插入 SQLite 表。

**各组件条目结构**：
- **情景条目**：
  M^(i)_epi = (eid_i, t_i, a_i, e_i, s_i, d_i, v_s,i, v_d,i)
  其中：eid 为唯一标识，t 为事件时间戳，a∈{user, assistant} 为行为者，e 为事件类型，s 为单句摘要，d 为完整事件上下文，v_s 和 v_d 分别为摘要和细节的稠密嵌入。
- **场景条目**：
  M^(i)_scene = (sid_i, c_i, w_i, v_i)，v_i = f_emb(c_i)
  其中：sid 为场景内唯一标识，c 为提取的特质内容，w∈[0,1] 为 LLM 赋予的重要性分数，v 为内容嵌入。

### 2.5 记忆检索

- **记忆选择**：规划 LLM 选出要查询的记忆子集 R 和关键词集 K。
- **逐记忆平衡检索**：对每个选中的记忆 r，并行走两条检索路径——BM25（文本匹配）+ 余弦相似度（嵌入匹配），每路返回 top-k 条。由于每个记忆贡献相同数量的候选，任何单一记忆都不会主导候选池。随后对跨记忆候选集做去重。
- **倒数排名融合（RRF）**：对所有候选按两种信号进行全局融合排序：
  RRF(c) = 1/(k₀+rank_bm(c)) + 1/(k₀+rank_emb(c))，k₀ 为平滑常数（设为60）。取 RRF 得分最高的 top-N 条注入提示词作为检索上下文。
- **查询充分性检查**：若规划 LLM 判断上下文不足，可触发二次查询（每记忆 3 条）。

## 6. 论文的主要结论与发现

1. **CreaMem 在两个基准上全面最优**：LoCoMo 上 4o-Judge 准确率达 54.61%（对标最佳基线 HippoRAG 2 的 47.66%）；LongMemEval-S 上达 66.40%（对标最佳基线 MemGAS 的 60.20%）。在所有评估指标（F1、BLEU-4、ROUGE-1/2/L、BertScore）上均一致领先。
2. **性能增益集中于多跳推理与时间性问题**：在 LoCoMo 上，CreaMem 的 Multi-hop 准确率超过最强基线 2.83 个百分点；Temporal 问题上优势尤为显著（GPT-4o-mini 骨干下超过最强基线 19.93 个百分点）。
3. **场景感知分区有效**：3-scene 配置比 1-scene（合并为单池）在相同内容与检索预算下高 2.3 个百分点，表明场景划分并非冗余。
4. **双编码带来协同增益**：Full System 较 Episodic only 高 9.2 个百分点（Temporal 问题上差距超过 11 个百分点），且 Episodic only 消耗的 token 比 Full System 多 42%——双编码不仅提升准确率还降低 token 开销。
5. **分区粒度存在最优平衡**：3-scene（Life/Work/Interest）效果最佳；过粗（1-scene）会导致无关内容竞争检索槽位，过细（4/5-scene）则过度碎片化、稀释各记忆的信息密度。
6. **检索预算存在非单调效应**：准确率在 k=30 达峰后在 k=40 下降，超出适度预算后额外条目反而作为噪声干扰回答，却伴随近线性增长的 token 成本。
7. **Life/Work/Interest 分类体系具有较好的覆盖率**：对 1,000 条 LoCoMo 对话轮次的审计显示，GPT-4o 与人类评分者覆盖度一致较高（人类评分 83.0–90.1%，GPT-4o 71.0%），LLM—人类一致性达 77.2%。
8. **CreaMem 仍存在失败情形**：主要包括两类——检索阶段无法将关联/隐含证据一并取回（如事件与游戏名分离存储、日期信息缺失），以及检索后无法在生成阶段有效整合已取回的多个证据条目。

## 8. 不足与局限

- **固定分类体系的泛化局限**：Life/Work/Interest 三分类是人为设定的粗粒度划分，并非普遍适用或最优本体。论文承认，它未必能均匀迁移到不同用户群体、文化背景或专业领域。
- **真实用户数据缺失**：评估集中在两个合成基准（LoCoMo 与 LongMemEval-S），虽然测试规模可观，但缺少真实长期交互数据的验证，外部效度有限。合成对话中可能存在的场景分布偏向尚待研究。
- **额外系统开销**：CreaMem 的端到端延迟为 2.9 秒/查询（vs A-Mem 的 1.98 秒），充分性检查可能触发二次检索而增加延迟与 token 消耗；写入时的提取也引入了额外的 LLM 调用成本。
- **存在路由与提取错误**：路由的精确匹配率仅约 67.94%（但部分匹配率达 94.79%）；500 条记忆抽样审计中，9.60%（Gemini 3.1 Pro 判定）/6.40%（GPT-4o 判定）包含无支撑的核心主张。
- **评估方法学遗留问题**：论文指出，LLM 提取型记忆系统在写入成本对比上因批处理粒度、模块提示词、存储抽象层级差异而缺乏统一标准；Recall@k/NDCG@k 等检索指标假设检索条目与参考证据直接对齐，但当记忆条目综合了多轮对话时该假设不成立。
- **生成后阶段的证据组合能力不足**：失败分析显示，即使正确的证据被成功检索并置于上下文中，模型有时仍无法在回答时正确组合不同条目的信息以推导答案。这是超出记忆架构本身的一个局限（取决于骨干 LLM 的推理能力），但 CreaMem 并未对此进行特殊干预。
