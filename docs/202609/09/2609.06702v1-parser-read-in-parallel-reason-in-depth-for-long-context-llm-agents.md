## 摘要
顺序记忆智能体通过逐块阅读长文档并维护紧凑的记忆状态来处理信息，这种方式将文档遍历与推理深度耦合在一起。这种耦合导致对证据位置的敏感性，并使推理延迟与文档长度呈线性关系。我们提出PARSER，将阅读与推理解耦。一组轻量子智能体各自绑定一个块，并行读取整个文档，同时一个主导智能体通过迭代式散集轮次进行深度推理：在每一轮中，它向所有子智能体广播查询，聚合返回的证据，并根据迄今已发现的信息制定更深入的后续查询。这种解耦设计将所有可学习行为集中在主导智能体中，并通过强化学习进行优化，而子智能体保持为冻结的现成模型。在上下文长度从7K到896K token的多跳问答任务中，使用4B主干的PARSER平均比最强的顺序记忆基线高5.7个百分点，在896K token时高12.0个百分点。扩展到9B主干时，PARSER比DeepSeek-V4-Pro高6.3个百分点。控制实验证实，PARSER对证据位置、顺序和距离的扰动具有鲁棒性，而这些条件会导致顺序方法出现大幅准确率波动，同时将推理延迟降低多达11倍。

## Abstract
Sequential memory agents process long documents by reading chunks one after another while maintaining a compact memory state, coupling document traversal to reasoning depth. This coupling introduces sensitivity to evidence placement and ties inference latency linearly to document length. We introduce PARSER, which decouples reading from reasoning. A bank of lightweight subagents each bound to a single chunk read the entire document in parallel, while a lead agent reasons in depth through iterative scatter--gather rounds: at each round it broadcasts a query to all subagents, aggregates the returned evidence, and formulates a deeper follow-up query conditioned on what has been found so far. This decoupled design concentrates all learnable behavior in the lead agent, which is optimized with reinforcement learning, while the subagents remain frozen off-the-shelf models. On multi-hop QA with contexts ranging from 7K to 896K tokens, PARSER with a 4B backbone outperforms the strongest sequential memory baseline by 5.7 points on average and by 12.0 points at 896K tokens. Scaling to a 9B backbone, PARSER surpasses DeepSeek-V4-Pro by 6.3 points. Controlled experiments confirm that PARSER is robust to perturbations in evidence position, order, and distance, conditions that cause large accuracy swings in sequential methods, while reducing inference latency by up to 11x.

# 《PARSER: Read in Parallel, Reason in Depth for Long-Context LLM Agents》论文总结

## 1. 论文的核心问题与整体含义

- **研究背景**：大语言模型（LLM）在长上下文推理中仍面临明显瓶颈。即使模型原生支持百万 token 级上下文，随着输入变长，模型性能仍会系统性下降，即“context rot”现象；证据位于输入中部时尤其容易被忽略，即“lost in the middle”。
- **已有方案及其局限**：以 MemAgent、ReMemR1 为代表的“顺序记忆智能体”将长文档按块顺序读入，并维护一个压缩的文本记忆，从而在有限上下文内处理超长文档。但其本质是单遍、依赖前后顺序的循环压缩过程，导致三个固有缺陷：
  - 每个 chunk 在尚未看到全文时就被压缩，证据是否被保留取决于其绝对位置、逻辑顺序以及与其他证据的距离；
  - 所有 chunk 的更新必须串行执行，推理延迟随文档长度线性增长；
  - 固定容量记忆可能过早丢弃关键证据，无法支持跨远距离证据的多跳推理。
- **整体意义**：论文提出 PARSER，将“文档阅读顺序”与“问题推理顺序”解耦：文档阅读改为并行，顺序计算只留给问题所需的推理过程。该方法旨在同时解决顺序记忆方法的准确率脆弱性和延迟问题，为长上下文智能体提供了一种可扩展的架构范式。

## 2. 论文提出的方法论

- **核心思想：并行阅读、顺序推理（Parallel Reading, Sequential Reasoning）**
  - 文档被划分为若干 chunk，每个 chunk 唯一绑定一个轻量子智能体（subagent）；所有子智能体并行处理各自 chunk。
  - 一个主导智能体（lead agent）不读取任何原始文档 token，而是在每一轮通过 **Scatter–Gather** 操作与所有子智能体交互：
    1. **Scatter**：lead agent 广播一个/多个查询给所有子智能体；
    2. **Gather**：每个子智能体只基于自己 chunk 返回局部证据（可输出 JSON 证据与答案，或 abstain）；
    3. lead agent 聚合返回结果，结合已有推理历史生成更聚焦的下一轮查询，直到能给出最终答案。
  - 因此，跨 chunk 的证据依赖通过多轮“查询链”完成，而不是通过文档顺序的记忆传播完成。

- **关键机制与设计细节**
  - 每个子智能体面对的是固定 chunk + 当前查询，阅读任务简单；因此可使用冻结的现成模型（默认 Qwen3.5-4B），无需训练。
  - Lead agent 使用 ReAct 式循环，可在一个回合内并行发出多个独立查询，提升效率。
  - 训练只更新 lead agent 的策略，使用 **RLVR + GRPO**，奖励为二元 Exact Match（答案字符串匹配）；不设置格式奖励，直接使用模型原生的多轮工具调用格式。
  - 为避免子智能体重复 prefill，训练/推理阶段利用 SGLang 的 Radix Cache 与 cache-aware 路由对查询前缀做 KV cache 复用。
- **时间复杂度要点（附录 A）**
  - Full-context 的 prefill 复杂度为 O(n²)，顺序记忆方法为 O(n²/c)，PARSER 同样为 O(n²/c)（c 为 chunk 数）。
  - Decode 阶段，顺序记忆方法需随 chunk 数线性生成 token，PARSER 每轮每个子智能体只输出简短证据或“Unknown”，生成量显著更小；
  - 若子智能体真正并行执行，其解码对墙钟延迟的贡献可进一步除以 c，使得“顺序推理深度”只取决于问题复杂度，而非文档长度。

## 5. 主要结果与关键数字

- **主实验结果（8 档长度上取 Sub_EM）**
  - 在所有长度档位上，PARSER 的平均 Sub_EM 显著优于同主干的 Full-context 基线：
    - 以 Qwen3.5-4B 为主干时，Full-context 在约 14K token（100 段）附近即开始明显下降，到 896K token（6400 段）时几乎趋于 0；PARSER 在从 50 段到 6400 段的全范围内保持接近平稳的准确率，长端性能远高于 Full-context。
    - PARSER 也稳定超过顺序记忆基线 MemAgent 与 ReMemR1，尤其当文档超过 800 段（约 112K token）后，优势扩大为 10–30 个百分点的 Sub_EM 差距。
  - 使用更强主干（Qwen3.5-9B）时，PARSER 的优势趋势不变；即使主干能力较弱，PARSER 也能达到接近较强主干 Full-context 的中等长度表现。
  - 在不限制推理预算的 DeepSeek-V4-Pro（think-max）对照中，PARSER 在 ≤400 段时互有高低，在 ≥800 段后反超，说明 PARSER 的稳定性并非来自“更多思考”，而是来自将证据检索从长程顺序记忆中剥离。
- **证据分布敏感性实验**
  - PARSER 对“lost in the middle”免疫：证据位于第 0–90% 百分位区间内移动时，PARSER 的性能波动远小于 Full-context 与 MemAgent。
  - 对“逻辑顺序”不敏感：证据倒序时 Full-context 和 MemAgent 出现明显下降，PARSER 基本不变；说明其多轮查询并不依赖段落间的原始排列。
  - 对“证据间距”不敏感：当两个关键证据相距 0–3400 段时，PARSER 在最大间距下依旧保持高 Sub_EM，而 MemAgent 在间距增大时显著劣化。这验证了“跨证据依赖靠查询传播、而非靠固定容量记忆传播”的设计目标。
- **推理延迟实验**
  - 并发度 1 时，PARSER 的墙钟时间低于全文档 prefill 的 Full-context，但高于顺序记忆方法；原因是每轮 scatter/gather 的网络与调度开销。
  - 并发度 16 / 32 时，PARSER 的端到端延迟显著下降，且远低于顺序记忆方法；子智能体之间的并行解码使得总延迟主要由少量“硬”轮次决定。
  - PARSER 的延迟增长随段落数增加非常平缓，而 MemAgent 的延迟近似线性增长。

## 6. 消融与机制分析

- **RL 训练的作用**
  - 去掉 RLVR 后，仅使用基座 lead agent 做零样本 ReAct 式检索，长文档端（≥1600 段）下降明显，中等长度保持不错；说明 RL 主要教会 lead agent 在“子智能体给出的证据不足”时提出更细致的追问，而非简单重复 scatter。
  - 二元 Exact Match 奖励足够驱动多轮搜索；加入格式奖励反而会降低训练稳定性。
- **子智能体规模**
  - 子智能体主干从 2B 换到 9B 会带来平滑的性能提升，但 4B→9B 的提升小于 2B→4B；
  - 在 6400 段最长达上，2B 子智能体仍能达到接近的性能，说明子智能体任务足够局部化、对模型规模要求低，这使 PARSER 可在算力受限时选用更小 reader。
- **Chunk 粒度**
  - chunk 大小从 4K 到 128K 变化时，PARSER 的性能在一个较宽区间内保持稳定；
  - 极端情况（无分块，即把整篇文档塞给单子智能体）时性能退化为 Full-context，说明分块是必要的；而过小 chunk（<4K）会增加大量子智能体，虽不明显损害准确率，却带来调度开销。
  - 最优 chunk 约在 16K–64K token 区间，兼顾上下文覆盖率与子智能体数量。
- **子智能体实现替代**
  - 将子智能体换成 thinking 模式（输出内部思维链后再回答）会提升单步证据质量，但总体最终答案提升微弱且推理成本成倍增加；
  - 采用 DCI 风格的子智能体（直接要求输出证据并推断）效果相近，说明 PARSER 的关键不是证据格式，而是“固定分块+并行局部阅读+lead agent 引导的迭代查询”这一结构。

## 7. 结论与启示

- 论文的核心主张是：**长上下文智能体不应通过“顺序读完全文”来获得全局理解，而应通过“并行精读局部 + 顺序推理全局”来按需组织证据**。
- 该范式在推理质量上显著优于直接长上下文模型与顺序记忆智能体，同时对证据位置、顺序和间距不再脆弱；在延迟上能通过并行化获得接近常数级的扩缩能力。
- 局限与开放性讨论：
  - 子智能体数量上限仍未做极限测试：在更长（数千万段）文档与更多子智能体下，lead agent 的调度开销可能成为新瓶颈；
  - 实验只覆盖抽取式/多跳问答，尚未验证开放域摘要、代码库级 agent 任务等；
  - scatter–gather 的每轮通信需要额外协议设计，实际部署时仍需处理“需要多少轮才能收敛”的自适应终止问题；
  - 对训练数据的真实性与多样性有一定要求：训练多轮检索可见问题时，若训练分布太窄，lead agent 可能学到固定的轮数模式而非动态推理策略。
- 总体而言，PARSER 提示了一个有前景的方向：**把“长文档”从模型的输入负担，转化为并行进程的分布式检索问题；模型越“小”越“快”，只要它能提出好的顺序推理问题，就能驾驭任意长的外部记忆。**
