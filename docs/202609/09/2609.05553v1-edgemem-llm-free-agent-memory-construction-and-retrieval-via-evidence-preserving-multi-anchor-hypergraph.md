## 摘要
代理记忆使LLM代理在回答新查询时能够利用早期的交互。现有方法通常将交互历史压缩为摘要或其他由LLM生成的表示。重复生成会增加成本，并可能在系统知道未来查询需要什么之前丢弃含有答案的细节。我们提出EdgeMem，一种基于简单原则构建的代理记忆方法：保留原始交互轮次，并通过互补的内容、时间和情节线索对其进行组织。EdgeMem通过轻量级本地处理构建多锚点超图来实现这一原则。检索直接返回源证据，并将LLM的使用保留用于最终答案生成，将对多会话历史的结构化访问与对原始对话的忠实保留相结合。在LoCoMo和LongMemEval-S上的实验展示了强大的检索和基于记忆的问答能力；在LoCoMo上，在共享提示下，EdgeMem在七个复现系统中取得了最高的严格评判分数（61.01对58.70），而构建和检索不需要生成式LLM调用。总体而言，EdgeMem表明，保留和组织源证据为代理记忆提供了有效且高效的基础，而无需生成式记忆管理。

## Abstract
Agent memory allows LLM agents to use earlier interactions when answering new queries. Existing methods often compress interaction histories into summaries or other LLM-generated representations. Repeated generation adds cost and can discard answer-bearing details before the system knows what a future query will require. We propose EdgeMem, an agent-memory method built around a simple principle: preserve original interaction turns and organize them through complementary content, temporal, and episodic cues. EdgeMem realizes this principle with a multi-anchor hypergraph constructed by lightweight local processing. Retrieval directly returns source evidence and reserves LLM use for final answer generation, combining structured access to multi-session histories with faithful retention of the original conversation. Experiments on LoCoMo and LongMemEval-S show strong retrieval and memory-grounded question answering; on LoCoMo, EdgeMem achieves the highest strict-judge score among seven reproduced systems under a shared prompt (61.01 versus 58.70), while construction and retrieval require no generative-LLM calls. Overall, EdgeMem shows that preserving and organizing source evidence provides an effective and efficient foundation for agent memory without generative memory management.

## 论文总结：EdgeMem——无LLM代理记忆的构建与检索

### 1. 论文核心问题与整体含义（研究动机与背景）

- **核心问题**：现有的大语言模型（LLM）代理记忆系统在构建和检索记忆时过度依赖生成式LLM（Generative LLM），导致两个关键缺陷：
  - **高昂的Token成本**：在记忆构建和每次查询时反复调用LLM，随着交互历史增长，Token消耗远超原始历史本身。
  - **证据不可逆丢失**：LLM生成的摘要或结构化表示可能在未来查询提出之前就丢弃或扭曲了原始交互中承载答案的关键细节，成为永久的“记忆黑洞”。
- **核心洞察**：受情节记忆（Episodic Memory）研究启发（通过内容、时间、情节上下文描述经历），本文提出了一种根本性的替代方案——**保留原始交互轮次作为原子记录**，并利用轻量级本地处理（非LLM）进行组织和检索，只在最终答案生成阶段调用一次LLM（称为**读取器**）。该方法的整体意义在于证明了：**保留并组织源证据是比生成式记忆管理更高效、有效的记忆基础**。

### 2. 方法论：核心思想与关键技术细节

- **核心思想**：**“保留原始，结构锚定”** ——不压缩、不改写、不丢失任何源对话轮次，而是通过多种上下文线索（锚点）将其组织起来，以便未来任何查询都能回溯到原始证据。
- **系统架构**：整体框架定义为三元组（Φ, Ψ, F），其中Φ是记忆构建，Ψ是记忆检索，F是读取LLM。
  - **核心不变式**：记忆构建Φ和检索Ψ的生成式LLM Token消耗严格为0： `tok_LLM(Φ) = tok_LLM(Ψ) = 0`。
- **记忆构建（Φ）：零LLM调用，纯本地注释与超图构建**
  - **本地注释（Local Annotation）**：仅使用轻量级NLP工具（如spaCy、dateparser）和转录元数据，为每个轮次生成注释：
    - **实体集（E_t）**：文本中的人物、组织、地缘政治实体、地点、事件等表面词汇。
    - **关键词集（K_t）**：去除停用词后的词元化内容词。
    - **时间戳（τ_t）**：来源于转录元数据或内容中的日期/时间提及。
    - **会话信息**：记录轮次所属的原始会话（情节）、会话内顺序、说话者。
  - **单源记录（Single-Source Records）**：原始对话文本 `x_t` 被原封不动地存储（而非重建），仅附带上述注释。
  - **多锚点超图构建（Multi-Anchor Hypergraph Construction）**：将每个源轮次作为顶点，通过三类锚点键（Anchor Keys）连接形成类型化超边，构成统一的超图结构：
    - **时间子超图（Time Sub-Hypergraph, `e_time`）**：按转录日期的日历月份将轮次分组。
    - **共现子超图（Co-occurrence Sub-Hypergraph, `e_co`）**：通过共享的实体和关键词将轮次连接起来。
    - **情节子超图（Episode Sub-Hypergraph, `e_epi`）**：将每个原生会话视为一个独立情节，并保留其内部轮次有序性。
- **记忆检索（Ψ）：零LLM调用，确定性通道与预算分配**
  - **查询处理**：同样通过本地管道提取查询的实体、关键词和时间区间线索。
  - **三类确定性检索通道**：
    - **情节通道**：作为证据核心，结合查询与单轮BM25得分和查询与整个情节拼接文本的BM25得分，综合排序选取相关轮次及其相邻上下文。
    - **共现通道**：作为补充证据，利用查询的“稀有”实体/关键词锚点，从其他会话中激活并选取未被情节通道选中的源轮次，以连接跨会话信息。
    - **时间通道**：作为门控补充，仅在查询包含明确的年月日期时激活，选择目标时间范围内情节的起始轮次和高分轮次。
  - **固定的证据预算（Evidence Pack）**：通过如 `P(q) = dedup(C_epi||C_co||C_time)` 的确定规则融合三条通道的结果。默认预算上限为 κ=18 个轮次、B=3072 个Token（情节通道k=14，共现通道n_co=4，时间通道n_time=2）。
- **答案生成（F）**：唯一使用LLM的阶段。将检索到的证据包（保留说话者、时间、原文信息）与查询一同输入一个“读取器”LLM（如gpt-4o-mini），由其基于证据生成最终答案。若证据不足，读取器会返回固定拒绝语句“Not mentioned in the conversation.”
