## 摘要
智能体的工作记忆是异质的。指令、工件、工具输出以及智能体自身生成的状态等对象在语义上扮演不同角色，并展现出不同的规模、保留时长和表征形式。近期研究已开始探索能够解释这种异质性的记忆管理机制。本工作聚焦语义异质性，并研究其应如何塑造编码智能体中工作记忆的管理与评估。通过对55条归档的编码智能体轨迹进行分析，我们发现语义上不同的工作记忆对象呈现出不同的保留与压缩行为。这种异质性促使我们采用具备语义感知的记忆管理策略。我们研究了两种语义感知策略：一种是对对象感知的压缩策略，另一种是基于检索的策略。评估显示，校准带来的增益可能无法迁移到留出任务上，且相同的token预算并不等同于此传递的上下文或管理成本。一次真实系统重放进一步暴露了仅凭名义预算无法捕捉的供给限制。这些结果共同说明了为何语义结构对智能体工作记忆至关重要，以及为何评估记忆管理策略不能仅依赖名义token预算。我们将这些经验归纳为四个层面：存储状态、传递的上下文、管理工作以及任务或过程结果。

## Abstract
Agent working memory is heterogeneous. Objects such as instructions, artifacts, tool outputs, and agent-generated state play different semantic roles and exhibit different size, retention, and representation profiles. Recent work has begun to explore memory-management mechanisms that account for such heterogeneity. This work focuses on semantic heterogeneity and studies how it should shape the management and evaluation of working memory in coding agents. Across 55 archived coding-agent trajectories, we find that semantically different working-memory objects exhibit distinct retention and compression behavior. This heterogeneity motivates semantically informed memory management. We study two semantically informed strategies: an object-aware compression policy and a retrieval-based policy. Their evaluation shows that calibration gains may not transfer to held-out tasks, and that equal token budgets do not imply equal delivered context or management cost. A real-system replay further exposes serving limits that nominal budgets alone do not capture. Together, these results show why semantic structure matters for agent working memory and why evaluating memory-management strategies requires more than a nominal token budget. We organize these lessons into four levels: stored state, delivered context, management work, and task or process outcome.

## 1. 核心问题与整体含义

**研究动机与背景：**

- 编码智能体（coding agent）的工作记忆呈现高度**异质性**：指令（instructions）、工件/产物（artifacts）、工具输出（tool outputs）、智能体自身生成的状态（agent state）等对象在语义角色、规模、保留时长、表征形式与生命周期特征上各不相同。
- 现有记忆管理机制（保留、压缩、驱逐、检索）往往将这些异构状态**一视同仁**地处理，忽视了语义类型差异。
- 评价记忆管理策略时，研究者常用**名义 token 预算**（nominal token budget）作为核心控制变量，但这一指标本身可能具有误导性——相同预算标签下，实际传递的上下文、管理成本与服务可行性可能相差甚远。
- 论文的核心主张是：**在管理之前必须先衡量（Measure before you manage）**，即应该从语义结构出发理解工作记忆，并从多个层级（而非单一预算数字）评估管理策略。

**研究问题拆解为两点：**

1. 语义异质性如何在编码智能体工作记忆中显现？
2. 在将收益归因于某个记忆管理策略之前，需要测量哪些量？

## 2. 方法论

**核心思想：**

- 将工作记忆对象视为**类型化对象**，按语义角色分类追踪其大小、保留时长、表征形式与压缩行为。
- 提出语义感知的管理策略，并以此作为案例研究来揭示评估中可能出现的误导。
- 提出**四层级评估框架**：存储状态（stored state）、传递的上下文（delivered context）、管理工作（management work）、任务或过程结果（task/process outcome）。

**关键技术细节与公式：**

- **对象会计（object accounting）**：对每个对象记录创建步骤 $c_o$、首次驱逐步骤 $e_o$、代理 token 大小 $s_o$，定义：
  - 保留区间：$r_o = \max(0, \min(e_o, T) - c_o)$
  - 内容体积：$V_c = \sum_{o \in c} s_o$
  - 保留加权成本：$R_c = \sum_{o \in c} s_o r_o$

- **对象感知压缩策略（Object-Aware, OA）**：手工设计的启发式评分（非学习型）：
  - 评分公式：$u_o = \max\left(10^{-6}, b_t e^{-d_t a_o} m_o [1+0.35\min(k_o,5)](1-p_t z_o) q_o\right)$，然后 $S_o = u_o / \max(s_o^{\text{rendered}},1)^{0.5}$。
  - 参数包括类型基值 $b_t$、衰减率 $d_t$、过期惩罚 $p_t$、子类型乘子 $m_o$、访问年龄 $a_o$、访问计数 $k_o$、过期指示 $z_o$、版本惩罚 $q_o$。
  - 最多四轮将低分对象从原始→压缩→摘要→指针形式降级；指令和新创建对象受保护。

- **检索式策略（GA 改编）**：改编自 Generative Agents 的 recency/relevance/importance 三组件：
  - $S_o^{GA} = 0.5 \cdot \tilde{0.99}^{s-\ell_o} + 3.0 \cdot \tilde{\cos}(e_o, e_q) + 2.0 \cdot \tilde{I_o}$，各组件在候选集上做 min–max 归一化。
  - 使用本地 BAAI/bge-small-en-v1.5 嵌入计算相关性，重要性通过独立模型请求获得 1–10 评分并按 run 内缓存。

**基线策略：**

- FIFO（按创建时间驱逐）
- LRU（早期版本用继承的访问时钟；后期版本 LRU-D 使用需求事件）
- 统一压缩（UC，统一年龄阈值 3 步 + FIFO 驱逐，但共用类型相关渲染器）

## 6. 主要结论与发现

1. **语义异质性真实存在**：
   - 工具输出占 55.5% 的内容体积但仅 40.2% 的保留加权成本；工件占 28.3% 体积但 38.9% 保留成本。
   - 工件中位大小 624 token（工具输出仅 73），工件平均驻留 10.71 步 vs 工具输出的 8.61 步。
   - 压缩比差异巨大：工件压缩比 0.150 vs 工具输出 0.673。
   - Pooled 平均值不是典型任务：task-level 工具输出份额 P10–P90 为 23.0%–78.1%，不同估计量没有矛盾。

2. **校准增益可能无法迁移**：OA 在校准集对 FIFO 的对比为 -1.633 重复调用（Holm p=0.0146），但留出集合只有 -0.500 且仅 2 个非零对，无留出对比通过 Holm 校正。校准结果不能视为已确认的策略收益。

3. **名义预算 ≠ 有效预算**：宽扫描中 6,000-token 下限使所有 25%/50% 对变成相同绝对预算条件；检索研究中 18/24 个上限超过名义 15% 锚点。

4. **共享上限不保证匹配的已传递上下文**：UC 与 FIFO 的差距在 8 个任务上 0/8 匹配，最大差距 88.8%。

5. **管理工作是必要的比较部分**：GA 的 285 次重要性调用和 OA 的 169 次摘要调用意味着同帽结果不是同计算对比；GA–FIFO 墙钟时间差在所有 8 个任务上为正（平均 +67.45 秒）。

6. **服务边界暴露可行性约束**：在 32,768-token 冻结限制下，无约束臂在某个任务上达到 37,883 token（25 步中 6 步超限），所有约束臂 ≤16,643 token——这是已传递上下文的硬可行性边界，而非任何策略的硬件优势。

7. **四层级评估框架**（存储状态 / 已传递上下文 / 管理工作 / 任务或过程结果）是评估工作记忆管理策略的基本最小报告集。

## 7. 优点

1. **诚实且严谨的自我审查**：论文系统性地披露了自身局限——未固定的服务模型修订版、不完整的请求/重试历史、生命周期信号缺陷、预算标签与有效预算之间的偏差、无有效修复评估——这在实证 AI 论文中相当罕见且值得肯定。
2. **精细的测量框架**：区分 Pooled 与 task-level 估计量、名义预算与有效预算、内容体积与保留加权成本、过程指标与修复成功，避免了许多常见混淆。
3. **统计处理的规范性**：使用精确检验而非近似检验、明确 Holm 校正族、报告 bootstrap 方法与种子、区分 bootstrap 区间与显著性检验的反演、明确不将非显著结果解释为等价性。
4. **审计脚本与证据定位**：附录 F.4 提供证据定位表（哪些文件支持哪些结论），附审计脚本、输入哈希和从属规范，这是可复现性的实际努力。
5. **不夸大结论**：明确不声称任何策略的普遍优越性、不声称缓存收益或服务加速、不声称语义实用性，视 OA 为启发式而非学习到的效用预测器。

## 8. 不足与局限

1. **实验覆盖面有限**：总体任务量偏少（8–24 个任务），仓库聚类严重（SymPy 占主导），检索阶段仅 8 个完整块且每臂单次运行，后续研究无有效修复评估。样本不足以支撑稳定的策略排序。
2. **以完成为条件的偏差**：停止规则的任意性（贪婪下限并非全局最小证明）导致分析仅覆盖完成块，无法推断到全部 24 个任务；中断轨迹不是修复失败。
3. **生命周期信号缺陷**：自动提示包含对访问时钟的污染（LRU 退化为创建顺序）、版本事件不反映语义变化（SymPy-19007 案例）、OA 的过期/替代信号不可靠，且没有修正版 OA 轨迹可供对照。
4. **预算标签混乱**：不同扫描之间下限不同（6,000 vs 1,200 token），名义百分比与实际预算/参考峰值之比差异大（11.9%–165.0%），早前 FIFO/ LRU 与后期实现不可直接比较。
5. **测量单元不一致**：cl100k_base 代理会计 vs 冻结的 Qwen tokenizer 会计不可直接比较；请求开销被排除在外；API 提示用量单独记录但未与托管状态成本统一。
6. **可复现性不足**：服务模型修订版未固定、历史请求/重试/人工干预不完全可重建、无完整匿名数据/代码发布、云生成不可逐字节复现；两个美元估算冲突且均为假设价格而非实际账单。
7. **缺乏社会影响讨论**：论文未讨论更广泛的社会影响（无论正面或负面）。
8. **资产许可信息不完整**：未列举所有数据集/模型资产许可证和条款。
