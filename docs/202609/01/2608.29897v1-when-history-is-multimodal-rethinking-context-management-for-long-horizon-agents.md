## 摘要
长时程智能体需要一个上下文管理器，通过被动策略或主动策略来决定记忆如何访问和重组，将不断增长的历史交互压缩到有界的工作上下文中。同时，先前的光学记忆工作主要将像素视为文本化历史的密集编解码器，通常预设将上下文渲染为光学记忆相对于文本会带来显著性能下降，因此将这种表示与SFT、自蒸馏或强化学习相结合以弥合差距，但未解决（i）在公平、受控比较下，视觉渲染作为上下文管理器的表现如何，以及（ii）当历史本质上是多模态的时，这种载体是否提供天然优势。在本文中，我们将上下文管理形式化为一种受预算约束的历史变换，并引入视觉渲染（VR）作为一种表示型上下文管理器。在共享框架、策略模型、触发器和任务领域下，我们在四个文本中心和三个多模态基准上，将VR与四种基线（不压缩、全部丢弃、滑动窗口、摘要）进行比较，发现视觉记忆是原生视觉证据的天然载体。基于这一发现，我们提出了VERA（面向长时程智能体的视觉证据保留策略），这是一种基于确定性渲染、无显式记忆操作、免训练的上下文管理器：在文本中心基准上，它像VR一样渲染文本历史；在多模态基准上，它保留原生视觉观察而非将其转换为文本。在几乎所有基准上，VERA相对于不压缩策略将累积非缓存令牌削减了31.5%-63.1%，在文本中心任务上与现有管理器相当，在多模态任务上达到所有基线中的最高准确率，支持了对长时程上下文管理的模态保留观点。

## Abstract
Long-horizon agents need a context manager to compress growing interaction histories into a bounded working context, via passive strategies or active strategies that decide how memory is accessed and reorganized. Meanwhile, prior optical-memory work mainly treats pixels as a dense codec for textualized histories, often presupposing that rendering context into optical memory incurs a significant performance drop relative to text, thus coupling this representation with SFT, self-distillation, or reinforcement learning to close this gap, leaving unresolved (i) how visual rendering performs as a context manager under a fair, controlled comparison, and (ii) whether this carrier offers a native advantage when history is inherently multimodal. In this paper, we formulate context management as a budget-constrained history transformation and introduce Visual Rendering (VR) as a representational context manager. Under a shared harness, policy model, trigger, and task domain, we evaluate VR on four text-centric and three multimodal benchmarks against four baselines (No Compression, Discard-All, Sliding Window, Summarization), finding visual memory is a natural carrier of native visual evidence. Building on this finding, we propose VERA (Visual Evidence-Retaining strategy for long-horizon Agents), a training-free context manager built on deterministic rendering with no exposed memory operations: on text-centric benchmarks it renders textual history as VR does, while on multimodal benchmarks it retains native visual observations instead of translating them into text. Across nearly all benchmarks, VERA cuts cumulative non-cache tokens by 31.5%-63.1% versus No Compression, matches existing managers on text-centric tasks, and achieves the highest accuracy among all baselines on multimodal tasks, supporting a modality-preserving view of long-horizon context management.

### 1. 核心问题与研究动机

- **背景问题**：长时程智能体（Long-horizon Agents）在执行深度研究、GUI操作、软件工程等任务时，轨迹可跨越数十至数百轮交互。**完整保留历史轨迹**会不断增加推理成本、最终超出上下文窗口限制，且长提示中的证据淹没会损害任务表现。
- **上下文管理的必要性**：需要一个显式机制将不断增长的历史交互转换为有界的工作上下文（bounded working context），即在保留关键信息的同时控制上下文规模。
- **现有工作的不足**：
  - 先前的光学记忆（optical-memory）工作（如DeepSeek-OCR、Glyph、MemOCR、AgentOCR等）**主要将像素视为文本化历史的密集编解码器**，即“把文本渲染成图片再用视觉编码器读回”，本质上仍是OCR式打包。
  - 这些工作**普遍预设渲染会带来显著性能下降**，因此必须耦合SFT、自蒸馏或强化学习等训练手段来弥合差距，导致视觉载体本身的价值从未在公平、受控的条件下被单独评估过。
  - 当历史**本身是多模态**（包含图片、截图、表格、图表等原生视觉证据）时，现有方法只是将一切转化为文本描述后再渲染，**丢弃了原生视觉证据中的空间结构和像素级信息**。
- **核心研究问题**：(i) 在公平、受控比较下，纯视觉渲染作为上下文管理器的表现如何？(ii) 当历史本身多模态时，视觉载体是否具有额外优势？

### 2. 方法论

#### 2.1 上下文管理的统一形式化定义

- 将上下文管理定义为**受预算约束的历史变换**：

$$ \tilde{H}_t = \mathcal{M}(H_t; B) $$

其中 $H_t$ 为交互历史，$B$ 为工作上下文预算，产生的 $\tilde{H}_t$ 须满足：

$$ \kappa(\tilde{H}_t, o_t) \leq B $$

- 有效的上下文管理器须满足**非空且严格更便宜**：

$$ \tilde{H}_t \neq \emptyset, \quad 0 < \kappa(\tilde{H}_t) < \kappa(H_t) $$

- 该定义排除了两个边界控制：No Compression（ $M_{NC}(H_t; B) = H_t$ ）和 Discard-All（ $M_{DA}(H_t; B) = \emptyset$ ），它们分别对应全保留和重置，而非真正的上下文管理器。
- 区分了固定管理器（按预定规则变换）与主动管理器（变换规则依赖输入状态，动态决定如何选择、丢弃、重写或摘要历史片段），以及持久化记忆架构（被逐出的内容可放入外部工具可寻址的存储中供后续查询）。

#### 2.2 视觉渲染（Visual Rendering, VR）

- VR保留最近轮次 $H_t^r$ 原文，将更早的被管理历史 $H_t^c = (H_t^{c,\text{text}}, H_t^{c,\text{native}})$ 渲染为图像：

$$ \mathcal{M}_{VR}(H_t; B) = \left( H_t^r, \text{Render}(H_t^{c,\text{text}}, H_t^{c,\text{native}}; B) \right) = (H_t^r, I_t) $$

- 关键在于**原生视觉证据**的概念：当某个观测的决策相关结构已由像素或空间排列承载时，直接保留图像，而非先生成文字描述再处理。

#### 2.3 VERA 策略

- **核心思想**：VERA（Visual Evidence-Retaining strategy for long-horizon Agents）是VR的免训练实现，采用**确定性渲染器**和策略模型已有的视觉编码器，引入的干预极小。
- **关键设计**（对应文中图1）：
  - 保持轨迹时间顺序，使用角色和工具标签保留来源信息。
  - 对图像搜索工具（image_search、image_crop、image_zoom_in）返回的图片，**直接放置在对应交互旁边**，而非替换为文字说明。
  - 对分析工具，自动检测结构化输出并渲染为紧凑表格，移除同一区块中重复的纯文本表格。
  - 基于**新近度**管理图像分辨率：最近N轮保留全分辨率渲染，更早的页面渐进式降低采样率。
- **默认超参数**：主实验统一使用0.75×画布缩放（来自RQ3中0.7×–0.8×最佳平台的中点），每次模型调用最多包含10张渲染图像，压缩触发阈值为64k活动上下文token（128k窗口的0.5）。
- **与现有光学方法的关键区别**：不需要学习的渲染策略、无需专门训练的读取器、不暴露记忆操作给智能体——因此能够分离出“视觉载体本身”的独立贡献。

### 6. 主要结论与发现

- **发现1（RQ1）**：在文本中心基准上，无单一策略全面最优，但**纯视觉渲染在聚合准确率最高（74.2%）**，且在每个基准上都使用最少的累积非缓存token（相对No Compression减少31.5%–54.8%）。Discard-All以73.7%紧随其后，可能受益于固定轮次预算内的重复重置效应。
- **发现2（RQ2）**：在多模态基准上，**VERA在所有三个多模态基准上均为最强**（BrowseComp-V3：31.7% vs No Compression 27.3%；MM-BrowseComp：28.5% vs 23.3%；AgenticDataBench：0.41 vs 0.38），同时大幅降低token消耗。消融实验证明，**保留原生视觉证据**带来的增益（相对文本渲染提升10.8%–32.6%）来自域原生视觉信息，而非仅靠光学打包。
- **发现3（RQ3）**：保留更早历史比仅保留近期上下文带来适度准确率提升（+1.1pp）和显著成本降低（token −20.4%、API调用 −20.5%、轮次 −16.8%）。渲染保真度与性能呈**非单调关系**：0.7×–0.8×达到最高准确率（71.0%），而满分辨率1×反而下降至64.0%，表明过度放大会增加冗余视觉token并分散注意力。
- **总体结论**：视觉渲染在无训练条件下即可作为强竞争力的上下文管理器；当历史自身为多模态时，保留域原生视觉证据比将其转化为文本具有更好的性能。上下文管理应不仅问“如何压缩”，还要问“哪些领域特定的多模态结构应保留”。

### 7. 优点

- **公平控制对比**：在共享harness、策略模型、触发器和任务协议下对比，隔离了“表示载体”作为独立设计维度，这是在现有光学记忆文献中缺失的。
- **形式化定义清晰**：将上下文管理定义为“预算受限的历史变换”，严格区分了真正的管理器与全保留/重置边界控制，澄清了长期研究中被混淆的概念。
- **免训练、零额外开销**：VERA无需SFT、RL、自蒸馏、专门读取器或外部记忆索引，仅靠确定性渲染就取得最佳聚合性能，展示了视觉载体的内在价值。
- **消融设计到位**：通过“文本渲染 vs 原生视觉证据渲染”的对比，将视觉载体的通用效果与域原生证据的特定贡献分离。
- **广泛的多模态覆盖**：从文本搜索延伸到图像搜索、本地裁剪/缩放检查和数据分析场景，拓展了上下文管理研究的测试面。
- **透明的不确定性说明**：作者明确指出了重置效应的机制性解释而非因果识别、渲染非单调性的证据局限等，学术表述严谨。

### 8. 不足与局限

- **极长时程的可扩展性有限**：VERA在结构上类似滑动窗口（O(N)复杂度），原始渲染观察保留在有界窗口内而非递归压缩，压缩比无法与递归摘要（O(1)复杂度）匹配。作者建议未来可与学习型访问策略或混合管理器耦合。
- **模态覆盖仅限视觉**：多模态实验集中于自然图像和渲染表格/图表，未验证音频、视频、原始数据库状态等模态的适用性。
- **过度单一的策略模型**：所有实验仅使用Gemini-3.5-flash-thinking，未验证在不同VLM（如开源模型）上的泛化性，结果可能受特定模型的视觉编码能力影响。
- **基准规模有限**：作为研究工作，未提出新基准；部分基准仅采样子集；多模态基准的问题数量未明确报告。
- **因果机制未完全识别**：重置效应的优势、渲染尺度与性能的非单调关系、注意竞争的解释均为“可能机制”而非严格因果识别。
- **语义保真度不保证**：渲染为像素后，被压缩的历史是否能被精确恢复取决于视觉编码器的能力；极低分辨率下的信息丢失风险未系统分析。
- **评估成本考量**：基准的推理成本限制了在更大样本上的验证（如BrowseComp-EN仅200题），这可能引入抽样偏差。
