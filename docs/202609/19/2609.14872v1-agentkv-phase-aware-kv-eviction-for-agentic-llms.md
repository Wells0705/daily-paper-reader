## 摘要
智能体服务消耗的 token 可比聊天机器人工作负载高出若干数量级，给 KV 缓存容量和解码时带宽都带来压力。多数 KV 淘汰方法使用从最近 token 中抽取的代表性查询来对缓存键进行评分，假设未来注意力与近期注意力相似。我们表明，智能体生成违背了这一假设：未来查询是 think、act、tool 及其他阶段的混合，并且主角分析表明这些组成部分占据具有可度量差异的查询子空间，因此基于近期性的代表会系统性地低估即将到来的阶段所需的键。我们提出 AGENTKV，它为每个阶段维护一个小的查询缓冲区，并基于这些查询缓冲区的并集对缓存键进行评分。我们进一步在持久化多轮服务路径中实现 AGENTKV，该路径跨轮次携带压缩的 KV 状态，并在线压缩保留的 KV 页。在两个模型、六个任务领域以及每种三个 KV 预算下，AGENTKV 相比 R-KV 平均提升任务分数 5.5 分，相比 Tri-attention 提升 5.3 分。相对于上游全 KV 的 SGLang，AGENTKV 将输出 token 吞吐量提升至多 1.80 倍。代码：https://github.com/LiuTaowen-Tony/agentkv。

## Abstract
Agentic serving can consume orders of magnitude more tokens than chatbot workloads, stressing both KV-cache capacity and decode-time bandwidth. Most KV-eviction methods score cached keys against representative queries drawn from the most recent tokens, assuming future attention resembles recent attention. We show that agentic generation violates this assumption: future queries form a mixture over think, act, tool, and others phases, and principal-angle analysis shows these components occupy measurably different query subspaces, so recency representatives systematically undervalue keys that upcoming phases will need. We propose AGENTKV, which maintains a small query buffer per phase and scores cached keys against their union. We further implement AGENTKV in a persistent multi-turn serving path that carries compressed KV state across turns and compacts retained KV pages online. Across two models, six task domains, and three KV budgets each, AGENTKV improves task score by 5.5 points on average over R-KV and 5.3 over Tri-attention. Relative to upstream full-KV SGLang, AGENTKV improves output-token throughput by up to 1.80x. Code: https://github.com/LiuTaowen-Tony/agentkv.

# AgentKV：面向智能体大语言模型的阶段感知 KV 淘汰——论文总结

## 1. 核心问题与整体含义

- **研究背景**：智能体（agentic）推理正成为 LLM 的核心用例，但其服务成本远高于单轮聊天。智能体工作负载可消耗比传统聊天多约 1000 倍的 token（Bai et al., 2026），导致序列长度剧增，KV 缓存容量与内存带宽成为服务吞吐和延迟的主要瓶颈。
- **核心矛盾**：现有 KV 淘汰方法（H2O、StreamingLLM、SnapKV、R-KV 等）大多假设"未来注意力类似于近期注意力"，用最近 token 中抽取的**代表性查询**对缓存键打分。但智能体轨迹在多轮中反复交替出现 think（推理）、act（动作生成）、tool（工具结果）、others（系统提示/用户问题）等**阶段（phase）**，未来查询分布并非平稳，而是阶段混合分布。
- **关键发现**：作者通过 t-SNE 可视化和**主角分析（principal-angle analysis）**证明，不同阶段的查询向量占据可度量的、彼此不同的查询子空间；因此基于近期性的代表会**系统性地低估**后续阶段所需的键。
- **整体含义**：这是首个显式建模智能体推理中"阶段混合查询分布"的 KV 淘汰方法，同时配套持久化多轮服务路径实现，将逻辑压缩转化为实际吞吐提升。

## 2. 方法论

### 2.1 核心思想
- 将未来查询分布 `p(q)` 建模为四个阶段特定分布的**混合**，而非单一的近期经验分布。
- 为每个阶段维护一个小的查询缓冲区，压缩时用**四个阶段缓冲区并集**作为代表性查询集合对缓存键打分，而非仅用最近窗口。

### 2.2 关键技术细节
- **阶段定义**：每个 token 被归入四类之一——`think`（助手推理片段）、`act`（工具调用参数）、`tool`（工具响应观察）、`others`（系统提示、工具描述、用户问题）。阶段是语义类别，而非轮次索引。
- **在线阶段解析器（Algorithm 1）**：基于 tokenizer 可见的 chat-template 标记（如 `<|im_start|>system`、`<|im_start|>user`、`<think>`、`<tool_call>`、`<tool_response>`）做确定性解析，使用滚动前缀识别被切分到多个解码 token 中的标记。**无需模型侧分类器，也无需新增特殊 token。**
- **阶段缓冲区**：每个阶段 ϕ 维护固定大小的 FIFO 缓冲区 `Qϕ`，存储其最近 `⌈q/4⌉` 个查询。
- **压缩事件评分**：在压缩事件 e 处，令 `Q(e) = Qthink ∪ Qact ∪ Qtool ∪ Qothers`，满足 `|Q(e)| ≤ q`（与近期基线代表预算一致）。每个候选键 i 的得分：

  `A(e)_i = (1/|Q(e)|) Σ_{q∈Q(e)} softmax(qᵀK(e)/√dh)_i`

  保留得分最高的 top-B 候选键，淘汰其余。**注意：所有候选键在同一池中评分，不按阶段划分键或设置阶段键配额。**
- **服务路径实现（Algorithm 2、3）**：
  - 每次解码 128 token 触发一次在线压缩；
  - 保留的 KV 条目被 gather 到紧凑目标槽位，释放页面归还分配器；
  - 将物理缓存长度与单调递增的逻辑长度分离，保留 RoPE 偏移和未来前缀扩展能力；
  - 兼容 chunked prefill、CUDA graph capture 和正常 decode 路径；
  - 在工具调用和后续用户轮次之间持久携带压缩 KV 状态。
- **默认超参数**：代表预算 `q=32`，每阶段环形容量 8，压缩间隔 Δ=128 token，streaming sink 大小 ws=32 token。

## 6. 主要结论与发现

- **任务质量**：在两模型、六领域、三预算下，AgentKV 相比 R-KV 平均提升 **5.5 分**，相比 Tri-attention 提升 **5.3 分**；最大且最一致的增益出现在 BFCL `multi_turn`（跨多个阶段转换仍相关的非近期指令与工具观察）。
- **服务吞吐**：相对上游全 KV SGLang，output-token 吞吐最高提升 **1.80×**（H100 NVL，Qwen3-32B，32k/1k）；RTX A6000 上 Qwen3-8B 提升 1.37×（16k/1k）与 1.76×（32k/1k）；H100 NVL 上 Qwen3-8B 提升 1.31×（32k/1k）。
- **阶段结构证据**：主角分析显示跨阶段角度显著大于同阶段不同步骤的角度；效用覆盖率诊断显示近期代表对 `tool` 阶段覆盖率仅 0.042（B=512），多阶段代表提升至 0.175（B=512）与 0.416（B=1536）。
- **机制结论**：阶段感知代表比匹配数量的近期查询平均提升 4.2 分；移除任一阶段都会降低精度；四阶段方案在固定 q 下平衡最佳；标签噪声导致性能渐进下降而非突变。
- **权衡关系**：增大预算 B 通常提升质量但降低吞吐；AgentKV 曲线在测量范围内始终位于 R-KV 与 Tri-attention 的右上方（质量与吞吐同时更优）。

- **问题识别新颖**：首次明确指出智能体 KV 淘汰中的"阶段诱导估计偏差"，并用主角分析给出可度量的几何证据，而非仅凭直觉。

## 8. 不足与局限

- **预算需手动指定**：当前使用人工设定的 KV 预算，未根据任务级质量或延迟目标自动选择；虽可小验证集调参，但增加了部署负担。
- **适用区间有限**：方法在**中等压缩比**最有用；极小预算下缓存容量主导代表选择，压缩压力弱时策略趋近全缓存、执行方差主导差异。
- **外部状态场景失效**：当任务已通过最近工具响应或外部记忆（如 τ2 `airline`、BFCL `memory`）暴露相关状态时，阶段感知保留优势不明显。
- **重复/退化推理风险**：重复性强的推理轨迹会使阶段缓冲区保留近似重复上下文；Nemotron 实验需额外组合 R-KV 冗余惩罚项来抑制。
- **统计未解析比例较高**：36 个对比中约 20–21 个未解析，部分结论依赖点估计而非置信区间。
- **实验覆盖**：仅覆盖英文智能体工具使用工作负载；未报告具体 GPU 数量；未涉及训练阶段。
- **标签鲁棒性**：10%–30% 标签损坏会降低精度（虽仍高于 R-KV 基线）；更细的阶段划分在固定 q 下反而更差。
