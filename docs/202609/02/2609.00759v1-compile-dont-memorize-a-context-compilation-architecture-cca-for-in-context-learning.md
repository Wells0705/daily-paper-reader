## 摘要
大型语言模型（LLM）越来越多地处理上下文学习（ICL）任务，在这些任务中，一个长而新颖的上下文为一系列问题定义了规则、知识和输出模式。在根据上下文每一个细节评分的基准上，即使是强大的开源权重模型也只能通过12-16%的任务：单是忽略一条规则就会导致整个回答失败。我们认为这种脆弱性是结构性的：占主导地位的“阅读-推理”范式要求模型在一次前向传播中完成提取、规划、生成和自我验证。因此，我们研究显式上下文编译能否解决这个问题，它相比现有的长上下文策略（如要点检索、多智能体自博弈）表现如何，以及由此带来的工具优势能适用于哪些任务结构和模型规模。我们提出了上下文编译架构（CCA），其核心创新在于带有固定槽位的类型化中间表示（IR）——rules.{must_do, must_not, conditional}、output_spec、available_tools、data_profile——任何自然语言上下文都能被一次性编译进这些槽位；随后可执行的验证器和违规门控的纠正循环作为下游配套机制。在CL-bench（包含4个开源基础模型的1,899个任务）上，CCA在每个基础模型上都优于普通提示方法和两个长上下文基线（ReadAgent-P、Ctx2Skill），将Kimi K2.5从15.4%提升至21.4%，且提升集中在规则密集的子类别。代码与缓存结果见 https://github.com/TonyQJH/cca-emnlp2026。

## Abstract
Large language models (LLMs) increasingly handle in-context learning (ICL) tasks where a long, novel context defines the rules, knowledge, and output schema for a series of questions. On benchmarks that grade against every detail of the context, even strong open-weights models pass only 12-16% of tasks: a single overlooked rule fails the whole response. We argue this brittleness is structural: the dominant "read-and-reason" paradigm asks the model to extract, plan, generate, and self-verify in one forward pass. We therefore ask whether explicit context compilation can fix it, how it compares to existing long-context strategies (gist retrieval, multi-agent self-play), and where the resulting harness benefit holds across task structure and model scale. We propose the Context Compilation Architecture (CCA), whose central novelty is a typed intermediate representation (IR) with fixed slots (rules.{must_do, must_not, conditional}, output_spec, available_tools, data_profile) into which any prose context is compiled once; executable verifiers and a violation-gated correction loop follow as downstream consequences. On CL-bench (1,899 tasks across 4 open base models), CCA outperforms vanilla prompting and two long-context baselines (ReadAgent-P, Ctx2Skill) on every base model, lifting Kimi K2.5 from 15.4% to 21.4% with gains concentrated on rule-dense sub-categories. Code and cached completions are available at https://github.com/TonyQJH/cca-emnlp2026.

## 1. 核心问题与研究动机

- **背景**：LLM 越来越多地面对长且新颖的上下文（数万至数十万字符），要求模型在一系列下游问题中遵循其中的规则、知识与输出格式；CL-bench 等基准以“每条细则均通过才算任务通过”的严格粒度评分。
- **核心问题**：即使强大的开源模型在基准上仅能通过 12–16% 的任务——单条规则遗漏即导致整个回答判负，暴露出结构性脆弱。
- **作者论断**：脆弱性源于当前占主导的“read-and-reason”范式——要求模型在一次前向传播内同时完成信息提取、规划、生成和自我验证；任一细节在长上下文与大量检核条件下被遗漏的联合概率随复杂度上升而急剧增大。
- **整体含义**：将 ICL 类比于活字印刷术，主张不应让模型依靠“预置模板（固定雕版）”去即兴适配，而是把长上下文当作“原稿”显式编译为可复用的、可机械校验的结构化“活字版”，是一种重要的范式转变，属于“harness engineering”范畴。

## 2. 方法论（CCA 架构）

**核心思想**：先在“每上下文一次”的离线阶段把散文上下文编译为带固定槽位的类型化 IR（中间表示），并为该上下文自动生成可执行的 Python 验证器；然后在“每任务一次”的在线阶段使用 IR 作为检核清单生成草稿，通过执行验证器发现违规，再由违规门控的修正循环修复。核心问题由“我是否记住了所有内容”转变为“我的代码验证器是否通过”。

**Compiled IR 结构**（关键创新）：固定槽位 JSON，包含以下字段——
- `role`：角色、语气、口吻；
- `rules`：分组为 `must_do`/`must_not`/`conditional`，每条规则带 `codeable` 标记（决定能否机械化验证）与 `code_hint`；
- `knowledge`：概念、实体、公式，及**保持逐字原文的 `exact_terms`**（评分细则常要求字面出现精确字符串）；
- `workflow`：有序步骤和决策点；
- `output_spec`：格式类型、tone、persona_voice、格式规则、长度；
- `available_tools`：工具名、用途、I/O 模式；
- `data_profile`：TSV/CSV/表格数据及其格式；
- `compilation_meta`：`recommended_strategy`（rule_engine/calculator/data_analysis/soft_reasoning）。

**四阶段流程**：
1. **Compiler（编译阶段）**：读取原始上下文并输出上述 JSON IR；强调对反事实/虚构内容保持原文抽取，绝不“修正”为训练知识；精确抽取所有逐字术语。
2. **CodeGen（代码生成阶段）**：按 `codeable` 规则数、数据格式与格式规则数决定生成至多三类 Python 模块：
   - `rule_checker(response_text)`：检查草稿中规则违规（强调**零误报优先**：不确定即放行）；
   - `format_validator(response_text)`：检查格式规则；
   - `data_analyzer(raw_data)`：在**每上下文阶段**对原始数据执行，结果作为缓存摘要注入 Reasoner-1（属于非草稿期模块）。
   所有模块以 try/except 包裹，代码失败只产生空结果，不中断流程。
3. **Reasoner-1（草稿生成）**：提示词拼接四块——系统提示（上下文优先、接受反事实、规则优先级）、**IR 渲染为检核清单（F2）**、条件注入的“CODE EXECUTION RESULTS”（当策略为 data_analysis/calculator 且 data_analyzer 成功时）、头尾截断后的原文（约 70% 头 + 30% 尾，F7）与实际提问。
4. **Verifier Execution + Reasoner-2（执行与修正）**：在草稿上运行草稿期验证器；违规数 ≥2 时触发 Reasoner-2，输入为违规列表（最多前 10 条，各 200 字符）与原始草稿，指令要求“仅修复标记违规、不得改动其余部分”；修正输出非空才替换草稿，否则保留原文（只增不减原则）。

**整体建模**（论文式 1）：输出联合概率分解为
`每上下文因子 P(I_c|c,I)·P(M_c|I_c)·P(s_c|M_c,c)` 乘以 `∏ 每任务因子 P(d_t|I_c,s_c,τ(c),q_t)·P(y_t|d_t,V_c,θ)`
其中 `I_c` 为 IR，`M_c ⊆ {rule_checker, format_validator, data_analyzer}`，`V_c` 为草稿期验证器子集，`θ=2` 为违规门控阈值，`τ` 为头尾截断。每个上下文阶段生成的工件在该上下文的所有任务间共享摊销。F1–F7 为消融分析单元，其中 F2 为 IR 检核清单注入，F6 为修正循环，F4 为验证器执行。

- **LongBench-v2**（跨基准验证探针）：503 个多选任务，用于验证 CCA 是否可泛化到单上下文任务为主的长上下文场景。

## 6. 主要结论与发现

- **RQ1（有效性）**：CCA 在每个基座模型上都取得最优 Overall 通过率；Kimi K2.5（15.4%→21.4%，+6.0pp）、GLM-5（16.1%→21.2%，+5.1pp）、DeepSeek-V3.2（15.0%→17.7%，+2.7pp），三者均通过 p<0.01 的 McNemar 检验；最小模型 Qwen3-Next-80B（3B 激活）提升仅 +0.5pp 且不显著。消融发现：**F2（IR 作检核清单注入）是承重组件**（单去 F2 掉 −3.07pp），F6（修正循环）次之（−1.28pp），F4（验证器执行本身）几乎只起日志作用（约 +0.5pp 的间接贡献）；存在 F2×F4/F6 的 +0.70pp 正交互效应；各组件贡献能被可加分解，总和精确等于 +6.00pp。
- **RQ2（与现有策略对比）**：ReadAgent-P 与 Ctx2Skill 在全部模型上都未超过 CCA；二者共同缺陷是**上下文与推理者之间存在有损抽象**（gist 摘要丢弃逐字命名事实；技能库蒸馏丢弃逐条检核）。CCA 是概念上的反转——IR 保留 exact_terms、CodeGen 产出可执行校验，紧贴 rubric 结构。在成本-质量 Pareto 图中 CCA 独占前沿，Ctx2Skill 位于远离前沿的右下角（约 190K tokens/task、near-Vanilla 通过率）。
- **RQ3（增益边界与调节因素）**：
  - **任务结构密度**：在规则密集领域增益最大——Legal & Regulatory（+20~+27pp）、Management（+11~+25pp）、Workflow Orchestration（+6~+11pp）等；在开放发散类任务（Game Mechanics、Lifestyle、Simulation Environment）上 CCA 反而逊于 Vanilla——IR 成为“普罗克拉斯提斯之床”，压缩了内容的探索空间。
  - **模型能力**：3B 激活的小模型无法吸收 IR+代码执行结果+原始上下文的三重输入（修正输出为空率更高），说明 harness 收益以基座模型“消费结构化信号的能力”为上限。
- **跨基准探针**：纯 CCA 在 LongBench-v2 总体落后（53.88% vs 57.85%），但在**需要跨文档/跨轮次重构结构**的 Multi-Doc QA（+5.69pp）与 Long-Dialog（+10.25pp）上获胜；用 `cca_meta.ir_ok` 作路由门控的 CCA-Adaptive 达到 60.24%，反超 Vanilla +2.39pp——证明 CCA 是**领域选择性工具**而非通用包装器。
- **成本**：CCA 按 ~2.85× Vanilla 的 token 换来全基座模型最大正向提升；其离线工件共享结构使 CCA-V2（无修正）能以 ~51% 边际成本换回约 79% 的提升（+4.72pp @ 22.7K tokens），并按任务数 N→∞ 逼近 27.7K/task。

## 7. 优点

- **问题诊断切中要害**：将低通过率归因于结构化瓶颈而非推理能力不足，提供了机制性解释并设计了对应解。
- **新框架立意新颖**：把 ICL 视为“上下文编译”问题——借助类型化 IR 与可执行 Python 验证器，实现了“让机械检查取代不可靠自省”的实质跃迁；活字印刷类比贯穿始终且贴切。
- **IR 设计完整且具工程可用性**：将散文转为首等机器可查的数据结构，`exact_terms` 字段正面回应“逐字要求”，`codeable` 标记区辨机械校验与语义判断的边界。
- **工程细节扎实**：若验证器零误报提示、防御性数据解析、try/except 兜底、修正只增不减规则、违规门控阈值 2、仅首 10 条违规 200 字符截断——均体现出高可靠性工程素养。
- **实验充分且规范**：4 方法×4 模型×19 细分类的主矩阵、全量消融、交互项量化、逐案例机制追踪、成本分解、截断审计、温度鲁棒性、跨基准验证与多评审三角验证相结合，公平性顾虑得到系统回应。
- **报告透明度高**：完整公布 prompt 核心、IR schema、伪代码、逐级成本、释放缓存补全与所有代码链路，可复现性强。

## 8. 不足与局限

- **消融覆盖不完整**：组件消融只在 Kimi K2.5 上全量执行；作者自认为在其他三模型（尤其是小激活模型上验证 F2/F6 交互饱和边界）自然扩展方向，尚未完成。
- **IR schema 覆盖有限**：对空间（几何、布局）、时间（长时规划、事件排序）相关结构的上下文无对应槽位；当前槽位直接为规则/程序/数据分析类而设。
- **编译器稳健性的验证不足**：不可解析 IR 发生率 <1% 但仅靠降级策略吸收，尚不是形式化保证；作者承认安全关键场景需进一步加固。
- **领域选择性限制**：在单上下文、开放发散类任务上 CCA 反而降低输出质量，LongBench-v2 总体落后于 Vanilla；作者用门控路由部分补救，但“结构无法提取时开销为负”这一根本局限依然存在。
- **评审风险与偏差**：主结果仅用单一 GPT-5.1 judge，跨评审一致性仅中等（κ 0.40–0.61）；未完成 100 任务的人工审计计划。多项指标为同源评审模型，存在评价偏差的残余风险。
- **零温度与采样规则**：主实验全部落在 temp=0，绝对数值略低于原 CL-bench 论文 23.7%（该文含更大封闭模型池且默认采样）；压缩的温度单一化固然利于归因，但也使增益界定的外部效度略受影响。
- **资源成本未显式列出**：无 GPU 型号、数量、时长等算力细节，无法完整复制其端到端资源需求场景。
