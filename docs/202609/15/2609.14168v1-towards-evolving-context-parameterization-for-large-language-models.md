## 摘要
上下文参数化使大型语言模型（LLMs）能够将上下文内化到可复用的模型参数中，从而避免在后续查询中重复处理。然而，现有方法通常假设上下文是静态的，并且缺乏在持续更新下区分有效性状态的显式机制。为研究这一现实场景，我们将记忆更新与序列演化（Memory Updating with Sequential Evolution, MUSE）任务形式化，并构建了 MUSE-bench 以评估更新吸收和未受影响信息保持。由此产生的挑战要求在调整记忆证据贡献的同时保持全局状态。受此启发，我们提出了 PLUME，一种免训练方法，它构建全局更新表示，激活记忆证据以形成局部参数视图，并在解码过程中自适应地整合它们的预测。在 MUSE-bench 上的综合评估表明，PLUME 在序列演化设置中有效，平均 ROUGE-L Recall 相对提升 29.9%，LLM-as-a-Judge 相对提升 54.9%。我们的代码见：https://github.com/xiaobingshi-LLM/PLUME。

## Abstract
Context parameterization enables large language models (LLMs) to internalize contexts into reusable model parameters, avoiding repeated processing across subsequent queries. However, existing methods typically assume static contexts and lack explicit mechanisms for distinguishing validity states under continual updates. To study this real-world scenario, we formalized the Memory Updating with Sequential Evolution (MUSE) task and constructed MUSE-bench to evaluate update incorporation and unaffected-information preservation. The resulting challenge requires preserving the global state while adjusting the contribution of memory evidence. Motivated by this, we proposed PLUME, a training-free method that constructs a global update representation, activates memory evidence to form a local parameter view, and adaptively integrates their predictions during decoding. Comprehensive evaluation on MUSE-bench demonstrated PLUME's effectiveness in sequential evolution settings, yielding relative improvements of 29.9% in average ROUGE-L Recall and 54.9% in LLM-as-a-Judge. Our codes are available at: https://github.com/xiaobingshi-LLM/PLUME.

# 论文总结：Towards Evolving Context Parameterization for Large Language Models

## 1. 核心问题与研究动机

- **背景**：上下文参数化（Context Parameterization）将长上下文内化到可复用的模型参数中，从而避免在后续查询中反复处理上下文（RAG、长上下文方法均存在重复推理开销）。
- **核心痛点**：现有方法（如 Context Distillation、Doc-to-LoRA）**默认上下文是静态且内部一致的**，缺乏在持续更新场景下显式区分信息有效性状态的机制。
- **现实场景**：在长期运行的智能体/交互系统中，信息持续累积；部分信息保持有效，部分被补充、替换或失效。若将不同有效性的信息联合保留，模型可能依赖已失效信息，产生不一致回答。
- **核心挑战**：在参数化状态中，既要**融入最新更新**，又要**保留未受影响的信息**，即需要在保持全局状态的同时调整记忆证据的贡献。
- **贡献形式化**：论文形式化了 **MUSE（Memory Updating with Sequential Evolution）** 任务，并构建 **MUSE-Bench** 作为评测基准。

## 2. 方法论：PLUME

PLUME（**P**arametric **L**oRA **U**pdates with **M**emory **E**vidence）是一个**免训练**方法，由三部分组成：

### 2.1 全局更新表示（Global Update Representation）
- 使用预训练的 D2L 超网络 $H_\phi$ 分别参数化更新前历史 $C_{old}$ 与完整历史 $C_{full}$：
  - $\Delta W_{old} = H_\phi(C_{old})$，$\Delta W_{full} = H_\phi(C_{full})$
- 全局更新表示为：
  - $\Delta W_g = \alpha \Delta W_{full} + \beta(\Delta W_{full} - \Delta W_{old})$
  - 第一项保留完整上下文状态；第二项**选择性放大最新更新带来的参数偏移**，但不丢弃它。
- 实现上通过沿秩维度拼接 LoRA 因子，全局适配器秩 $r_g = r_{full} + r_{old}$（单适配器时为 16），**不做逐元素相减或稠密权重合并**，代数上精确等价。
- 生成时预测分布：$p_{g,t}(v) = p_{\theta \oplus \Delta W_g}(v \mid q, y_{<t})$

### 2.2 查询激活的记忆证据（Query-Activated Memory Evidence）
- 将 $C_{full}$ 切分为记忆单元，用**查询词覆盖 + 饱和词频匹配**进行词法打分。
- 在分数落在最高分 $s_{max}$ 的 $\delta$ 余量内的单元中，**激活时间上最新的一个**作为局部记忆证据 $m^\star(q)$（近期性只在可比相关候选间打破平局）。
- 证据参数化：$\Delta W_e(q) = H_\phi(m^\star(q))$，预测分布 $p_{e,t}(v)$。
- 超网络**只接收被选中的证据文本**，查询仅通过证据选择间接影响 $\Delta W_e(q)$。

### 2.3 自适应记忆证据解码（Adaptive Memory Evidence Decoding）
- 用 **JS 散度**衡量局部证据与全局预测的 token 级分歧：$d_t = D_{JS}(p_{e,t} \parallel p_{g,t})$
- 将分歧映射为单调递增、有上界的门控权重：$\lambda_t = \lambda_{max} \cdot \frac{d_t}{d_t + \tau}$
- 融合打分并取 argmax：$S_t(v) = \log p_{g,t}(v) + \lambda_t \log p_{e,t}(v)$
- 设计意图：**全局预测为解码主干，局部证据仅在分歧时做针对性校正**，避免退化为纯局部解码。

## 3. 实验设计

### 3.1 基准与数据集
- **MUSE-Bench**：由 5 个数据集构建——SQuAD、ROPES、2WikiMultihopQA、MultiFieldQA-en、QASPER，共约 **2,944 个上下文、12,932 个 QA 对**，平均完整历史长度 3,811.9 tokens（SQuAD 328.3 → 2Wiki 18,539.8）。
- 构建流程：保留原问题与上下文结构，仅更新目标事实及其依赖（依赖闭包），将更新上下文追加到原上下文，形成支持新答案且不再支持旧答案的历史。
- 质量验证：GPT 系列模型（GPT-5.5、GPT-5.6-Sol）进行 26 轮质量校验，并辅以人工抽查。
- **跨任务泛化**：额外使用 GSM8K（数学）和 CRUXEval（代码推理）。

### 3.2 评测协议（四维度）
- D1 答案覆盖（ROUGE-L Recall）、D2 语义等价、D3 最终答案一致性（D2/D3 用 GPT-5.6-Sol 作为 LLM Judge，二者同时满足才得 1）、D4 局部性（Locality，未受影响查询上的 ROUGE-L Recall）。

### 3.3 对比方法
- Base Model（w/o Context、w/ Context oracle）
- **D2L**（Doc-to-LoRA）及 D2L oracle
- **CD**（Context Distillation）及 CD oracle
- **AnyEdit**（知识编辑基线，AlphaEdit-ARE 配置）

### 3.4 模型骨干
- Qwen3-4B-Instruct-2507（主骨干）、Gemma-2-2B-it；均使用官方预训练 D2L 超网络 checkpoint（20K 步）。

## 4. 资源与算力

- 论文明确说明：所有实验在**两张 NVIDIA A800 GPU** 上以 **bfloat16 精度**完成。
- 使用官方预训练的 D2L 超网络 checkpoint（`checkpoint-20000`，即 20K 训练步）；PLUME 本身**免训练**，推理时冻结基座模型与超网络。

  - 优点：覆盖多数据集、多骨干、多任务类型，含 oracle 上界参照与效率维度；评测使用统一 prompt、统一生成设置、温度 0、greedy 解码，可复现性较好。

## 6. 主要结论与发现

- **主结果**：PLUME 在所有 5 个 MUSE-Bench 数据集上均优于实际参数化方法。平均 ROUGE-L Recall 从 44.46（D2L）提升至 57.76（**+29.92%**）；LLM-as-a-Judge 从 34.49 提升至 53.41（**+54.84%**）。
- **局部性最优**：PLUME 的 Locality 达 84.24，分别比 D2L 和 CD 高 10.25（+13.85%）和 20.30（+31.75%）分，说明更新对未受影响信息的干扰被有效抑制。
- **跨任务泛化**：GSM8K 上平均分从 23.18/16.42 提升至 45.39/41.47；CRUXEval 上从 39.48/13.63 提升至 62.31/50.62。
- **持续更新鲁棒性**：从 3 次到 20 次更新，Recall 仅下降 2.09 分（79.27 → 77.18）。
- **消融结论**：去掉全局表示（memory-only）归一化 Recall 仅 57.28；去掉记忆证据（global-only）为 63.95；完整 PLUME 为 81.36。全局表示负责维持当前上下文状态，记忆证据提供互补增益。
- **候选秩分析的关键发现**：top-1 Recall 为 45.90%，top-5 达 71.79%——有效信息**大多保留在输出分布中，只是被无效候选压过**，因此需要的是针对性重加权而非重建信息。
- **敏感性**：$\beta=0.75$、$\tau=0.3$、$\lambda_{max}=1$ 时达到 Recall 与 Locality 的最佳平衡；过度放大局部证据反而损害两者。

## 7. 优点

- **问题定义新颖且现实**：首次系统研究"持续更新下的上下文参数化"，将有效/失效/未受影响信息共存于同一参数化状态的场景形式化为 MUSE 任务。
- **免训练、轻量**：PLUME 不需要任何训练，更新开销与 D2L 基本持平（如 SQuAD 更新延迟 0.447s vs D2L 0.466s），远低于 CD 和 AnyEdit。
- **设计有据可依**：方法动机直接来自候选秩分析（信息被抑制而非丢失），全局+局部互补的设计逻辑清晰，$\alpha/\beta$ 与 $\lambda_{max}$ 的敏感性实验验证了"全局为主、局部为辅"的定位。
- **精确的 LoRA 组合**：通过秩拼接实现 Eq. 6 的代数精确表示，避免稠密合并或重压缩，工程实现干净。
- **评测维度全面**：同时覆盖答案质量（Recall/语义/最终答案一致性）、局部性、效率（延迟/显存）、持续更新与跨任务泛化。
- **可复现性**：公开代码，统一评测 prompt 与生成设置，附完整标注指南与算法伪代码。

## 8. 不足与局限

- **依赖 D2L 的天花板**：PLUME 完全构建在 D2L 之上，超网络将上下文压缩为紧凑 LoRA 参数，本质上有损，长/信息密集上下文的保真度受限于底层参数化方法。
- **免训练的双刃剑**：干预仅限参数构造与解码阶段，**无法直接提升超网络本身区分有效更新与失效信息的能力**。
- **数据构造偏差风险**：MUSE-Bench 由 GPT 系列模型生成与验证，可能存在系统性偏差；虽有人工抽查与 26 轮校验，但人工评估仅覆盖 50 个上下文子集。
- **oracle 对比的公平性**：CD (oracle)、D2L (oracle) 使用查询特定信息，与部署方法不可直接比较（论文已声明），但可能影响读者对性能差距的解读。
- **算力报告不完整**：未给出训练/实验总时长与完整算力统计。
- **任务范围限制**：主要在 QA、数学、代码推理上验证；对更开放的生成任务、多模态、多轮对话等场景的适用性未知。
- **超参数依赖**：$\beta$、$\tau$、$\lambda_{max}$、$\delta$ 等需针对场景调参，跨领域泛化时可能需要重新搜索。
