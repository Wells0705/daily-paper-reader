## 摘要
语言模型智能体如何有效利用可复用知识库来解决长时程任务？近期工作越来越关注智能体技能：以技能包表示的可复用能力，即包含指令、脚本及其他资源的多文件捆绑包，帮助智能体执行特定任务。智能体技能通常通过将技能指令加载到智能体上下文中，并依赖智能体遵循这些指令来执行。然而，随着任务时程变长，这种方法变得越来越脆弱，因为随着上下文窗口中积累的信息越来越多，推理质量会下降。我们研究了一种替代方法，即将技能包改为作为子代理来调用。子代理执行不是将技能指令加载到主上下文中，而是生成专门用于解决各个子任务的新上下文窗口。我们表明，当技能包暴露出清晰的输入-输出契约，且其指令编码了履行这些契约所需的过程性知识时，子代理执行优于智能体技能执行。代价是额外的通信开销，因为主智能体与其子代理之间需要额外的 token 来协调。我们的结果表明，可复用知识的收益不仅取决于其内容，还取决于它如何被组织和调用。

## Abstract
How can language model agents effectively leverage libraries of reusable knowledge to solve long-horizon tasks? Recent work has increasingly focused on agent skills: reusable capabilities represented as skill packages, i.e., multi-file bundles containing instructions, scripts, and other resources that help agents perform specific tasks. Agent skills are typically executed by loading their skill instructions into an agent's context and relying on the agent to follow them. As task horizons grow, however, this approach becomes increasingly brittle, because reasoning quality degrades as more information accumulates in the context window. We investigate an alternative approach in which skill packages are instead invoked as subagents. Rather than loading skill instructions into the main context, subagent execution spawns fresh context windows dedicated to solving individual subtasks. We show that subagent execution outperforms agent-skill execution when skill packages expose clear input-output contracts and their instructions encode the procedural knowledge needed to fulfill those contracts. The tradeoff is additional communication overhead, as extra tokens are required to coordinate between the main agent and its subagents. Our results show that the benefit of reusable knowledge depends not only on its content, but also on how it is organized and invoked.

## 1. 核心问题与整体含义

- **研究动机**：LLM 智能体在长时程任务中越来越依赖“智能体技能”（agent skills）。技能通常以技能包形式存在，即包含 `SKILL.md` 指令、脚本、示例、参考文档等多文件资源。
- **现有范式的问题**：传统 agent-skill 执行方式会把技能指令直接加载进主智能体上下文，再让主智能体按指令执行。随着任务变长，工具调用、观察结果和中间推理不断累积，上下文膨胀导致推理质量下降、执行变得脆弱。
- **核心追问**：可复用知识应以何种方式被组织和调用，才能在长时程任务中真正发挥作用？
- **整体含义**：论文提出并验证一种替代路径——把技能包作为“子代理”（subagent）调用。子代理为每个子任务开启独立上下文窗口，只把最终输出返回主代理。其核心观点是：可复用知识的收益不仅取决于内容，还取决于它如何被组织、封装和调用。

## 2. 方法论

- **形式化基础**：
  - 工具调用智能体在轮次 \(t\) 中，由 LLM 策略 \(\pi_{\text{LLM}}\) 基于上下文 \(c_t\) 生成回复、工具选择与参数；工具执行器返回输出；上下文按  
    \(c_{t+1}=c_t \oplus (r_t,k_t,x_t,o_t)\) 追加交互轨迹。
- **Agent skill 执行**：
  - 技能包表示为 \(s=(d,m,R)\)：\(d\) 是技能描述，\(m\) 是 `SKILL.md` 指令，\(R\) 是脚本与资源集合。
  - 调用 agent skill 时，工具执行器把技能指令 \(m_k\) 直接返回并加载进主上下文，技能执行由主策略 \(\pi_{\text{LLM}}\) 自己完成。
  - 问题：技能指令增加主上下文负担，长任务下加剧上下文过载。
- **Subagent 执行**：
  - 子代理同样由技能包构造，但不把技能指令暴露给主上下文。
  - 工具执行器实例化一个独立子策略 \(\pi^{(k)}=\pi_{\text{LLM}}(m_k \oplus \cdot)\)，用任务输入 \(x_t\) 初始化新上下文 \(c^{(k)}_0=x_t\)。
  - 子代理在独立上下文中执行工具调用推理，最后只返回最终回复 \(r^{(k)}_T\)。
  - 关键差异：主代理不读写子代理内部轨迹，二者仅通过输入和输出通信。
- **理论视角**：
  - 长上下文推理退化与“带宽有限注意力”有关；关键指标不是总 token，而是任一上下文窗口的峰值上下文长度。
  - 子代理通过信息封装降低峰值上下文，但引入主代理与子代理之间的通信开销，通常增加总 token。
- **输入-输出契约设计**：
  - 借鉴强化学习中的 options 框架：option 由 initiation set、option policy、termination condition 组成。
  - 有效子代理技能包应显式包含：何时可调用、如何执行、返回什么。
  - 技能描述被结构化为 \(d=(q_{\text{in}},h,q_{\text{out}})\)：\(q_{\text{in}}\) 为输入契约，\(h\) 为用途摘要，\(q_{\text{out}}\) 为输出契约。
  - 技能包变为 \(s=((q_{\text{in}},h,q_{\text{out}}),m,R)\)，子代理实现从合法输入集合到合法输出集合的映射。
- **技能包合成流程**：
  - 先用 OpenHands + GPT-5.3 Codex 在 SkillsBench 任务上独立运行三次，收集成功轨迹。
  - 再用 Copilot CLI（Claude Opus 5，子代理由 GPT-5.5 驱动）从成功轨迹中合成“程序性 + 明确 I/O 契约”的技能包。
  - 成功为 87 个任务中的 64 个合成技能包，主实验在 64 任务子集上进行。
