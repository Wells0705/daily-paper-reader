## 摘要
当 AI 系统能够适应其使用者时，它们会变得更有用；但在多智能体系统中，一个智能体学到的有用上下文往往无法被其他智能体使用。我们提出内核管理的共享内存，这是一种系统级抽象：专用智能体写入结构化、带标签的记忆，而由智能体系统内核（而非单个智能体）来管控检索、隐私执行与提示注入。我们在 AIOS 上实现并评估了该设计，并在三种助手模型（GPT-4o、Llama-3.1:8B、Qwen-2.5:7B）上、共 1800 次试验中，将其与三种替代方案进行比较。与使用相同底层存储的非托管外部记忆后端（Mem0）相比，内核管理的检索与注入使个性化评分在 5 分制上提升 2.4–4.0 分（例如，GPT-4o 上的画像使用率从 1.05 提升至 4.69），且所有比较均在 p < 10^-18 水平上显著。与标准检索增强注入相比，增益同样很大，且在三种模型上均保持一致。与完整、未过滤的上下文拼接（其软上限在于可用上下文而非响应质量）相比，内核管理的注入在三个模型中的两个上与性能在统计上相当，在第三个模型上表现出较小的、与模型相关的差距，同时使用的提示显著更短：三种模型的端到端延迟降低 15–61%，每次调用的 token 用量与推理成本也相应减少。这些结果表明，将记忆管理集中于智能体系统内核，而非将检索与隐私执行留给单个智能体，能够以很小一部分成本获得无约束上下文所带来的大部分个性化收益。

## Abstract
AI systems become more useful when they can adapt to the people using them, but in multi-agent systems, useful context learned by one agent often remains unavailable to others. We present kernel-managed shared memory, a system-level abstraction in which specialized agents write structured, tagged memories while the agent-system kernel, not individual agents, governs retrieval, privacy enforcement, and prompt injection. We implement and evaluate this design on AIOS and compare it against three alternatives across three assistant models (GPT-4o, Llama-3.1:8B, Qwen-2.5:7B) and 1,800 total trials. Against an unmanaged external memory backend (Mem0) using identical underlying storage, kernel-managed retrieval and injection improve personalization scores by 2.4-4.0 points on a 5-point scale (e.g., 1.05 to 4.69 profile usage on GPT-4o), with every comparison significant at p < 10^-18. Against standard retrieval-augmented injection, gains are similarly large and consistent across all three models. Against full, unfiltered context concatenation, a soft ceiling on available context rather than on response quality, kernel-managed injection statistically matches performance on two of three models and shows a small, model-specific deficit on the third, while using substantially shorter prompts: end-to-end latency is 15-61% lower across all three models, with corresponding reductions in per-call token usage and inference cost. These results indicate that centralizing memory management in the agent-system kernel, rather than leaving retrieval and privacy enforcement to individual agents, delivers most of the personalization benefit of unconstrained context at a fraction of its cost.

# 论文总结：Kernel-Managed Shared Memory for System-Wide Personalization

## 一、核心问题与整体含义

- **背景**：个性化（记住用户偏好、当前任务、历史交互）是 AI 系统有用的关键。在多智能体系统中，不同智能体各自学到用户上下文的不同片段（稳定偏好、任务上下文、直接对话），但这些信息彼此隔离，系统无法作为整体表现一致。
- **核心问题**：现有做法是"智能体自管记忆"（agent-managed memory）——每个智能体各自检索、过滤、注入自己的记忆，导致：
  - 逻辑在智能体间重复实现；
  - 隐私执行退化为"每个智能体的约定"（SDK convention / prompt 指令），极易出错；
  - 跨智能体的用户上下文无法统一可见。
- **整体含义 / 主张**：应把个性化从应用层提升为**系统级能力**，由独立于任何单个智能体的**智能体系统内核（agent-system kernel）**集中负责写序、隐私执行、检索、排序、格式化与提示注入。作者将这一抽象称为**内核管理共享内存**。
- **实现载体**：在 AIOS（LLM 智能体操作系统式框架）上实例化，但强调该抽象不绑定 AIOS——任何具备共享记忆后端与可控提示构造路径的多智能体运行时都可实现。

## 二、方法论

### 1. 系统模型与形式化

- 智能体集合 $A=\{a_1,\dots,a_n\}$，记忆存储 $M$；查询 $q=(a_i,u,x)$，其中 $a_i$ 为请求智能体、$u$ 为用户标识、$x$ 为输入提示。
- 记忆项 $m=(u,o,t,s,c)$：用户、所有者智能体、记忆类型、共享策略、内容。
- 记忆类型：`profile`、`task_context`、`conversation`；共享策略：`private` / `shared`。
- 内核将提示变换为增强提示 $x'=K(a_i,u,x)$，$K$ 即内核管理的个性化函数。

### 2. 内核五步操作

1. 对目标用户强制"写前读"排序（写屏障）；
2. 检索候选记忆 $R=\text{search}(M,u,x)$；
3. 按可见性规则过滤；
4. 按语义相关性与 token 预算排序并截断；
5. 注入选定记忆 $x'=\text{inject}(x,R_k)$，且注入属于**系统调用路径**而非应用层提示拼接。

### 3. 用户身份解析

- 智能体之间没有一致的用户身份概念，直接用请求智能体自身标识作代理会在并发试验下造成跨用户污染。
- 采用显式优先级链：请求附带的标识符 → 最近注册的会话标识符 → 已观测标识符的回退注册表 → 请求智能体自身标识符（最后手段），并在内核边界统一强制。

### 4. 可见性规则与隐私不变式

- 可见性判定：若 $o=a_i$（本人所写）为 True；若 $s=$ `shared` 为 True；否则 False。
- 共享策略缺失、畸形或显式 private 一律按 private 处理，使隐私成为**内核不变式**而非 SDK 约定。
- 该规则是仅依赖记忆元数据的**静态安全性质**：对任意执行历史都无条件成立（区别于写屏障那种只在有界超时内成立的活性/一致性性质）。

### 5. 写屏障与 read-after-write 一致性

- 问题：写入智能体与检索异步，检索可能在写入持久化索引前执行，静默降低个性化质量且无可见错误。
- 方案：**per-user_id 单调递增序列号 + 写屏障**。每次写入在接受时打序号 $\sigma(w)$；检索开始时取该用户的最高序号快照 $\sigma^*(u)$，阻塞直到所有 $\sigma(w)\le\sigma^*(u)$ 的写被确认 drain，默认超时 5000 ms。
- 保证：检索要么观察到全部 $\le$ 快照的写，要么超时；超时后**fail-open**（优先活性，允许用部分上下文继续回答）。
- 设计理由：写卡住只是个性化降级而非正确性破坏；而可见性永不 fail-open。成本仅限单个 user_id 且有界于写入智能体数量，不阻塞其他用户的检索。

### 6. 表示与格式化

- 结构化存储 ≠ 结构化注入：早期实验中原始 JSON 记忆内容对小型本地模型难以可靠使用。
- 内核施加格式化函数 $c'_m=\text{format}(c_m)$，把画像/任务记忆渲染为自然语言陈述，结构化形式保留用于检索与审计（该因素被单独列为消融，但仅有 pilot）。

### 7. 智能体角色与可配置性

- **ProfileAgent**：抽取稳定用户属性（偏好、工具、语言、响应风格）；
- **TaskAgent**：抽取短期工作上下文（目标、阻塞、下一步）；
- **AssistantAgent**：**检索自由（retrieval-free）**的消费者，不直接访问记忆后端、不自建个性化提示，所有个性化上下文经内核注入路径到达。
- 纯推理时方案，无需重训练；支持可配置的抽取、注入、相关性阈值、记忆预算、屏障超时与可插拔记忆提供方。
- 附录给出系统调用式接口：`MemoryManager`、`Mem0Provider`、`ContextInjector`、`MemoryWriteBarrier`、`MemoryFormatter`、`ConversationExtractor`；智能体永不直接调用提供方或屏障，从而可在不改智能体代码的前提下替换提供方、检索策略或超时。
- 注入流水线：抽取最新查询 → 语义检索 → 从元数据推导 user_id → 跨智能体检索共享记忆 → 合并去重 → 相关性过滤 → 按相关性排序 → 格式化 → 按 token 预算截断 → 以 `===== MEMORY CONTEXT =====` 前缀作为系统消息注入。

## 三、实验设计

- **数据集 / 场景**：**无真实数据集**。每次试验合成一个用户画像、一个任务上下文和一个**故意欠指定**的模糊后续查询（如 "What should I focus on next?"），使个性化内容必须来自注入的记忆而非查询本身。评估流水线为 Phase 1（仅私有记忆）与 Phase 2（启用共享），两者仅共享策略不同。
- **模型**：GPT-4o、Llama-3.1:8B、Qwen-2.5:7B（区分架构效应与单纯能力效应）。
- **对比方法（3 个基线 + 本方法）**：
  - `naive_concat`：完整合成画像/任务上下文直接拼接进提示，无检索无过滤——是"可用上下文的软上限，而非响应质量上限"。
  - `vanilla_rag`：上下文分块索引，嵌入检索 top-k chunk。
  - `mem0_default`：Mem0 外部记忆，配置为仅私有，无内核编排、无写序、无跨智能体共享。
  - `kernel_shared`：本方法。
- **关键对照设计**：`mem0_default` 与 `kernel_shared` **共用同一底层存储提供方**，因此二者差距可归因于内核级写序、身份解析与隐私执行，而非"是否提供了额外上下文"。
- **评判**：由 **GPT-5.4**（与所有被评助手模型不同，以避免自我偏好）在 1–5 分制上评三个维度：Profile Usage、Task Usage、Integration。
- **配置**：`auto_extract: true`、`auto_inject: true`、相关性阈值 0.3、每次最多注入 10 条记忆、记忆 token 预算 2000、写屏障启用且超时 5000 ms。
- **人类验证**：30 个 GPT-4o 试验（每方法 6 个唯一项，共 24 个唯一项 + 6 个重复项），随机顺序、不透明标识、单盲，单评分者仅评 Integration 维度。
