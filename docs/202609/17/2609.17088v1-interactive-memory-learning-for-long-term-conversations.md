## 摘要
大语言模型的最新进展显著增强了智能体对长期对话进行建模的能力。尽管取得了这些成功，现有方法通常采用静态启发式范式，即信息被被动存档，而缺乏自适应的记忆价值评估。因此，这些方法无法自我演化，也无法使其记忆管理与不断变化的用户需求保持一致。为解决这一问题，我们提出 ICML（InteraCtive Memory Learning，交互式记忆学习），一种将记忆机制从被动存档转变为可学习、交互式记忆策略的多智能体框架。具体而言，我们首先采用会话合成流水线生成专家数据，以促进在未见场景中的快速测试时适应。在此基础上，ICML 利用在线强化学习机制，其中 Planner 智能体选择性地编码高价值信息，Trigger 智能体动态检索这些信息以优化回复质量，两个智能体通过持续交互反馈共同演化。至关重要的是，两个智能体通过延迟奖励机制实现同步，该机制将未来反馈传播回更早的存储决策，从而确保记忆策略与用户期望精确对齐。实验结果表明，ICML 显著优于强基线，并展现出随着交互累积而持续提升回复质量的独特能力。

## Abstract
Recent advancements in large language models have significantly enhanced the capabilities of agents in modeling long-term conversations. Despite these successes, existing approaches typically adopt a static heuristic paradigm, where information is passively archived without adaptive memory valuation. Consequently, these methods fail to self-evolve or align their memory management with evolving user needs. To address this, we propose ICML (InteraCtive Memory Learning), a multi-agent framework that transforms the memory mechanism from a passive archive into a learnable, interactive memory policy. Specifically, we first employ a session synthesis pipeline to generate expert data, facilitating rapid test-time adaptation in unseen scenarios. Building on this, ICML utilizes an online reinforcement learning mechanism where a Planner agent selectively encodes high-value information and a Trigger agent dynamically retrieves it to optimize response quality, whereby the two agents co-evolve through continuous interaction feedback. Crucially, both agents are synchronized through a delayed reward mechanism that propagates future feedback back to earlier storage decisions, ensuring memory policies are precisely aligned with user expectations. Experimental results demonstrate that ICML significantly outperforms strong baselines, exhibiting the unique capability to continuously improve response quality as interactions accumulate.

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想
- 提出 **ICML（InteraCtive Memory Learning）** 多智能体框架，将记忆管理建模为**部分可观测马尔可夫决策过程（POMDP）**，通过**在线强化学习**实现测试时的自主适应与自我演化。
- 两个协作智能体：**Planner**（选择性编码高价值信息）与 **Trigger**（动态检索记忆），二者通过**延迟奖励机制**共同演化。

### 2.2 问题形式化
- POMDP 元组为 ⟨S, A, O, R, γ⟩。
- **观测**：当前用户查询 u_k、近期对话历史 H_k、外部记忆状态 M_k。
- **联合动作**：a_k = (a^p_k, a^t_k)，其中 Planner 动作 a^p_k ∈ {0,1}（保存/丢弃），Trigger 动作 a^t_k ∈ {0,1,…,N}（选择某条记忆或不需要记忆）。

### 2.3 回顾式会话合成（Retrospective Session Synthesis）
用于解决冷启动问题，生成高质量专家数据：
- **反向故事线生成**：以新用户首次透露约束/偏好的交互为**种子会话**，用 LLM 作为用户模拟器递归生成前置会话，确保生成历史与当前偏好存在严格因果逻辑一致性。
- **前向依赖标注**：
  - 为 Planner 标注每一轮的信息增益二值标签 y^p（是否值得保存）；
  - 为 Trigger 标注解决种子会话查询所需的目标检索索引 y^t，并混入**硬负例**（同会话无关轮次）与**软负例**（随机全局记忆）以增强判别能力。
- 产出专家数据集 D_expert，用于策略 π_θ 的初始化。

### 2.4 ICML 框架
- 采用共享的 **Actor-Critic** 架构稳定在线学习，两个智能体协作。
- **Planner 智能体**：
  - 观测用户查询，策略输出保存/丢弃二值分布；
  - 使用 backbone LLM 提供**即时代理奖励** r^proxy ∈ [0,1]（评估信息内在价值），并对丢弃高价值轮次施加**遗漏惩罚** −α·r^proxy。
- **Trigger 智能体**：
  - 观测查询、对话历史与候选记忆集合，策略输出记忆索引上的类别分布（索引 0 表示无需记忆）；
  - 使用 backbone LLM 对最终回复进行多维度打分，得到**质量奖励** r^qual ∈ [0,1]。
- **响应生成**：将检索到的记忆 m_{a^t_k} 与上下文拼接，由 LLM 生成最终回复 r*。

### 2.5 跨会话真实奖励（Cross-Session Truth Reward）
- 解决记忆效用验证的延迟问题：维护一个**待定奖励缓冲区**，存储等待验证的 Planner 潜在经验。
- 当 Trigger 在未来轮次 k_future 激活某条记忆 m_i 时，回溯其创建轮次 k_past，将未来质量评估传播回去：
  - **公式**：r^truth_{k_past} = r^proxy_{k_past} + λ · r^qual_{k_future} · I(m_i is triggered)
  - 其中 λ 为权重因子，I(·) 为指示函数。
- 该机制将历史存储决策与长期实际效用对齐，使 Planner 与 Trigger 相互适应。

### 2.6 在线策略优化
- 使用 **PPO** 算法端到端优化，收集轨迹 τ = {(o_k, a_k, r_k)}。
- **Critic 损失**：最小化估计价值 V^j_ϕ(o^j_k) 与实际回报 R^j_k 的均方误差。
- **Actor 损失**：采用裁剪替代目标，含重要性采样比 ρ^j_k、优势 A^j_k、熵奖励 S[π^j_θ]，裁剪系数 ε。
- 联合优化使两个智能体共同演化各自策略。

## 6. 主要结论与发现

- **演化记忆超越静态启发式**：ICML 在三个数据集上均达到 SOTA，显著优于管理为中心、生成为中心及长上下文基线。
- **与 LLM 及人类期望一致对齐**：在 LLM 交叉评估与人工评估中，ICML 在一致性、连贯性、参与感、人性化、记忆性等维度均表现最优，胜率约 66%-70%（p<0.01）。
- **整体完整性支撑演化循环**：消融实验显示每个组件都必不可少，其中**跨会话真实奖励**影响最大，**演化机制**次之，**合成数据**解决冷启动，**Planner 与 Trigger 缺一不可**。
- **协同智能体的涌现行为**：
  - Planner 演化后能清晰区分高价值与低价值信息；
  - Trigger 能将用户查询与真实记忆映射到紧密语义簇，与无关噪声分离。
- **规模匹配促进高效协作**：Planner 与 Trigger 规模匹配时性能峰值，平衡架构是成本有效的协同策略。
- **持续共演化提升性能**：10 个会话中 Planner 精度与 Trigger 召回率持续上升。
- **适度预热实现测试时适应**：0.25K-0.5K 合成数据量最优，过少无法解决冷启动，过多导致过拟合。
- **Token 与延迟高效**：推理 token 稳定、存储增长极小；构建延迟与检索延迟远低于 THEANINE 和 MemoryOS，Session 5 总处理时间仅 10.22s（对比 MemoryOS 826.61s）。
- **奖励模型鲁棒**：即使使用 1B 参数的弱 Judge，性能下降也很小，框架不依赖特定奖励模型。

## 7. 优点

- **范式创新**：首次将长期对话记忆从被动归档转变为可学习的交互式策略，提出 plug-and-play 的在线 RL 框架，支持自主测试时适应。
- **机制设计精巧**：
  - **跨会话真实奖励**将未来反馈回溯至历史存储决策，解决记忆效用延迟验证问题；
  - **代理奖励 + 遗漏惩罚**保障早期探索阶段高价值信息不被丢失；
  - **回顾式会话合成**通过反向生成保证因果一致性，有效缓解冷启动。
- **双智能体协同**：Planner 与 Trigger 共享 Actor-Critic 并共同演化，形成闭环优化。
- **实验全面且严谨**：覆盖 3 个真实数据集、多种 backbone、多类基线，消融、缩放、效率、鲁棒性、人工评估一应俱全，并报告统计显著性。
- **工程实用性**：token 消耗稳定、延迟低至毫秒级、可插拔集成闭源 LLM，具备实际部署潜力。
- **认知心理学启发**：将人类选择性编码与反馈更新机制引入对话记忆，具有较强的理论支撑。

## 8. 不足与局限

- **应用范围受限**：论文明确声明专注于开放域陪伴式对话与个性化对齐，不涉及复杂推理、数学、编码或标准问答等严格事实检索任务。
- **领域验证单一**：仅在对话领域验证，虽提出通用范式，但未在更广泛的时间依赖任务中测试。
- **算力信息缺失**：未报告 GPU 型号、数量、训练时长等关键算力细节，影响可复现性与资源评估。
- **评估偏差风险**：
  - LLM-as-a-Judge 与人工评估均可能引入主观偏差；
  - 人工评估仅 5 名内部评估者、每数据集 50 个样本，样本量有限；
  - 自动指标（BLEU、ROUGE）在开放域对话中的有效性本身存在争议。
- **奖励依赖 LLM Judge**：虽然鲁棒性实验表明弱 Judge 也可用，但核心训练仍依赖 LLM 评分，可能继承其偏见与不稳定。
- **超参数敏感性**：λ=0.5 最优，偏离会带来性能下降，实际部署需调参。
- **长期演化验证有限**：共演化实验仅扩展到 10 个会话，更长周期的稳定性与灾难性遗忘风险未充分探讨。
- **基线可比性**：部分基线（如 THEANINE）在不同 backbone 下表现差异较大，跨方法比较需谨慎。
