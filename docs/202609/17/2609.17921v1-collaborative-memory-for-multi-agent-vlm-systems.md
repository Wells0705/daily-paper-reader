## 摘要
视觉语言模型（VLM）智能体结合专门的感知、工具与推理来处理复杂的视觉任务。在多智能体场景中，不同智能体会检查不同的图像区域、视频帧或视觉表示，因此协作不再局限于分布式推理，还延伸到分布式感知。这使得共享视觉上下文成为VLM智能体协作中的核心问题。本文围绕协调不同解释并更新依赖推理的需求，来构建记忆层次、跨智能体共享与一致性机制。有效协作要求智能体基于其他智能体的贡献继续推进，恢复缺失的视觉上下文，并随着新证据的出现协调不同解释。共享视觉记忆不仅保留图像或文本摘要，还保留观察、智能体解释与后续推理之间的依赖关系。这些设计考量共同决定了信息在VLM智能体之间如何流动与演化。所提框架为构建可靠且资源高效的智能体团队提供了基础。

## Abstract
Vision-language model (VLM) agents combine specialized perception, tools, and reasoning to address complex visual tasks. In multi-agent settings, different agents inspect different image regions, video frames, or visual representations, so collaboration extends beyond distributed reasoning to distributed perception. This makes shared visual context a central problem in VLM agent collaboration. In this paper, we frame memory hierarchy, cross-agent sharing, and consistency mechanisms around the need to reconcile interpretations and update dependent reasoning. Effective collaboration requires agents to build on contributions from other agents, recover missing visual context, and reconcile differing interpretations as new evidence emerges. Shared visual memory preserves not only images or textual summaries but also the dependencies among observations, agent interpretations, and subsequent reasoning. Together, these design considerations shape how information flows and evolves across VLM agents. The proposed framework provides a foundation for building reliable and resource-efficient agent teams.

## 1. 核心问题与整体含义（研究动机与背景）

- **基本定位**：本文是一篇 6 页的**框架/立场型（position/framework）论文**，而非实证研究论文。它不为某个具体任务提出可训练模型或算法，而是为"多智能体 VLM 系统如何共享视觉记忆"提出一套**设计框架与研究议程**。

- **问题起点**：VLM 智能体把视觉观测与文本指令结合，并通过任务上下文、外部工具、辅助模型扩展为有目标的感知-推理系统。在**多智能体**场景下，不同智能体检查**不同的图像区域、视频帧或视觉表示**，因此协作不再只是"分布式推理"，而是扩展为**分布式感知**。

- **核心难题**：共享视觉上下文。中间视觉观测与解释必须在**跨智能体边界**上保持**可访问、可验证、可修订**。仅交换最终答案不够——智能体需要发现别人看到了什么、补齐缺失证据、并在早期解释变化时重新审视结论。

- **张力（tension）**：视觉任务中"专精分工"与"共享理解"相互冲突。
  - 图表/信息图任务需要把图形元素与标签、版式联合解读；一个智能体在小区域上很高效，但该区域可能恰好缺少协作者所需的图例。
  - 修改"柱—标签"关联可能在**像素完全不变**的情况下使另一智能体的比较结论失效。
  - 因此，**对局部工作充分的信息，对协作者可能不足以复用或校验**。

- **典型场景驱动**：
  - 移动界面操作、长视频推理；
  - 流式视频（既要及时响应，又要持续观测并访问早期上下文）；
  - 病理切片复核（吉像素级切片局部细节 + 整体组织上下文 + 报告）。

- **与已有工作的差异**：LLM 智能体记忆研究（MemGPT、A-Mem 等）多关注**单智能体**的上下文管理与结构化记忆；新近工作开始研究跨智能体/跨模型的选择性记忆共享（INMS、G-Memory、DecentMem、MAGE）。本文认为，对 VLM 团队而言，额外要求是：**观测与解释必须始终链接到可让他人复用、验证、修订的视觉上下文**。

- **三个核心设计问题**：
  1. 记忆应如何把局部观测链接到协作者所需的上下文？
  2. 访问方式应如何适配接收方的任务与模型接口？
  3. 修订发生后，应如何促使协作者复查依赖该修订的结论？

## 2. 方法论：核心思想、关键机制与流程

### 2.1 核心思想

- 以**"观测—解释—后续推理"之间的依赖关系**为组织中心，构建**共享视觉记忆**。
- 三条设计支柱互相依赖：**记忆层级**（决定保留什么上下文）、**跨智能体共享**（决定可用表示如何被访问）、**一致性机制**（使修订对依赖方可见）。

### 2.2 情景设定（贯穿全文的示例）

- 以**航天器热真空测试**为例（引用 JWST 集成科学仪器模块的低温真空测试，原始数据达 TB 级）。
- 四个角色：
  - **A 图例智能体**：工程图纸理解模型 + 传感器位置记录，把绘图颜色关联到部件；
  - **B 图表智能体**：标定记录、时序分析工具、热仿真模型，解读温度峰值与梯度；
  - **C 表格智能体**：测试规程 + 表格抽取工具，选取当前阶段与硬件配置对应的限值；
  - **D 推理智能体**：汇总贡献并发起进一步检查。
- 具体数据：光敏探测器峰值 38 K（限值 40 K）、光学反射镜峰值 47 K（限值 50 K）。
- 关键依赖：B 需要 A 提供的图例；B 与 C 可并行；D 的比较需要信息在任务间传递。

### 2.3 记忆层级（Memory Hierarchy）

- **三层结构**：
  1. **智能体本地缓存**：近期观测 + 模型特有特征；
  2. **共享工作记忆**：证据、主张（claims）、未完成请求；
  3. **持久存储**：可复用证据与团队经验。
- **关键区分**：**访问范围（access scope）与保留时长（retention lifetime）是两个独立选择**；持久记录也可以是私有的；三层存储**不必物理分离**。
- 流式视频示例：一个智能体缓存近期帧并发布事件描述，链接到可检索的带时间戳片段；其他智能体检查更早片段或整合共享发现。
- **关键设计点**：共享工作记忆必须区分"已检查区间"与"待检查区间"，避免把**延迟处理误判为无事件**。

### 2.4 链接表示（Linking Representations）

- 多种表示并存，**不构成保真度的全序关系**：
  - 源图像与裁剪图（保留可见证据，避免团队完全依赖文本描述）；
  - 视觉特征（视觉编码器输出的向量）；
  - 结构化观测（带边界框的识别文本、表格单元、区域关联）；
  - 主张（claims，对智能体解释的概括）。
- 举例说明互补性：裁剪图可能丢失远处图例，而简洁的结构化记录却能完整描述某个比较。
- **Provenance（来源追溯）**：记录来源区域、贡献智能体、该解释引用的先前观测。例如"探测器峰值 38 K"这一主张需同时链接到柱与图例关联。
- **机制要点**：稳定来源标识符 + 坐标支持检索；解释之间的显式链接支持后续修订。

### 2.5 选择性共享（Selective Sharing）

- 共享多少、以何种形式共享，取决于**接收方被分配的工作**：
  - D 若要校验某温度值，需要部件、测试阶段、区间、峰值、单位、来源引用；
  - B 若要校验关联，则需同时查看柱与图例。
- **共享策略**按接收方的**操作类型、模型接口、可用工具、预算**选择相关证据与适配表示。
- **访问接口**需标明：表示形式、来源、所读解释的版本、以及检索证据所需权限。

### 2.6 跨模型共享（Sharing Across Models）

- 视觉交换与适配器支持超越自然语言的通信（如 Vision Wormhole 通过视觉输入接口传递隐式推理，为不同 VLM 家族配备编码器/解码器）。
- **复用编码视觉特征**可减少重复视觉处理，但不同 VLM 在**特征维度、位置编码、输入接口**上存在差异。
- 一种可行做法：用**适配器**把存储特征映射到接收模型的输入空间，而**保持共享表示固定**；若接口不暴露特征输入，接收方只能使用图像或其他表示。
- **重要约束**：跨模型特征复用必须**保留与视觉来源的链接**，不能只匹配张量维度。
- **评价标准**：复用价值取决于**协作推理质量**与**总成本**（适配、编码、检索、重复检查），而非兼容性或压缩率本身。

### 2.7 一致性与调和（Consistency and Reconciliation）

- **调和解释**：
  - 一致性取决于各智能体的解释是否建立在**兼容的证据、来源状态与上下文假设**之上；
  - 冲突可能源于检查了不同区域/帧/来源版本，因此调和首先要确认冲突主张是否条件于同一证据；
  - **一致同意不等于独立确认**——多个智能体可能继承同一错误解释；
  - 共享记忆应保留各智能体检查过的证据及其派生解释，以支持**证据级调和与定向复查**。
- **修订依赖推理**（流程示例）：
  1. B 起初把反射镜峰值 47 K 误配给探测器 → D 标记其违反 40 K 限值；
  2. B 对照 A 的图例复查已保存的柱 → 探测器实为 38 K；
  3. B 修订关联后，**D 必须用 C 未变的限值重新计算**；
  4. 若不重算，共享记忆中会同时存在"修订后的关联"与"基于旧版本的结论"。
- **理论渊源**：真值维护系统（Doyle, 1979）用记录的理由支持信念修订；对话记忆中的过时信息处理（Mem0、LongMemEval）亦有积累；本文的增量在于——视觉任务中，**修订必须跟踪那些在源图像与抽取数值均未改变时仍会变化的关联**。
- **提议机制**：把派生主张链接到支撑性解释，使贡献智能体能**请求复查依赖结论**；但注意，复查请求只**标识需要复查的工作，并不确立替代答案**。
- **修订的传播**：
  - 若 D 已在用 B 的早期解释推理，**更新共享记录并不会更新 D 的本地上下文**；D 在发布结果前应检查存储主张是否仍与所用一致；
  - **并发的冲突主张应保持可区分，而不是静默互相覆盖**。
- **可靠性与同步权衡**：
  - 等待全部观测被验证会**阻塞协作**；带着未验证主张继续会**扩散错误**；实用策略需在**延迟与错误传播**之间平衡，同时保留备选解释、使修订可见；
  - 记录的依赖支持**选择性复查**，但**缺失链接**会导致受影响结论未被检查，此时需要**更大范围的重检**；
  - **记录交付给智能体的输入，并不等于确立模型实际使用了哪些输入**；即使记录自洽也可能整体错误，且验证本身也可能引入错误；
  - 目标是**可靠的联合推理，且不必让每个智能体重复每个观测**。

### 2.8 未来方向（文中提出的研究议程）

- **记忆与任务分配的联合优化**：证据需求或可用工具变化时，需重新考虑"谁检查哪份证据、协作者收到什么上下文"；核心问题是如何**联合学习任务分配**与**共享记忆中观测/解释/未决请求的选择**，并以**正确性 + 通信与处理成本**作为反馈，与固定角色（按需请求上下文）作对比。
- **从反复协作中学习**：借鉴语言智能体的经验学习（Reflexion、ExpeL），从成功与失败中蒸馏可复用流程；保留经验时须链接其**支撑证据、独立校验的结果、适用条件**，后续修正应触发对相关经验的复查；在新任务上评估**迁移性**；目标是"更少重复处理或延迟的正确修订"，并计入维护成本；短任务、罕见修订、影响多数结论的变更，可用于检验**维护成本何时超过收益**。
