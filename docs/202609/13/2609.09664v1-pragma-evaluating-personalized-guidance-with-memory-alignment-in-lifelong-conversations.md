## 摘要
大语言模型（LLM）越来越多地被部署为与用户进行长期交互的个性化助手。随着对话变得越来越长，依赖完整交互历史会变得愈发低效且不可靠：长上下文会带来大量计算开销，使模型难以持续识别并利用与当前请求最相关的信息。这些挑战推动了能够组织和检索用户特定信息的记忆系统的发展。在真实交互中，用户常常寻求实用指导，例如推荐、规划和决策支持。与事实回忆任务不同，个性化指导要求模型整合多次过往对话中的信息，并对用户不断变化的偏好和经历进行推理。然而，现有的对话记忆评估主要关注检索和事实回忆。为研究这一挑战，我们提出了 PRAGMA，一个用于评估长期对话中个性化指导的基准。PRAGMA 包含精心整理的纵向对话历史、证据标注，以及基于不断变化的用户情境和错误用户假设的指导场景。在检索系统、记忆系统和长上下文模型上的实验表明，当前系统既难以找回合适的对话证据，也难以将其有效用于个性化指导。我们的结果强调了需要这样的记忆架构：它支持稳健的对话检索，以及超越证据回忆的、以记忆为基础的推理。

## Abstract
Large language models (LLMs) are increasingly deployed as personalized assistants that interact with users over extended periods of time. As conversations grow longer, relying on full interaction histories becomes increasingly inefficient and unreliable: long contexts introduce substantial computational overhead, making it difficult for models to consistently identify and utilize the most relevant information for the current request. These challenges have motivated memory systems that structure and retrieve user-specific information. In realistic interactions, users often seek practical guidance such as recommendations, planning, and decision support. Unlike factual recall tasks, personalized guidance requires models to integrate information across multiple past conversations and reason about changing user preferences and experiences. However, existing conversational memory evaluations mainly focus on retrieval and factual recall. To study this challenge, we introduce PRAGMA, a benchmark for evaluating personalized guidance in long-term conversations. PRGAMA contains curated longitudinal conversation histories, evidence annotations, and guidance scenarios grounded in evolving user contexts and incorrect user assumptions. Experiments across retrieval systems, memory systems, and long-context models reveal that current systems struggle both to recover the appropriate conversational evidence and to effectively use it for personalized guidance. Our results highlight the need for memory architectures that support robust conversational retrieval and memory-grounded reasoning beyond evidence recall.

## 1. 核心问题与整体含义

- **研究动机**：LLM 正被广泛部署为长期个性化助手（推荐、辅导、生产力助手等）。随着对话历史增长，直接依赖完整历史带来两大问题：一是计算开销巨大，二是模型难以持续、稳定地定位当前请求最相关的信息。这催生了选择性存储与检索用户信息的记忆系统。
- **现有评测缺口**：已有对话记忆基准（LongMemEval、LoCoMo、ConvoMem、PersonaMem、HiCUPID、ImplexConv 等）主要关注**检索与事实回忆**，或采用多选题/显式画像条件设定，对**开放式个性化指导**（推荐、规划、决策支持）覆盖不足。
- **真正的难点**：个性化指导要求模型（1）整合跨多轮对话的信息；（2）推理用户随时间演化的偏好与经历；（3）识别并纠正用户与历史相冲突的错误假设。相关证据往往**时间上分散**、与最终请求**仅隐式关联**，使检索本身也极具挑战。
- **构建难点**：合成长期对话若设计不当，易产生浅层轨迹，或出现可用"最近性启发式"和词面匹配轻易解决的查询。
- **整体含义**：论文提出 **PRAGMA**（PRActical Guidance with Memory Alignment）基准，主张个性化指导的瓶颈不仅是"能否检索到证据"，更是"能否把证据有效地用于生成"。研究强调需要同时支持稳健对话检索与记忆落地推理的记忆架构。

## 2. 方法论

### 2.1 核心思想：二维查询分类法
- 两个正交维度：
  - **记忆动态（Memory Dynamics）**：静态的**事件级经验** vs. 演化的**纵向用户轨迹**。
  - **查询对齐（Query Alignment）**：用户假设与历史证据**一致** vs. **冲突需纠正**。
- 组合得到四类查询：
  - **Event-Align**：基于连贯事件级经验给出指导；
  - **Event-Correct**：用户对事件级经历有错误回忆，需先纠正再指导；
  - **Traj-Align**：需推理跨时间演化的用户轨迹；
  - **Traj-Correct**：用户拟议决策与长期轨迹冲突，需给出纠正性指导。

### 2.2 基准构建流程
- **用户模式设计**：从 Privasis-Zero 选取 100 个合成用户，提取人口统计属性（年龄、收入阶层、母语、国籍等）与事件列表；用 **gpt-5** 为每人生成（1）一句话人格摘要，（2）事件主题，（3）两条**相互独立**的潜在行为轴。
- **事件级查询构造**：生成 2–5 个带时间戳的事件（时间跨度 2025-05-01 至 2026-04-30）。
  - Event-Align：查询提及主题作为检索线索，但要求模型解释过往经历应如何影响建议。
  - Event-Correct：混合多个过往事件构造"部分错误"的回忆，用户基于错误前提求建议，需模型先发现不一致。
- **轨迹级查询构造**：生成 4–8 个带时间戳的纵向状态，跨**两条同时演化**的行为轴（避免单轴退化为"取最近状态"）。
  - Traj-Align：用户显式提及轴所对应的抽象特质，轴在写入查询前被改写为抽象描述符（如单词概念），避免词面捷径。
  - Traj-Correct：构造单独看合理、但与长期轨迹（需联合两轴推理）相冲突的决策。
- **对话历史构造**：每个证据项用 **gpt-5-mini** 扩展为自然会话；另为每人生成 **30 个与目标主题/轨迹轴无关**的填充主题并扩展为会话。证据会话按时间排序，填充会话**均匀插入**，且**首尾必为填充会话**，以抑制位置与最近性启发式。
- **人工验证**：6 名标注者（3 位共同作者、2 位 NLP 研究者、1 位语言学研究者），对查询现实性、证据正确性、类型一致性、是否存在浅层捷径做二元 yes/no 判断，可提出改写。论文明确**不报告标注者间一致性**，并说明验证以质量控制为主、未做穷尽双标注。
- **标注与评估协议**：
  - **检索评估**：标注每查询所需的证据会话，报告 Recall、Precision、F1 与 **Exact Recall**（是否召回全部所需证据），主要在会话级。
  - **响应评估**：以 **gpt-5** 为 LLM judge，按查询类型专属 rubric 打两个维度分：
    - **Alignment**：与用户经历/纵向历史的一致性；
    - **Grounding**：响应是否显式引用标注证据。
    - 四类查询 × 两维度 = **8 套 rubric**。
  - 元数据包含查询类型、证据会话、gold response（基于摘要证据 + rubric 生成）与 no-context response。

## 3. 实验设计

- **Benchmark（即 PRAGMA 本身）**：100 用户、400 查询（每类 100）；共 4,167 个会话，其中事件会话 494、轨迹会话 673、填充会话 3,000（占 72.0%）。平均每用户 41.67 个会话、323.92 轮；每用户约 160K tokens 历史（范围 127K–194K）；每查询平均需 4.91 条证据，证据平均跨度 282.8 天；查询平均 44.6 tokens。
