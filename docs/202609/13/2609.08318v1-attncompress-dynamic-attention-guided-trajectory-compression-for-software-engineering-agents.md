## 摘要
从以人为中心的辅助转向自主软件工程（ASE）智能体，使得解决复杂的真实世界软件工程任务成为可能。然而，这些智能体的试错特性会生成冗长的交互轨迹，在上下文窗口限制和成本方面造成严重瓶颈。尽管上下文压缩提供了一种潜在补救方法，但先前方法受限于静态剪枝策略和粒度不匹配，往往无法保留对软件工程任务至关重要的语义依赖和句法细节。为了在减少上下文长度的同时严格保留关键任务证据，我们提出了 AttnCompress，一种动态注意力引导的轨迹压缩框架。与现有方法不同，AttnCompress 通过三种关键机制弥合了语义完整性与动态适应性之间的差距：（1）基于困惑度（PPL）突增的结构感知分段，以保留代码和日志的句法结构；（2）使用代理注意力权重的相关性估计，以量化历史块与智能体当前推理的精确相关性；（3）动态滚动窗口，随着任务演进重新评估并召回历史上下文。在 SWE-Bench-Verified 和 Multi-SWE-Bench 上的大量评估表明，AttnCompress 达到了 53.17% 的通过率，优于先前最先进的基线，同时将 token 消耗降低了 21.6%，总成本降低了 33.6%。该框架被证明是模型无关的，并能有效泛化到多种编程语言。

## Abstract
The transition from human-centric assistance to Autonomous Software Engineering (ASE) agents has enabled the resolution of complex real-world SE tasks. However, the trial-and-error nature of these agents generates lengthy interaction trajectories, creating severe bottlenecks in terms of context window limits and cost. While context compression offers a potential remedy, prior approaches suffer from static pruning strategies and granularity mismatches, often failing to preserve the semantic dependencies and syntactic details crucial for SE tasks. To strictly preserve critical task evidence while reducing context length, we introduce AttnCompress, a dynamic attention-guided trajectory compression framework. Unlike existing approaches, AttnCompress bridges the gap between semantic integrity and dynamic adaptability through three key mechanisms: (1) structure-aware segmentation via perplexity (PPL) spikes to preserve the syntactic structure of code and logs; (2) relevance estimation using proxy attention weights to quantify the precise relevance of historical blocks to the agent's current reasoning; and (3) a dynamic rolling window to re-evaluate and recall historical context as the task evolves. Extensive evaluation on SWE-Bench-Verified and Multi-SWE-Bench demonstrates that AttnCompress achieves a pass rate of 53.17%, outperforming prior state-of-the-art baselines while reducing token consumption by 21.6% and total costs by 33.6%. The framework proves to be model-agnostic and generalizes effectively across diverse programming languages.

## 1. 核心问题与研究动机

- **背景**：自主软件工程（ASE）智能体（如 SWE-agent、Trae-Agent）以 ReAct 循环（Thought → Action → Observation）解决真实 GitHub Issue，取得显著进展。
- **核心痛点**：智能体的"试错"特性产生冗长交互轨迹，导致上下文窗口溢出、API 成本上升、推理延迟增加，并诱发"Lost-in-the-Middle"推理退化。
- **关键数据**：作者统计轨迹 token 分布发现 **Observation（工具输出）占 62.6%**，远高于 Action（24.8%）、Thought（8.6%）与 Task Input（4%），因此压缩观测内容是效率瓶颈的核心。
- **现有方法的两大缺陷**：
  - **无法处理动态上下文依赖**：ObsMask、AgentDiet 等采用"静态一次性"压缩，剪枝不可逆；而 SE 调试中智能体常发生 **焦点漂移（focus shifting）**（如从 `auth_service.py` 转向早前看过的 `utils.py` 的 regex 问题），被丢弃的历史无法召回。作者抽样 100 条轨迹，发现 **40 条存在焦点漂移问题**。
  - **粒度不匹配与精度损失**：粗粒度（消息级）压缩会保留整段冗余日志（如 `django-11133` 中 700+ 行噪声中仅 15 行有用）；细粒度（token 级，如 Lingua）会破坏 JSON/AST 结构；摘要式（AgentDiet）依赖 LLM 重写，存在丢失行号/变量名等细节及幻觉风险，且额外 LLM 调用带来高开销。

## 2. 方法论：AttnCompress 框架

**核心思想**：作为插入轨迹管理器与后端 LLM 之间的**即插即用、免训练中间件**，通过三个连续阶段实现"结构保真 + 动态适应"的轨迹压缩。

- **阶段一：基于 PPL 尖峰的结构感知分段**
  - 将工具输出按行切分，用小型代理模型计算每行平均困惑度 PPL（式 1）。
  - 计算相邻行 PPL 差值 $D_i = |PPL(l_i) - PPL(l_{i-1})|$，用自适应阈值 $\tau = \mu + h \cdot \sigma$ 检测局部极大值作为语义边界。
  - 单行碎片块与前一块合并，得到语义连贯的块序列 $B=\{b_1,...,b_m\}$，避免破坏 JSON/函数体语法。（论文采用非重叠分段，指出重叠方案留作工程改进。）

- **阶段二：基于代理注意力的重要性估计**
  - **输入构造**：`压缩/原始历史 + 新观测 O_new + 查询 token q_gen`（如 `<|im_start|>` 生成起始 token，置于序列末尾）。
  - **打分**：对代理模型做一次前向传播，**同时**获得 PPL 所需 logits 和注意力图；块 $b_i$ 的得分为查询 token 到块内所有 token 注意力权重的均值（式 2）。
  - **贪心选择**：按得分降序累加块，直到达到 token 预算 $L_{budget} = \rho \cdot \sum|b_i|$（默认 $\rho=0.2$），未选中块丢弃。

- **阶段三：动态滚动窗口维护（三层记忆 + 双模式）**
  - **Immediate Memory**：最近 $k$ 轮（默认 k=2）保持原始未压缩。
  - **Short-term Memory**：中间区域作为滚动缓冲区，每轮针对当前查询重新打分与压缩。
  - **Long-term Memory**：固定归档区，默认保持文本不变以**最大化前缀缓存命中率**。
  - **Mode 1 增量更新**（常规）：仅重压短期区，与已压缩长期归档拼接。
  - **Mode 2 全局刷新**（短期缓冲区累积超过阈值 M=10 时触发）：合并长期与短期，全局重选，允许"复活"此前被丢弃的深层历史块，并推进归档指针（代价是缓存失效，但频率低）。

- **实现细节**：集成进 Trae-Agent；代理模型选用 Qwen3-4B-Instruct；默认超参：k=2、ρ=0.2、PPL 阈值 -2、注意力层取最后一层、M=10。

## 6. 主要结论与发现

- **效果**：SWE-Bench-Verified 平均通过率 **53.17%**，为所有压缩方法最高，较 SOTA AgentDiet（51.17%）相对提升 3.9%，且在三个后端 LLM 上均全面领先。

- **方法层面**：
  - 巧妙将 PPL 分段与代理注意力**合并进单次前向传播**，几乎零额外推理成本。

  - 完全**免训练、模型无关、即插即用**，不依赖特定代理框架或模型族。
- **实验层面**：
  - 多维评估体系（通过率 + token + 金钱成本 + 延迟 + 步数），并区分 $C_{agent}$ 与 $C_{comp}$。

## 8. 不足与局限

- **压缩仍存在信息损失**：主要失败模式是仍可能丢弃后续变得重要的文件路径、辅助函数或错误信息，导致智能体无法在剩余步数内恢复。
- **与全上下文仍有差距**：SWE-Bench-Verified 上 53.17% vs Original 55.17%，Multi-SWE-Bench 上 19.67% vs 20.33%，未实现无损压缩。
- **框架泛化性验证不足**：受算力限制，仅在一个代理框架（Trae-Agent）上评估，跨框架可迁移性仅有理论论证。
- **代理注意力与端到端性能关系不清晰**：Table 5 的注意力对齐排名与 Table 6 的端到端通过率排名**并不严格一致**（如 1.7B 对齐度最高但通过率最低），作者归因于差异过小与智能体随机性，机制解释尚不充分。
- **分段策略简化**：采用非重叠分段，作者自承块间重叠可能改善跨边界连贯性，但未实现。
- **效度威胁**：
  - **内部效度**：专有 LLM 可能存在 SWE-Bench 数据泄露（以 Multi-SWE-Bench 缓解，但未根除）。
  - **构造效度**：基于测试通过（plausible）判定成功，不等价于开发者语义修复（correct）。
  - **成本假设**：代理模型按 API 定价折算，与实际本地部署成本结构可能不符。
- **超参与算力门槛**：依赖 8×A100 环境，代理模型层选择、PPL 阈值等虽表现出鲁棒平台期，但仍需初步调参；小模型（1.7B）对长程依赖识别能力不足。
