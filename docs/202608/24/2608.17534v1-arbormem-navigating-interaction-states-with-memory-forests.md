## 摘要
大语言模型日益作为持久性对话助手，需要记忆来保留相关经验并维持跨交互的连续性。现有方法通过长上下文处理、选择性检索和结构化记忆组织来改进对对话历史的访问。然而，大多数系统将记忆访问视为检索相关过去信息，而没有首先确定当前回合恢复的是哪个先前交互状态。当对话交织多个可能被中断并稍后重访的任务、人员和计划时，这一局限变得尤为重要。我们提出ArborMem，一种在线记忆框架，将长期对话表示为可导航的交互状态森林。每个分支保留一条局部连贯的轨迹，而森林则维护多条可能稍后恢复的轨迹。对于每个新输入，ArborMem定位相关状态，恢复其分支局部上下文，并跨分支检索可复用证据进行增强，从而在不混淆语义相关但结构不同的轨迹的情况下保持交互连续性。现有的长期记忆基准涵盖了多种记忆与推理能力，但并未明确分离分支结构挑战。因此，我们引入BranchMemEval，一个用于交织且可恢复交互轨迹的受控诊断基准。在LongMemEval、LoCoMo、BEAM 100K和BranchMemEval上的实验表明，ArborMem在三个既定基准上比最强基线高出3.36至10.31个百分点，在BranchMemEval上高出5.0个百分点。在受限读取预算下其优势增大，同时完整记忆查询保持在半秒以内。

## Abstract
Large language models increasingly serve as persistent conversational assistants, requiring memory that preserves relevant experience and maintains continuity across interactions. Existing methods improve access to conversational history through long-context processing, selective retrieval, and structured memory organization. However, most systems treat memory access as retrieving relevant past information without first determining which prior interaction state the current turn resumes. This limitation becomes particularly important when conversations interleave multiple tasks, people, and plans that may be interrupted and later revisited. We introduce ArborMem, an online memory framework that represents a long-running conversation as a navigable forest of interaction states. Each branch preserves a locally coherent trajectory, while the forest maintains multiple trajectories that may later be resumed. For each new input, ArborMem localizes the relevant state, restores its branch-local context, and augments it with reusable evidence retrieved across branches, preserving interaction continuity without conflating semantically related but structurally distinct trajectories. Existing long-term memory benchmarks cover diverse memory and reasoning capabilities but do not explicitly isolate branch-structured challenges. We therefore introduce BranchMemEval, a controlled diagnostic benchmark for interleaved and resumable interaction trajectories. Experiments on LongMemEval, LoCoMo, BEAM 100K, and BranchMemEval show that ArborMem outperforms the strongest baselines by 3.36 to 10.31 percentage points on the three established benchmarks and by 5.0 points on BranchMemEval. Its advantage grows under constrained read budgets, while complete memory queries remain below half a second.

## 1. 核心问题与整体含义（研究动机和背景）

长期对话记忆的核心挑战在于：当对话中交织着多个任务、人物、计划，且这些轨迹可能被中断并稍后恢复时，现有系统往往无法正确判断当前回合究竟延续的是哪一条历史轨迹。

现有方法（长上下文模型、检索增强、结构化记忆系统）的共同局限是：**将记忆访问视为“检索相关过去信息”，而忽略了“定位当前对话所恢复的交互状态”这一前置步骤**。例如，一段对话可能交织“论文修改”和“会议出行”两条轨迹，当用户问到“修订后的数字他上传了吗”，语义上最相近的近期上下文是会议出行，但正确回答需要回溯到更早的论文修改轨迹。若仅依赖语义相关性检索，容易混淆这两条结构不同但语义相关的轨迹。

ArborMem 的核心主张是：**在检索历史证据之前，必须先确定当前输入恢复了哪条交互轨迹**。这是对长期对话记忆范式的一个重要补充——从“记住什么、怎么组织、怎么检索”进一步延伸到“当前对话处于哪个状态”。

## 2. 论文提出的方法论（核心思想、关键技术细节、公式或算法流程）

### 2.1 整体框架

ArborMem 将长期对话记忆建模为一个**可导航的交互状态森林**。系统状态定义为：

> **Sₜ = (Fₜ, Mₜ)**

其中：
- **Fₜ（对话森林）**：每个节点代表一次用户-助手交互后建立的局部状态；父边表示状态延续；从根到节点的路径构成一条局部连贯的轨迹。
- **Mₜ（可复用证据库）**：存储可从原轨迹外复用的信息，包括原子事实（如偏好、日期、项目细节）和结构化记录（如助手生成的内容、事件、可变状态条目），每项保留来源和修订元数据。

### 2.2 三个核心阶段

**阶段一：状态定位（State Localization）**

对于每个新输入 uₜ，系统优先定位应恢复的交互状态，遵循优先级级联：
- **快速路径**：显式延续线索直接附加到活动状态；显式时间回溯线索通过全局时间线解析。
- **常规路径**：构建混合候选集 Cₜ，包含三类来源——语义召回（FAISS 向量搜索）、关键词/实体召回、主题锚点匹配。

每个候选节点通过**分支感知表示**（主题键 + 路径摘要 + 节点摘要 + 实体）进行重排序。定位得分为：

> **sₜ(v) = s_ce(v) + s_key(v) + s_rec(v) + s_topic(v)**

父状态选择规则：

> **pₜ = arg max sₜ(v)（若 max sₜ(v) > τ），否则 ∅（开新根）**

**阶段二：上下文组装与生成（Context Assembly & Generation）**

- 恢复根到 pₜ 的路径作为**分支局部轨迹**（主要上下文）。若轨迹长度超出预算，将较早前缀压缩为摘要，保留最近的原始回合。
- **跨分支证据检索**：从三个来源补充——轨迹外的补充回合、可复用原子事实、结构化记录。
- 将四个记忆通道与当前输入组装为证据包：

> **Eₜ = {C_localₜ, E_turnₜ, E_factₜ, E_structₜ, uₜ}**

最终响应：**aₜ = G(Eₜ)**

**阶段三：在线提交（Online Memory Commit）**

生成完成后才进行内存更新：
- 新交互作为所选父节点的子节点插入（或成为新根）。
- 更新路径摘要、语义/关键词索引、结构元数据、活动状态指针。
- 后生成提取器识别可复用原子事实和结构化记录，链接到源节点，通过修订元数据标记过时信息。
- **因果边界**：aₜ 只依赖先前已提交的状态 Sₜ₋₁，从本次交互提取的信息只能从 t+1 回合开始可读。

## 3. 实验设计（数据集 / 场景 / Benchmark / 对比方法）

### 3.1 评测基准

| 数据集 | 规模与特点 | 评估内容 |
|---|---|---|
| LongMemEval | 500 个问题 | 信息抽取、多会话推理、时间推理、知识更新、弃权 |

### 3.2 BranchMemEval 设计

覆盖五个诊断维度：
- **B1 Backjump**：在干预对话后恢复较早轨迹（26 题）
- **B2 State update**：在正确轨迹内检索最新值（16 题）
- **B3 Assistant artifacts**：记忆助手生成的列表和记录（24 题）
- **B4 Cross-branch bridging**：跨轨迹组合证据（14 题）
- **B5 Twin threads**：区分结构相似的平行议程（20 题）

构造方式为程序化规划 + LLM 自然语言实现，自动验证答案可支持性、防泄漏、平行轨迹可区分性。

### 3.3 对比基线（8 个）

- **直接上下文类**：Full-context、Recent
- **检索/压缩类**：BM25、Session Summary
- **结构化记忆类**：Graphiti、A-MEM、Mem0、LiCoMemory

### 3.4 主实验结论

ArborMem 在所有四个基准上均取得最优结果：
- LongMemEval：68.40%（优于最强基线 9.00 点）
- LoCoMo：53.15%（优于最强基线 10.31 点）
- BEAM 100K：49.75%（优于最强基线 3.36 点）
- BranchMemEval：81.00%（优于最强基线 5.00 点）

## 6. 论文的主要结论与发现

1. **状态定位是长期记忆的关键前提**：在检索历史证据前，先确定当前输入恢复的交互轨迹，能显著提升对话连续性。

2. **ArborMem 在多个基准上一致优于现有方法**：在 LongMemEval、LoCoMo、BEAM 100K 上超过最强基线 3.36–10.31 个百分点，在自建 BranchMemEval 上领先 5.0 个百分点。

3. **受限读取预算下优势更明显**：在 256–1K tokens 的高度受限预算下，ArborMem 超出最强竞争者 16–26 个百分点，说明状态定位能显著提升证据选择效率。

4. **全文历史暴露不等于可靠使用**：BranchMemEval 中 Full-context 方法准确率仅 66%，而 ArborMem 达到 81%，验证了"可见性 ≠ 可用性"的论点。

5. **消融实验确认各组件互补**：状态定位的去除使 30B 设置下准确率从 82% 降至 70%（降幅 14.6%），原子事实检索对较大模型效应最大，结构化提取对较小模型效应最大。

6. **实际部署可行**：完整记忆查询延迟低于半秒，内存构建成本为每回合 1.363 秒，端到端吞吐量（10.45 题/小时）优于 Mem0 和 A-MEM。

## 7. 优点（方法或实验设计上的亮点）

1. **问题定位精准**：识别出"交互状态定位"这一被现有工作忽视的关键步骤，具有清晰的实际意义。

2. **记忆拓扑设计新颖**：采用森林结构（单亲节点）而非纯图结构，既保证了清晰的主上下文路径，又支持跨分支的信息复用，避免了语义相关但结构不同轨迹的混淆。

3. **因果边界严谨**：严格保证生成后才提交内存，信息只能从下一回合开始可读，这在对话记忆系统中尤为重要。

4. **受控基准设计精巧**：BranchMemEval 使用程序化规划控制结构化变量（分支、事实槽、更新、干扰项），并设置"轨迹混淆"作为独立错误类别，能精确区分"检索失败"与"轨迹混淆"。

5. **多层级验证**：主实验覆盖 4 个基准，辅助实验覆盖读取预算、效率、消融三个维度，形成完整的证据链。

6. **工程实现细节透明**：附录提供了完整的提示词、内存模式、超参数和配置，可复现性强。

7. **公平对比设置**：共享答案模型、共享证据预算、冻结历史回放、规则化评分，最大限度减少评估偏差。

## 8. 不足与局限（实验覆盖、偏差风险、应用限制）

1. **BranchMemEval 规模有限**：仅 33 个会话、100 个问题，虽为受控诊断设计，但统计效力有限，难以确认在更广泛真实场景中的普适性。

2. **对新基准的验证不充分**：BranchMemEval 仅在一个模型（Qwen3-30B）上做了完整基线对比，未展示不同规模模型的表现差异（消融实验除外）。

3. **真实部署场景覆盖不足**：基准主要集中在"在固定历史上回答问题"，未充分覆盖开放式交互、用户主动删除记忆、错误记忆累积等真实场景。

4. **效率对比存在偏差风险**：效率实验中 ArborMem 延迟高于基线（因额外定位和分支重建），虽然端到端吞吐量最优，但基于不同数据子集（50 题）的对比可能不够全面。

5. **结构化记忆依赖性问题**：ArborMem 依赖可靠的信息提取、摘要、更新和修订能力；提取错误、过期或冲突记忆可能持续存在并累积传播错误。

6. **多意图歧义处理有限**：当前单父节点森林假设每回合只有一个明确恢复状态；对于多意图或歧义回合（可能对应多个状态），路由错误可能传播至后续记忆更新。
