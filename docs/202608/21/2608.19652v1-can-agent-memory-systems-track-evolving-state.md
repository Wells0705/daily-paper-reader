## 摘要
随着基于LLM的代理被部署用于更长且更高风险的任务，它们的记忆系统仍然存在关键缺口。虽然现有的记忆基准主要侧重于回忆型任务，但我们认为有效的记忆系统必须追踪世界状态的演化；随着事实、约束和决策在长时间交互中被修订，答案必须反映当前状态而非被取代的状态。我们将此能力定义为状态追踪，并在StateMemBench中实例化，这是一个包含234个多会话场景、跨越两种对话长度机制的基准。其封闭池评分用于判断答案是反映当前状态、被取代状态还是其他失败，从而通过构造将状态追踪失败与其他错误分离。我们的分析表明，该任务对现有记忆系统、检索增强基线和长上下文基线都具有挑战性。然后，我们提出了StateMem，一种状态优先的记忆方法，显式追踪取代关系和关系依赖，并表明在DeepSeek-V4-Flash上，其当前状态准确率比最强同骨干基线提高了1.8倍（0.205 -> 0.363），在Qwen-3.5-9B上比最强记忆系统提高了1.6倍（0.149 -> 0.233），同时与长上下文基线保持竞争力。最后，我们表明相同状态方法可以作为轻量级单调用包装器应用于现有记忆系统，在StateMemBench上通过六个记忆和检索后端将当前状态准确率提升+32到+67个百分点。一个长度和成本匹配的对照组将其中+15到+32个百分点归因于状态结构而非增加的上下文。

## Abstract
As LLM-based agents are deployed for longer and higher-stakes tasks, their memory systems continue to have crucial gaps. While existing memory benchmarks focus largely on recall-shaped tasks, we argue an effective memory system must track the evolving state of the world; as facts, constraints, and decisions are revised over a long interaction, answers must reflect the current state and not a superseded one. We define this capability as state tracking and instantiate it in StateMemBench, a benchmark of 234 multi-session scenarios spanning two conversation-length regimes. Its closed-pool grading scores whether an answer reflects the current state, the superseded state, or fails otherwise, separating state-tracking failures from other errors by construction. Our analysis shows that this task is challenging for existing memory systems, retrieval-augmented baselines, and long-context baselines. We then present StateMem, a state-first memory method that explicitly tracks supersession and relational dependencies, and show it improves current-state accuracy over the strongest same-backbone baseline by 1.8x (0.205 -> 0.363) on DeepSeek-V4-Flash and over the strongest memory system by 1.6x (0.149 -> 0.233) on Qwen-3.5-9B, while remaining competitive with the long-context baselines. Finally, we show the same state approach can be applied as a lightweight single-call wrapper over existing memory systems, lifting current-state accuracy by +32 to +67 points on StateMemBench across six memory and retrieval backends. A length- and cost-matched control attributes +15 to +32 of those points to state structure rather than added context.

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：现有 LLM 智能体记忆系统及记忆基准过度聚焦于"回忆（recall）"能力，即能否从长历史中检索到相关事实；但长期、高风险的智能体任务要求记忆系统能够**追踪世界状态的演化**——当事实、约束、决策在多会话交互中被修订后，答案必须反映"当前生效的状态"，而非已被取代的过期状态。
- **关键概念——状态漂移（State Drift）**：相关事实已存在于组装好的上下文中，但智能体却基于过期或不完整的版本作答。即障碍不在于"检索不到事实"，而在于**未能追踪该事实对当前状态的相关性**。
- **研究缺口**：现有基准（LoCoMo、LongMemEval、MemoryArena 等）未将状态追踪从回忆、推理、检索等能力中干净地剥离；作者通过跨基准标注分析发现，即使"完美检索"（oracle）条件下，状态漂移仍是占比最高的失败类别（LongMemEval oracle 上达 44.4%），说明这是一个独立且被忽视的能力维度。其整体含义是：**记忆系统设计应从"回忆优先"转向"状态优先"**。

## 2. 提出的方法论

### 2.1 状态漂移的形式化定义与标注
- 漂移判定采用有序排除规则：先排除检索失败、金标问题、理解失败、格式错误（schema mismatch）、推理失败，仅当输出匹配"可用的但过期/错误范围且从未撤回的事实版本"时才判为漂移；无法归类的点被丢弃而非默认归类（保守标注）。
- 采用对抗性过滤 + 跨模型家族双判官确认机制（DeepSeek-V4 × GPT-4o），只有两家族都判定为漂移才算确认；人类标注者交叉验证表明判官给出的漂移率是"上限"。

### 2.2 StateMemBench 基准
- **符号事件程序（Symbolic Event Program）**：每个场景由类型化状态操作序列（规则声明、值更新、范围豁免、承诺、撤回）构成，正确答案由确定性求值器重放程序得到，金标可编程验证。
- **惰性读者策略族（lazy reader policies）**：实现若干可执行启发式（信任最近提及、信任最高频值、引述已声明值而不重算、过早丢弃锚定决策），当某策略与完整重放不一致时即形成"陷阱场景"，并构成五种失败模式签名：
  - **Status（状态错误）**：值已变化但读者锚定在较早的"响亮承诺"上；
  - **Salience（显著性错误）**：有效值在场但被更高频/更突出的竞争者击败；
  - **Sequence（序列错误）**：已声明的派生值在输入变化后未被重算；
  - **Compound（复合错误）**：多种机制交互；
  - **Anti-trap（反陷阱）**：锚定答案仍然正确，只有过度激进的失效策略才会出错。
- **规模**：Set A（短）190 个单探针场景（18 会话，约 165 轮，约 3k tokens）；Set B（长）44 个场景（约 38 会话，约 599 轮，7–15k tokens，三线程融合 + 三部分问题）。共 234 场景、322 个分级探针。
- **领域**：研究（research）、购物（shopping）、个人理财（personal finance），使用真实公开数据（arXiv/bioRxiv 论文、Instacart 数据集、信用卡交易数据集）提供"表层素材"，但状态值独立采样，探针无法从源材料回答。
- **封闭池评分（Closed-pool grading）**：每个探针构造 3–4 个候选答案（金标、漂移目标、中性干扰项），将答案分为"反映当前状态/反映被取代状态/其他错误"。

### 2.3 StateMem 方法（状态优先记忆）
三个阶段的流程：
1. **摄取（Ingestion）**：TurnEncoder 每轮调用一次 LLM，把对话轮解析为结构化"状态单元" `u = (id, content, priority, source, deps)`，其中 deps 含 `derived_from` 和 `coupled_with` 两类依赖链接；单元持久化于 StateStore。
2. **更新（Update）**：应用标记的取代关系（旧单元置为 `superseded`），随后**确定性 Rechecker** 遍历依赖图 G=(U,E)，将依赖链上受影响的单元标记为 `needs_recheck`——全程 O(|E|) 且零额外 LLM 调用。
3. **测试时（Test Time）**：确定性组装有效状态块（按优先级/来源分组、标记需重算单元），一次 LLM 调用基于该状态块 + 重算引导提示生成答案。

### 2.4 StateMemWrapper（轻量包装器）
- 将 StateMem 的状态解析逻辑压缩为**单次答案调用**：Trace（≤250 词，按时间顺序列出值链、规则、当前生效值）→ Resolve（四条优先级规则：后者取代前者、常设规则优于一次性实例、派生值重算而非引述、事实仅在显式取代/过期时退役）。
- 不新增 LLM 调用，不增加存储，附加成本为固定的 155 token 指令 + ≤250 词 trace；匹配对照 `wrapper-ctrl` 仅保留"通用问题条件化提取"，用于隔离"状态结构"与"额外文本量"。

## 6. 主要结论与发现

1. **状态漂移是真实且普遍的失败**：即便在完美检索（oracle）下，LongMemEval 失败中 44.4% 为状态漂移；多会话类问题漂移率（71.4%）远超知识更新类（25.0%）。在 MemoryArena 购物上漂移占 63.5%。
2. **现有方法在 StateMemBench 上普遍失败**：同骨干长上下文仅 0.149（两个基座），最强记忆系统 A-Mem/Mem0 为 0.199/0.149，最强基线 GraphRAG（Qwen 上）0.224；最强长上下文模型 GPT-5.4-Nano 也仅 0.277。反陷阱类接近天花板，而显著性类几乎全面崩盘。
3. **StateMem 显著领先**：DeepSeek 上总体 0.363（比最强记忆系统 A-Mem 0.199 提升 1.8 倍，比稠密检索 0.205 提升 1.8 倍）；Qwen 上 0.233（比 Mem0 0.149 提升 1.6 倍）；两项均显著（配对 McNemar p<0.001）。
4. **消融定位关键组件**：取代标记是最大增益来源（DeepSeek 上 0.174→0.298）；移除重算引导损失 6pp；依赖传播对目标模式有帮助但在 Set B 反陷阱上过度传播（-12.5pp）。
5. **失败机制按骨干分离**：弱骨干（Qwen）上各方法漂移率趋同（61–66%），瓶颈在"回答器"而非"记忆层"；强骨干（DeepSeek）上 StateMem 漂移率下降 15pp、正确数 +42，说明强模型能利用显式状态表征转化原本的漂移。
6. **状态追踪是可分离的轴**：StateMemWrapper 在 12 个单元格上全部显著提升后端（+31.7 至 +66.6 点），其中结构贡献 +15.0 至 +31.7 点（匹配对照隔离）；但在 LongMemEval/DeepSeek 上结构与对照的差距缩小（-5 至 +5），说明强回答器对结构需求更低。
7. **状态追踪不牺牲回忆**：在 LongMemEval 和 LoCoMo 上 StateMem 与长上下文基线持平或略高，增益集中于时间推理和知识更新类问题。

## 7. 优点

- **概念贡献清晰**：将"状态追踪"从回忆、检索、推理中严格分离，给出可操作的形式化定义与保守标注流程。
- **基准设计精巧**：符号事件程序 + 确定性求值器保证金标可验证；封闭池设计使"漂移答案/其他错误"可机器计分；反陷阱控制防止"总偏好最新值"的廉价启发式刷分；双长度机制（Set A/B）隔离了维护能力与干扰物规模。
- **方法简单、可控、可解释**：StateMem 的确定性依赖图传播无 LLM 调用，消融清晰归因；Wrapper 形式证明状态结构是独立可移植的能力轴。
- **实验严谨性**：跨模型家族判官确认、人类标注审计、PABAK/AC1 修正 kappa 的通缩、推理 A/B 对照（证明漂移非推理能力不足）、长度/成本匹配对照（隔离结构贡献）——多处设计体现强方法论意识。
- **结论具有可迁移价值**：对现有多个记忆系统（Mem0、A-Mem、LightMem、MemOS）及检索/图 RAG 后端的一致提升，说明该发现具有普适性。

## 8. 不足与局限

- **合成数据限制**：场景由 LLM 渲染生成，无法完全反映真实世界中智能体记忆的使用形态；作者自认这限制了外部效度。
- **陷阱机制与 StateMem 同源**：基准陷阱来自 StateMem 设计所针对的同一"惰性读者策略族"，因此 StateMem 在自家基准上的增益应视为上界，需依赖外部基准（LongMemEval/LoCoMo）作为泛化验证。
- **上下文规模有限**：Set A 约 3k tokens、Set B 约 7–15k tokens，远小于现代 LLM 的上下文窗口，无法真正压力测试"超长程"状态漂移；35B 模型甚至因 KV-cache 截断受影响。
- **判官/渲染偏差风险**：判官（deepseek-v4-pro）与一个基座（DeepSeek）共享模型家族；场景由 Claude 家族模型渲染，可能存在家族内偏好偏差。
- **计算成本**：StateMem 每轮一次 LLM 编码调用，总资源消耗显著高于长上下文基线，实用性受限于成本。
- **运行次数与规模**：所有结果为单次运行；基座仅为中小模型，前沿模型（除 GPT-5.4-Nano 作为长上下文基线外）未作为记忆系统基座测试；部分子类样本量小。
- **风险考量**：更强的状态追踪可能促使用户过度依赖 LLM 智能体，在个人理财等敏感领域可能产生负面效果（作者在局限性中明确提及）。
- **标注漂移率有上偏风险**：LLM 判官标注的漂移率被人类审计系统性下调，意味着正文报告的漂移率为上限估计。
