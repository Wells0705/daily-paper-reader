## 摘要
前缀缓存在多智能体大语言模型（LLM）服务中引入了一个基本权衡：为某个智能体保留较长的系统提示词键值（KV）缓存可加速其未来调用，但同时会减少可用于批处理并发请求的GPU内存。在多阶段工作流中，现有调度器倾向于优先考虑即时前缀局部性或整体工作流进度。然而，在共享KV缓存预算下，孤立地优化任一目标都可能因下游延迟或频繁的前缀替换而延长任务级作业完成时间（JCT）。为取得平衡，本文提出TOPAS，一种面向任务的前缀感知调度器，它联合决定在缓存中保留哪些智能体前缀以及调度哪些请求执行。TOPAS通过权衡每个任务最长剩余服务路径的预期缩减与下游前缀复用的近期收益，并考虑前缀移动和抢占的成本，来对候选决策后状态进行评分。同时引入任务级老化机制以防止饥饿。我们在SGLang框架中实现了TOPAS，并在三个合成DAG和两个MetaGPT软件开发工作流上评估其性能。与每个工作负载和指标下表现最佳的基线相比，TOPAS在合成工作负载上将平均/第99百分位JCT最多降低了39.8%/49.4%，在MetaGPT-SOP上将平均JCT降低了9.8%，在MetaGPT-TL上将平均/第99百分位JCT降低了22.0%/26.6%。

## Abstract
Prefix caching introduces a fundamental tradeoff in multi-agent large language model (LLM) serving: retaining a long system-prompt key-value (KV) cache for an agent accelerates future calls, yet it reduces the GPU memory available for batching concurrent requests. In multi-stage workflows, existing schedulers tend to prioritize either immediate prefix locality or overall workflow progress. However, under a shared KV cache budget, optimizing either objective in isolation can prolong tasklevel job completion time (JCT) through downstream delays or frequent prefix replacement. To strike a balance, we here propose TOPAS, a Task-Oriented Prefix-Aware Scheduler that jointly decides which agent prefixes to keep in the cache and which requests to schedule for execution. TOPAS scores candidate post-decision states by trading off the expected reduction in each task's longest remaining service path against the near-term benefit of downstream prefix reuse, accounting for the costs of prefix movement and preemption. A task-level aging mechanism is also incorporated to prevent starvation. We implement TOPAS within the SGLang framework and assess its performance on three synthetic DAGs and two MetaGPT software-development workflows. Compared with the best performing baseline for each workload and metric, TOPAS reduces the mean/p99 JCT by up to 39.8%/49.4% on the synthetic workloads, while lowering mean JCT by 9.8% on MetaGPT-SOP and mean/p99 JCT by 22.0%/26.6% on MetaGPT-TL.

## TOPAS：面向多智能体LLM服务的工作流感知前缀状态调度——论文详细总结

### 1. 核心问题与整体含义（研究动机与背景）

多智能体LLM应用通过多个角色化智能体之间相互依赖的请求来完成复杂任务。每个请求包含一个智能体特有的静态前缀，同一智能体在不同任务中的请求可以复用该前缀的KV缓存。服务系统（如SGLang）在GPU内存中保留这些缓存（即前缀驻留）可以消除冗余的预填充计算，但会与并发执行的请求竞争有限的KV缓存预算。长系统提示词进一步放大了复用的收益和驻留的成本。

由此产生了一个基本权衡：**保留一个智能体的长前缀KV缓存能加速其未来调用，但会减少可用于批处理并发请求的GPU内存；反之亦然。** 在多阶段工作流中，现有调度器往往要么优先即时前缀局部性（如LPM），要么优先整体工作流进度（如SRPT）。但在共享KV缓存预算下，孤立优化任一目标都可能造成问题：优先局部性会导致上游阶段滞留、下游任务饥饿；优先进度则会导致频繁切换智能体、反复加载/卸载前缀，降低有效服务容量。两类策略都会延长任务级作业完成时间（JCT）。

**核心研究问题**：在受限的GPU内存预算下，服务系统如何在整个工作流执行过程中协调前缀驻留和请求接纳，以最小化任务级JCT？

### 2. 方法论：核心思想、技术细节与关键公式

#### 2.1 核心思想

TOPAS（Task-Oriented Prefix-Aware Scheduler）将前缀驻留视为**显式的工作流级调度决策**，与请求接纳联合优化。在每个调度点，调度器共同决定：

- 哪些智能体前缀保留在KV缓存中；
- 哪些就绪请求被接纳执行。

#### 2.2 问题形式化

- 所有任务遵循相同的已知DAG \(G = (V, E)\)，任务 \(J_i\) 在时间 \(\tau_i\) 到达。
- 调度动作选择决策后状态 \(S' = (R', Q')\)，其中 \(R'\) 为驻留前缀集，\(Q'\) 为运行请求集。
- 约束条件：\(\sum_{a \in R'} \ell_a + \sum_{r \in Q'} d_r(t) \leq B_t\)，即静态前缀KV与动态KV之和不超过可用预算。

#### 2.3 核心评分函数

对候选状态 \(S'\)，TOPAS 计算得分：

**Score(\(S'|S_t\)) = \(J_{admit}^{age} - J_{move} - J_{redo} - J_{revoke} + V_{reuse}\)**

各项含义：

- **\(J_{admit}^{age}\)（接纳收益，带年龄加权）**：估计被接纳请求完成后对任务**最长剩余LLM服务路径**的预期缩减量。基于经验条件残差分布计算最长剩余路径（LP），允许关键路径随阶段推进而变化。年龄加权 \(g_i(t) = 1 + \rho\log(1 + \frac{t-\tau_i}{H_{age}})\) 防止新任务持续插队。
- **\(J_{move}\)（前缀迁移成本）**：前缀KV在GPU与CPU之间交换的时间开销，按转移带宽折算。被影响的每个任务仅计一次。
- **\(J_{redo}\)（重建成本）**：被抢占请求需通过自回归解码重建已生成token KV的成本。
- **\(J_{revoke}\)（撤销信用）**：被抢占请求之前的接纳信用被撤销，防止未完成请求反复收取接纳收益。
- **\(V_{reuse}\)（近期前缀复用价值）**：评估候选前缀集中，有多少下游阶段即将就绪（仅剩一个未完成前驱），按下一次前缀加载时间的倒数加权。仅一步前瞻，不深挖多步。

#### 2.4 层次化状态搜索

直接联合搜索组合爆炸，TOPAS 采用**前缀集生成 + 请求分配**分离的两层搜索：

- 当活跃智能体池 \(|A_t| \leq M\) 时，**穷举**所有前缀子集；
- 当池较大时，采用贪心初始搜索 + 单智能体添加 + 二元组添加 + 修复操作（drop/swap）的高效搜索，复杂度限制在 \(O(|A_t|^2)\)。
- 对每个前缀集，GREEDY PACK 在KV预算约束下贪心打包请求：保留被覆盖的运行中请求、按"每额外KV容量的年龄加权条件进度"排序接纳新请求，并重复迭代直到无正增益为止。
- 搜索过程中保留所有可行的中间分配状态，最终选出得分最高的状态执行。

### 6. 主要结论与发现

1. **纯局部性或纯进度策略均不足**：LPM和SRPT在多种负载下均不如结合两者考虑的简单策略，揭示了前缀局部性与工作流进度之间的固有矛盾。

2. **TOPAS显著降低任务级JCT**：
   - 合成工作负载上（对比每负载每指标最优基线）：平均JCT降低27.5%~39.8%，p99 JCT降低30.8%~49.4%；

4. **老化机制是重要保障**：任务级老化防止新到达任务持续抢占旧任务，是整体性能的关键组成部分。

### 7. 优点

- **问题定义新颖且切中要害**：将前缀驻留与请求接纳形式化为联合优化问题，而非视为请求排序和缓存替换的间接副产品，属于首次。
- **基于DAG的调度决策**：通过最长剩余路径（LP）而非简单的剩余处理时间来度量任务进度，考虑了工作流结构的非对称性（非瓶颈分支的推进不等于任务整体推进）。
- **联合状态评分机制完备**：同时考虑接纳收益、前缀迁移成本、抢占重建成本、信用撤销和近期复用价值，各成本项均有清晰模型。
- **层次化搜索设计合理**：小规模穷举保证最优性、大规模贪心加对组修复控制复杂度，兼顾效果与效率（调度开销仅0.31%墙钟时间）。
- **诊断实验扎实**：两部分诊断实验（交替/分组批处理对比；LPM/SRPT对比）清晰揭示了研究问题的实际存在性和重要性。
- **多个真实Agent应用验证**：使用MetaGPT真实数据集，提升结果的可信度。

### 8. 不足与局限

- **单GPU范围限制**：所有实验在单块A100上完成，未验证在多GPU或分布式场景下的可扩展性与效果；实际生产环境多为多机多卡。
- **假设任务共享同一DAG**：论文假设所有任务遵循相同的已知DAG结构。实际多智能体应用中，不同任务可能采用不同流程，甚至动态调整流程。
- **未充分讨论前缀数量大的可扩展性**：DAG-10-Wide有10个前缀命名空间，但更大规模（如数十个智能体的场景）的搜索成本未验证。
- **工作负载多样性有限**：合成工作量使用固定长度查询/生成；MetaGPT虽真实但只覆盖软件开发场景，未涵盖更广泛的Agent应用（如对话式多智能体、多跳工具调用等）。
- **超参数敏感性未明确**：β（复用压力强度）、ρ（老化强度）、M（穷举阈值）、K（caps）等关键超参数的取值与敏感性分析没有在正文中详细呈现。
