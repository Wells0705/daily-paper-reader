## 摘要
硬件内核优化需要反复进行编译、正确性测试、性能剖析和修订。LLM智能体可以自动化该过程的某些部分，而更强的基座模型、更长的上下文窗口以及更长的执行周期已改善了单个任务内的优化效果。仅凭这些进展，智能体无法从已完成的优化运行中学习。现有的内核优化智能体很少保留一个决策、其观察到的执行反馈以及后续基于该证据做出的决策。同时，保留每一条先前的轨迹也不切实际，因为不断扩大的历史记录会与当前任务争夺上下文。我们提出了KOPE，一种用于硬件内核优化的经验驱动框架。KOPE将带有正确性和性能反馈的优化轨迹记录到经验图记忆中，然后通过主动上下文管理与注入，在固定的token预算下检索相关经验。该图保留了决策顺序、观察到的结果以及替代分支，从而使在目标硬件上收集的证据能够为后续的优化步骤和任务提供信息。在相同的GLM-5.2设置下，KOPE的逐算子加速比几何均值是最强竞争基线CANNBot的1.54倍。在完整的53算子消融实验中，主动上下文管理与注入将通过率从60.0%提升至84.6%，将评估者报告的正值字段几何均值从0.0382提升至0.0661，并将相对于被动的智能体主导上下文构建的优化token消耗从159亿降至11.13亿。启用经验图记忆可将全套测试通过率从55.2%提升至84.6%，并在有效的时序比较中产生1.43倍的几何均值加速。这些结果表明，在基座模型保持不变的情况下，通过外部经验可以实现持续优化。

## Abstract
Hardware kernel optimization requires repeated compilation, correctness testing, profiling, and revision. LLM agents can automate parts of this process, and stronger foundation models, longer context windows, and longer execution horizons have improved optimization within individual tasks. These advances alone do not enable an agent to learn from completed optimization runs. Existing kernel-optimization agents seldom preserve a decision, its observed execution feedback, and the later decisions that use that evidence. Retaining every prior trajectory is also impractical because an expanding history competes with the current task for context. We present KOPE, an experience-driven framework for hardware kernel optimization. KOPE records optimization trajectories with correctness and performance feedback in Experience Graph Memory, then uses Active Context Management and Injection to retrieve relevant experience under a fixed token budget. The graph retains decision order, observed outcomes, and alternative branches, allowing evidence collected on the target hardware to inform later optimization steps and tasks. Under the same GLM-5.2 setting, the geometric mean of KOPE's per-operator speedups is $1.54\times$ that of CANNBot, the strongest competing baseline. In a complete 53-operator ablation, Active Context Management and Injection raises pass rate from 60.0\% to 84.6\%, increases the evaluator-reported positive-field geometric mean from 0.0382 to 0.0661, and reduces optimization token consumption from 15.9B to 1.113B tokens relative to passive agent-led context construction. Enabling Experience Graph Memory raises full-suite pass rate from 55.2\% to 84.6\% and yields a $1.43\times$ geometric-mean speedup on valid timing comparisons. These results support continual optimization through external experience while the foundation model remains fixed.

## 2. 论文提出的方法论：核心思想、关键技术细节、公式与算法流程

- **KOPE 框架总览**：一个闭环的“经验驱动优化工作流”，对每个候选内核先编译、正确性验证、性能剖析，再将完整轨迹记录到持久化记忆中，并在后续决策与任务中复用。
- **核心机制一：经验图记忆（Experience Graph Memory / KOPE-Mem）**
  - 记录每个优化事件为**双表示**：追加式的 Markdown 探索日志（Journal）+ 结构化的 JSON 案例（Case）。
  - 案例包含算子与输入场景、优化思路、代码变化、编译/运行反馈、正确性、绝对加速比、置信度、会话/步骤/前驱 ID 等。
  - 构建**决策到结果的有向无环森林**：节点为决策及结果，边表示“在某个优化状态下发起了另一次尝试”；支持替代分支；边只记录执行谱系，不声明因果。
  - **图感知检索与排序**：先按精确过滤器（算子、优化层、思路标识、结果标签）和语义检索构建相关池；再用**下游折扣结果得分**：
    - 定义步进比 \( r_v = a_v / a_{prev(v)} \)（根或无正前驱时 \( r_v=1 \)）；
    - 按结果标签分组（有效/部分/无效/负面）；
    - 计算折扣下游得分 \( d(v) = w_{self} r_v + w_{succ} \gamma \sum_{u\in succ(v)} d(u) \)，取 \( w_{self}=w_{succ}=0.5, \gamma=0.7 \)；
    - 在相似相关性的案例内按置信度排序。该得分只是检索启发式，不视为因果效应估计。
- **核心机制二：主动上下文管理与注入（Active Context Management and Injection）**
  - **动态上下文分层**（非永久存储位置）：
    - **Hot**：内核规范、当前最优代码、最新反馈、优化目标——必须包含；
    - **Warm**：检索到的案例、日志摘要、过程摘要（含成功动作和失败模式）；
    - **Cold**：更广泛文档、跨类别经验、较旧摘要。
  - **预算感知组装**：给定模型窗口 \( W \)、系统提示大小 \( S \)、生成预留 \( G \)、最近保留 \( R \)，可用知识预算为 \( B_k = \max(0, W - S - G - R) \)；先保证 Hot 负载 \( H \le B_k \)，再按图上排序经验填充 Warm（上限 \( Q_w \)），剩余容量给 Cold（上限 \( Q_c \)）。
  - 每次迭代前都重建提示，使最近记录的事件能立即影响下一次决策。
- **学习循环**：对于任务 \( x_t \) 第 \( k \) 次迭代：检索经验 \( z_{t,k}=R(s_{t,k}, M_{t,k}) \)，组装提示 \( C_{t,k}=I(s_{t,k}, z_{t,k}; B) \)，LLM 决策 \( a_{t,k} = \pi_\theta(C_{t,k}) \)，执行环境返回结果 \( y_{t,k}=E(a_{t,k}) \)，更新记忆 \( M_{t,k+1}=U(M_{t,k}, s_{t,k}, a_{t,k}, y_{t,k}) \)。记忆在任务间持久化（\( M_{t+1,0}=M_{t,K_t} \)）。
- **正确性优先**：只有正确且改进性能的候选才替换当前最优；失败证据（编译失败、错误输出、性能回退）也被保留供后续参考。

## 6. 论文的主要结论与发现

- **系统级效果（GLM-5.2）**：KOPE 在全套 1,060 用例上通过 **897 个（84.6%）**，CANNBot 通过 613 个（57.8%）；KOPE 的逐算子加速比几何均值是 CANNBot 的 **1.54 倍**。
- **Deepseek-V4-Pro 下**：KOPE 通过 783 个（73.9%，得分 1242.90），CANNBot 39.3%（得分 1015.38）；但在 31 算子交集上 CANNBot 的得分和正值加速比略高，说明 KOPE 的主要优势是**覆盖率和全套正确性**，而非在每个条件性能统计上都支配。
- **CUDA-Agent 在稀疏语料 Ascend 设置中**：通过率仅 9.1%–14.7%，且**未解决任何完整算子**；表明仅靠模型能力和任务内细化在目标专用语料稀缺时不足。
- **主动上下文管理与注入消融**：全套通过率从 60.0% 提升至 84.6%（+24.6 pp），正值字段几何均值从 0.0382 提升到 0.0661（1.73×），聚合优化 token 消耗从 15.9B 降至 1.113B（–93.0%）。说明增益不是靠把更大历史放进 prompt 实现的。
- **经验图记忆消融**：启用图记忆后全套装通过率从 55.2% 提高到 84.6%（+29.4 pp）；在 412 个配对计时用例上产生 **1.434× 几何均值加速**；从 L2–L4 的加速增益分别为 1.455×、1.501×、9.175×（L1 上两者相当）。
- **RISC-V 迁移**：Ascend 记忆可提高通过覆盖率（60.3% → 83.3%）但降低固定交集性能（0.388× → 0.145×）；K3 本地记忆与组合记忆进一步提升覆盖和性能（组合设置 92.2% 通过率、0.786× 固定交集加速，为冷启动的 2.027×）。结论：KOPE 是**可重定向、通用**的经验复用与自适应工作流，但不能保证硬件无关的加速效果。

## 7. 优点

- **问题定位精准**：明确区分“模型内知识缺失”与“经验未持久化”两件事，解决的是后者——外部经验复用，不依赖微调，可适用于公共语料稀疏的新硬件。
- **方法设计巧妙**：
  - 图记忆保留**决策顺序、观测结果和替代分支**，并引入下游折扣得分，使检索不仅能看文本相似性，还能考虑后续结果；
  - **双表示（Journal + Case）** 兼顾语义检索与精确结构查询；
  - 主动上下文管理将“长历史”变为**有预算约束的精选提示**，显著降低 token 消耗的同时提升效果；
  - 明确区分“谱系”与“因果”，不把检索得分当作因果估计，科学严谨。
- **实验设计规范**：使用完整基准、缺席算子计失败、正交集对比、奖励黑客防护、多重指标（通过率、得分、速度、token）；提供跨硬件迁移实验来加强泛化性主张。

## 8. 不足与局限

- **实验强度不足**：每个配置只有一次归档运行，无重复与方差估计；性能结论基于较小配对所有（尤其 L4 仅 28 例）。
- **消融颗粒度不够**：主动/被动上下文是整机制消融，没有分离检索、压缩、注入各自贡献；图记忆消融也没有区分图结构本身与案例内容的作用。
- **公平性风险**：系统对比同时改变多个工作流因素，无法排除实现细节差异的干扰；CUDA-Agent 的条件速度统计覆盖子集差异大，不能作为代表性能。
- **应用场景限制**：实验硬件限于华为 Ascend 910C 与 RISC-V K3，内核语言限于 AscendC 与 Triton；未在 NVIDIA GPU 等更常见的硬件上验证（尽管 CUDA-Agent 是 GPU 工作流，但这里只被当作稀疏语料下的对比对象）。
- **上下文预算配置固定**：Hot/Warm/Cold 的上限没有在线学习机制，超参是手动设定的。
- **外部迁移不是全自动成功**：Ascend 记忆直接迁移会降低性能，说明跨硬件经验存在“可行性”与“性能”转移的不对称；因此该方法仍需目标侧的本地反馈来校准。
