## 摘要
基于大语言模型的智能体日益依赖外部记忆来支持长程推理与交互。然而，主要瓶颈不在于简单地存储过往经验，而在于当相关信息分散于多次交互中时，能够恢复正确的证据集合。现有方法难以解决这一访问问题。全上下文方法需要嘈杂的长上下文搜索，平面检索往往返回孤立且不完整的记录，而基于图的记忆系统可能构建成本高昂，同时会压缩丰富的事件上下文。我们提出RippleMem，一种长期记忆系统，用自适应关联回忆替代一次性检索。受线索依赖的情景回忆和关联补全启发，RippleMem将交互历史存储为富含线索的情景记忆单元，并将其组织在事件中心的记忆图中。给定查询时，它首先通过混合线索回忆相关记忆锚点，然后沿语义和结构关联从这些锚点扩展，以恢复缺失的支持证据。这样，最初回忆的记忆不仅作为答案上下文，还作为完成作答所需证据的线索。在LoCoMo和LongMemEval-S上的实验表明，RippleMem在评估设置中实现了最佳整体性能，将LLM-as-a-Judge准确率在LoCoMo上提高了3.95%，在LongMemEval-S上提高了高达11.87%，同时将图构建成本降低了约30倍。

## Abstract
LLM-based agents increasingly rely on external memory to support long-horizon reasoning and interaction. However, the main bottleneck is not simply storing past experience, but recovering the right set of evidence when relevant information is distributed across many interactions. Existing approaches struggle with this access problem. Full-context methods require noisy long-context search, flat retrieval often returns isolated and incomplete records, and graph-based memory systems can be expensive to construct while compressing rich event context. We introduce RippleMem, a long-term memory system that replaces one-shot retrieval with adaptive associative recollection. Inspired by cue-dependent episodic retrieval and associative completion, RippleMem stores interaction history as cue-rich episodic memory units and organizes them in an event-centric memory graph. Given a query, it first recalls relevant memory anchors through hybrid cues, then expands from these anchors along semantic and structural associations to recover missing supporting evidence. In this way, initially recalled memories serve not only as answer context, but also as cues for completing the evidence needed to answer. Experiments on LoCoMo and LongMemEval-S show that RippleMem achieves the best overall performance across evaluated settings, improving LLM-as-a-Judge accuracy by 3.95% on LoCoMo and up to 11.87% on LongMemEval-S, while reducing graph construction cost by about 30x.

## 1. 论文的核心问题与整体含义

- 长期智能体（LLM-based Agent）面临的核心问题不是“如何存储过往经验”，而是**当答案所需的证据分散在多次交互中时，如何恢复出完整、可回答的证据集合**。  
- 现有记忆系统存在三类典型缺陷：
  - **全上下文方法**：依赖嘈杂的长上下文搜索，容易丢失关键证据，存在“中间丢失”等效应；
  - **扁平检索方法**：往往只返回与查询最直接匹配的孤立记录，无法组合跨会话的分散信息；
  - **图记忆方法**：虽引入结构化关联，但构建成本高，且无指导下图扩展容易检索到相关但不支持答案的记忆。
- 论文将长期记忆访问重新定义为“**证据恢复问题**”：相关历史可能已被存储，但由于支持信息分布在不同交互中，检索系统仍可能无法将其组装成可回答的证据集。  
- RippleMem 的核心思想是：**记忆访问应是证据条件化的联想回忆，而不是一次性查询匹配**。最初回忆出的记忆不仅是答案上下文，更应作为线索，继续引导找回缺失的支持性证据。

## 2. 论文提出的方法论

- **总体架构**：RippleMem 采用“写–读”两阶段设计，受认知科学中事件分割、线索依赖回忆与联想补全等概念启发，但不声称对人类记忆进行机制建模。

- **写阶段：事件中心记忆构建**
  - 将对话历史切分成有重叠的轮次窗口，通过 schema 引导的 LLM 提取器生成结构化的“线索丰富情景记忆单元”。
  - 每个记忆单元表示为：
    - `m_i = (r_i, v_i, P_i, L_i, T_i)`
    - `r_i`：归一化的事件重述（可独立理解）；
    - `v_i`：`r_i` 的稠密向量；
    - `P_i / L_i / T_i`：可落地的参与者、地点、时间线索（无法确定时留空，不推测）。
  - 将对话历史组织为“事件中心记忆图”：节点为记忆单元，边为语义关联与结构关联。
    - **语义关联**：基于余弦相似度 `s_sem(i,j)=cos(v_i,v_j)`；
    - **结构关联**：聚合参与者、地点、时间的 Jaccard/时间区间重叠相似度；
    - **稀疏图构建**：新记忆插入时，通过语义近邻和线索索引获得有界候选池，仅保留超过阈值的边，控制每节点最多 K 条语义/结构边，降低构建成本。

- **读阶段：自适应联想回忆**
  - **混合初始召回**：从查询中提取语义、词汇、结构化线索，得到初始证据集 `C0`。
  - **记忆锚点规划**：由受约束的 LLM 控制器判断是否需要继续回忆；若需要，则从当前证据中选定少量锚点，并定义“缺失支持目标”（目标重述 + 目标线索）。
  - **锚点局部扩展**：仅从锚点出发，在有限跳数内沿语义/结构两条通道扩展候选记忆，按与缺失目标的匹配度选出支持集 `Sr`，更新证据集 `C`，循环直至充分、无新支持或达到轮次预算（实验中取额外 1 轮）。
  - **证据组装**：去重合并后，用固定权重的打分函数对记忆排序，截取 top-K 记忆作为生成上下文。

- **核心创新**：将“已召回记忆”同时作为答案证据和继续检索的线索，实现从一次性检索到有目标、有边界的联想回忆。

## 3. 实验设计

  - **LongMemEval-S**：500 道问题，覆盖多会话推理、时间推理、知识更新、用户事实、偏好回忆、助手信息等类型。

- **对比方法**：
  - 在主实验中对比：Full-Context、Mem0 / Mem0g、Zep、MemGAS、M-Flow、REMem、SimpleMem、RF-Mem 等。
  - 在 LongMemEval-S 上还引入 LightMem、MemU、MemOS、EverMemOS 等报告结果。
  - 在 EverMemBench 上对比 Full Context、MemoBase、Mem0、Zep、MemOS、RF-Mem。
  - 部分基线采用与 RippleMem 相同的记忆单元和证据预算，以隔离“记忆访问策略”差异（如 RF-Mem）。

- **评估指标**：
  - LoCoMo：F1、BLEU-1、LLM-as-a-Judge 准确率；
  - LongMemEval-S / EverMemBench：LLM-as-a-Judge 准确率（或选项精确匹配）。

- RippleMem 在 LoCoMo 和 LongMemEval-S 上均取得最佳整体性能，较最强基线相对提升 Judge 准确率 3.95%（LoCoMo）和最高 11.87%（LongMemEval-S）。

## 7. 优点

- **问题定义有新意**：将长期记忆访问形式化为“证据恢复/证据补全”问题，而非简单检索问题。
- **认知启发落地清晰**：事件式记忆单元、丰富线索绑定（人物、地点、时间）、线索依赖回忆等概念被转化为可操作的工程实现。
- **方法设计完整**：写阶段构建“线索丰富 + 事件图关联”的记忆基座；读阶段采用“混合召回 → 锚点规划 → 局部扩展 → 证据组装”的受控流水线。
- **成本控制好**：通过稀疏图、候选池限制、固定轮次预算等方式，将图构建成本降低约 30 倍，同时保持甚至提升效果。

## 8. 不足与局限

- **场景覆盖有限**：论文仅评估文本对话记忆；未涉及多模态交互、具身智能体、工具使用环境，后者的记忆可能包含视觉观察、动作状态和外部工具状态。
- **LLM 中介开销**：记忆提取、查询分析、回忆规划均依赖 LLM，相比单次检索会引入额外延迟和成本；论文虽给出 token 数量，但未全面评估端到端延迟。
- **长时连续记忆压力不足**：论文指出当前 benchmark 对“持续增长的个人记忆、长期时间线、用户状态演化、记忆老化、隐私删除”等压力测试有限，需更长时间尺度的评测。
- **统计稳健性不足**：未报告多次重复实验的方差或显著性检验，主要指标依赖 LLM-as-a-Judge，可能受 judge 模型偏好或提示敏感度影响。
