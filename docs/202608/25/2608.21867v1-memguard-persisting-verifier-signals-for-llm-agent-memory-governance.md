## 摘要
LLM智能体正从单提示使用转向长任务流，其中可复用记忆成为终端、软件工程和网络任务的核心能力。这种记忆只有在存储的经验在数百次交互中保持可靠时才有用，但两种故障模式在实践中打破了这一假设。第一种是不可靠的准入：失败轨迹、偶然成功和误导性观察因看似相关而进入记忆，随后误导后续决策。第二种是记忆漂移：长期运行的记忆库积累重复、过时和冲突的记录，仅靠检索无法修复。MemGuard的关键区别在于将验证器输出视为持久化的生命周期元数据，而非一次性过滤器。它将多标准评分令牌验证转化为奖励、置信度、标签和不确定性描述符，在激活前附加到每个候选对象，并在检索、冲突解决、摘要和归档过程中复用。我们在Terminal-Bench 2.0、SWE-Bench Verified、WebArena和Mind2Web上，使用四种骨干网络对MemGuard进行评估，并与四种记忆基线及仅验证器控制进行对比，在匹配的运行时间预算下进行。在五个随机种子上平均，MemGuard在所有16种骨干-基准组合中均取得最佳成功指标和最低平均步数，相较于我们评估的记忆方法中最强的先前基线ReasoningBank，最大提升为WebArena上7.9个成功率点、Mind2Web上5.6个步成功率点，以及终端和软件工程基准上2.4-3.5个点。代码可在https://github.com/whyyyyy123/MemGuard获取。

## Abstract
LLM agents are moving from single-prompt use to long task streams in which reusable memory becomes a core capability for terminal, software-engineering, and web tasks. Such memory is useful only when stored experience remains reliable across hundreds of interactions, but two failure modes break that assumption in practice. The first is unreliable admission: failed trajectories,accidental successes, and misleading observations enter memory because they appear relevant, then mislead later decisions. The second is memory drift: long-running banks accumulate duplicate, stale, and conflicting records that retrieval alone cannot repair. MemGuard's key distinction is to treat verifier output not as a one-shot filter, but as persistent lifecycle metadata. It converts multi-criteria score-token verification into reward, confidence, label, and uncertainty descriptors that are attached to every candidate before activation and reused during retrieval, conflict resolution, summarization, and archival. We evaluate MemGuard on Terminal-Bench 2.0, SWE-Bench Verified, WebArena, and Mind2Web across four backbones, comparing against four memory baselines plus a verifier-only control under matched runtime budgets. Averaged over five seeds, MemGuard achieves the best success metric and lowest average steps in all 16 backbone-benchmark settings, improving over ReasoningBank, the strongest prior baseline among the memory methods we evaluate, with a largest gain of 7.9 success-rate points on WebArena, 5.6 step-success-rate points on Mind2Web, and 2.4-3.5 points on terminal and software-engineering benchmarks. Code is available at https://github.com/whyyyyy123/MemGuard.

### 1. 核心问题与整体含义（研究动机和背景）

随着 LLM 智能体从单次提示使用转向长任务流（如软件工程、Web 导航、终端操作），可复用记忆已成为其核心能力。然而，现有的智能体记忆系统在实际使用中存在两大关键故障模式：

- **不可靠准入（Unreliable Admission）**：失败的轨迹、偶然的成功、误导性的 Web 观察、无效补丁等都可能被当作“有相关性”写入记忆，进而在后续任务中误导决策。
- **记忆漂移（Memory Drift）**：长期运行后，记忆库中累积重复、过时、冲突甚至过度泛化的记录，单纯依靠检索无法修复或剔除这些有害信息。

论文的核心观察是：现有系统往往将验证器（Verifier）的输出仅用作一次性筛选，没有让其证据在记忆的整个生命周期中持续发挥作用。MemGuard 的核心含义在于：**验证信号应被转化为持久的生命周期元数据**，在记忆的录入、检索、冲突消解、摘要和归档等环节中持续参与治理，从而从根本上提升智能体记忆在长期任务流中的可靠性。

### 2. 方法论：核心思想、关键技术细节、公式或算法流程

MemGuard 是一个验证器引导的记忆治理框架，其核心思想可概括为：将从轨迹验证中得到的奖励、置信度、标签与不确定度等信号持久化地附加到每条记忆记录上，使记忆库成为“生命周期管理对象”，而非“仅追加的索引”。

#### 2.1 核心流程

- 智能体执行任务，记录轨迹 τ、最终输出 y、执行状态 e。
- 验证器基于多准则（任务完成度、证据一致性、执行有效性、可泛化性）对轨迹进行评分，并输出标签 ℓ ∈ {verified_success, verified_fail, uncertain}、奖励 R 和置信度 c。
- 记忆归纳模块将轨迹转化为“过程提示”（procedural hints）、“工具使用记忆”（tool-usage）和“失败规避记忆”（failure-avoidance）三类结构化的候选记录。
- 治理模块决定候选记录是激活、拒绝、合并、替换、摘要化还是归档。

#### 2.2 关键公式与技术细节

- **奖励估计（公式 1）**：轨迹奖励通过对各准则、各视图下的分值分布求加权期望得到：

  Rt = ∑ wj · (1/|Rt|) ∑ E[φ(v)]

  其中 φ(v)=(v−1)/4 将得分 token 映射到 [0,1]，wj 为准则权重。

- **不确定性触发重复验证**：结合边界分数（reward 与不确定带的距离）和离散度分数（各准则或各视图的分歧），计算:

  ut = α·bt + (1−α)·st

  当 u_t 超过阈值时，触发额外视图（证据视图与风险视图）进行重新验证。

- **准入策略**：只有当 R ≥ 0.70 且 c ≥ 0.60 时，候选记忆才被激活为主动记忆；低质量经验被拒绝、保持临时状态或转去“失败防护池”。

- **精度导向检索（公式 3 和 4）**：检索分数综合考虑相关性、验证器质量、可应用性、最近使用和成功复用信号，同时扣除冲突、过时和验证器风险惩罚。失败防护记忆使用独立路径，采用更严格的相关性和置信度阈值。

- **冲突检测（公式 5）**：先通过结构化签名计算相似度，若相似度高于阈值且推荐动作或验证标签不一致，则判定为冲突；冲突按验证标签、奖励、置信度、最近使用和复用次数排序解决。
