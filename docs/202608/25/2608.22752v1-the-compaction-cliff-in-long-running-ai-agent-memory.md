## 摘要
在AI智能体的上下文中，一条安全规则和一段情景日志争夺相同的令牌。当预算溢出时，两者以相同的速率被摘要；只有规则需要精确措辞才能保持可执行。在20个生产智能体配置上，使用Sonnet 4.6的Claude Code的/compact提示在一次压缩后保留了53%的安全规则，在五次压缩后保留了10%。我们将此命名为压缩悬崖（Compaction Cliff）。我们通过知识分流（Knowledge Triage）来解决这一问题，该框架按类型对智能体知识库的每一行进行分类，并让每种类型通过其自身的保留策略进行路由。三个确定性操作符在三种上下文管理操作中实现这种分流：TypeCompact在每类保真度下原地重写条目，TypeDecompose将过于庞大无法安全压缩的主题进行分区，并在分区之间复制在作用域内的安全规则，TypeRetrieve从外部存储获取条目，并将作用域内的规则优先于相关性进行固定。在五个公共语料库上，TypeCompact在各种比率下比最强的一次性LLM压缩器多保留2至4倍的安全规则，在五轮中达到96%的召回率。TypeDecompose达到0%的局部性违规率，而均匀分区为93%。TypeRetrieve达到100%的recall@50，而最佳一次性LLM检索器为73%。在三个下游行为基准上，我们在医疗合规性方面超过了生产环境Sonnet压缩器（在保留率上的配对McNemar检验p < 10^-8，N = 200），在零售任务通过率上超过了完整策略和分层基线（p < 0.01，N = 115），并在航空领域超过了分层压缩（p = 0.024）。我们发布了AgentArtifactCorpus（包含来自54,628个公共GitHub仓库的396,934个智能体配置）、分类器以及参考实现。

## Abstract
A safety rule and an episodic log compete for the same tokens in an AI agent's context. When the budget overflows, both are summarized at the same rate; only the rule needs exact wording to remain enforceable. On 20 production agent configurations, Claude Code's /compact prompt on Sonnet 4.6 preserves 53\% of safety rules after one compaction round and 10\% after five. We name this the Compaction Cliff. We address it with Knowledge Triage, a framework that classifies each line of an agent's knowledge base by type and routes each type through its own retention policy. Three deterministic operators implement this triage across the three context-management operations: TypeCompact rewrites items in place under per-type fidelity, TypeDecompose partitions a topic too large to compact safely, replicating in-scope safety rules across partitions, and TypeRetrieve fetches items from external storage with in-scope rules pinned ahead of relevance. On five public corpora, TypeCompact preserves 2--4$\times$ more safety rules than the strongest single-shot LLM compactor at every ratio, with 96\% recall over five rounds. TypeDecompose reaches 0\% locality violations against 93\% under uniform partitioning. TypeRetrieve reaches 100\% recall@50 against 73\% for the best single-shot LLM retriever. On three downstream behavioral benchmarks, we outperform the production Sonnet compactor on medical compliance (paired McNemar $p < 10^{-8}$ on preservation, $N = 200$), the full-policy and hierarchical baselines on retail task pass rate ($p < 0.01$, $N = 115$), and the hierarchical compaction on the airline domain ($p = 0.024$). We release AgentArtifactCorpus (396{,}934 agent configurations from 54{,}628 public GitHub repositories), the classifier, and the reference implementation.

### 1. 核心问题与整体含义

- **核心现象——“压缩悬崖”（Compaction Cliff）**：在长期运行的AI智能体中，安全规则（如“患者对青霉素过敏”）与情景日志等普通信息共享同一上下文窗口。当上下文预算溢出触发压缩时，两者以相同速率被摘要，而安全规则需要**精确措辞**才能保持可执行。导致约束条件被倒换措辞或直接丢弃，可能引发灾难性后果（如推荐青霉素类抗生素）。
- **关键量化证据**：在20个生产智能体配置上，Claude Code的 `/compact` 命令（Sonnet 4.6）**一轮压缩仅保留53%的安全规则，五轮后仅剩10%**。这种“悬崖式”衰减在4个LLM压缩器家族和最强非LLM压缩器上一致出现，说明问题具有结构性。
- **现有工作的空白**：压缩（Compaction）、分解（Decomposition）、检索（Retrieval）三大上下文管理操作在文献中被独立处理；且**均不依据知识类型区分保留策略**——安全约束与背景信念以相同速率丢失。MaRS虽提出了类型化记忆，但采用单一子模效用，无法保证安全类别的独立保护。
- **核心含义**：提示词压缩或分层截断这类“类型盲”（type-blind）策略存在系统性的安全缺陷。智能体知识的保留策略必须按类型差异化，安全规则需要“白名单式”精确保留。

### 2. 方法论：知识分流（Knowledge Triage）

#### 2.1 五类型知识模型
将智能体知识库中每一项分类为五类（基于396,934个真实智能体工件归纳）：

| 类型 | 定义 | 失真容忍度 |
|------|------|-----------|
| 约束（C） | 限制智能体行为、违反即安全失效的规则 | **零容忍**，必须原样保留 |
| 程序（P） | 逐步操作指令 | 仅当执行语义等价时可改写 |
| 信念（B） | 被当作事实的断言 | 有界语义距离 |
| 偏好（F） | 软性指南 | 高容忍，可摘要/合并 |
| 情景（E） | 过去事件或观察 | 可自由丢弃 |

形式化定义为元组 K=(I, τ, T, π, σ)，其中 σ 定义每个约束的**作用域**（适用于哪些主题叶节点），支持分解和检索中的局部性推理。

#### 2.2 分类器 τ（SafetyMargin）
- **核心思想**：通过**反事实安全评分**而非语法形式判断约束。margin(i) = max over actions [P(unsafe | a, K∖{i}) − P(unsafe | a, K)]，高于0.5标记为约束。
- **动机**：声明式表述（“患者对X过敏”）占真实安全文本的49.8%（openFDA）和61.1%（LegalBench），而语法形式分类器（正则、少量提示LLM）在声明式表述上表现崩溃（召回率低至0%~62%），SafetyMargin提升至90%。
- **替代方案**：选择性级联（正则→编码器→LLM→弃权即硬）、一次性LLM调用、纯表面启发式；均有权威性加权（系统>开发>用户>工具>检索）。

#### 2.3 三个确定性算子

**TypeCompact（压缩）**：
- 将项目分流至三条保真度通道：约束和程序→**硬通道**（全文保留）；信念和偏好→压缩通道；情景→占位符。
- 附带**验证器**：提取每个约束的规范形式（否定+宾语短语）并检查出现在输出中；缺失则恢复原文或上报 `Unsafe`。
- 安全要求：∀约束 i，在 C(K) 中存在 d_C(i, i')=0 的副本。

**TypeDecompose（分解）**：
- 按主题分组、按预算分块，然后将每个约束**复制**到其作用域覆盖的所有分区。
- 安全要求“约束局部性”：任何包含某约束作用域内条目的分区也必须包含该约束。
- 开销 = 复制成本，与约束作用域覆盖的分区数成比例（本地约束零开销）。

**TypeRetrieve（检索）**：
- 先固定作用域内的约束（`inscope(q,c) ⇔ topics(q) ∩ σ(c) ≠ ∅`），再用剩余预算按相关性填充，非LLM开销。
- 安全要求“优先级”：∀作用域内约束，无论相似度分数如何，必须出现在结果集中。

三算子组合：先尝试压缩 → 低于最小安全预算 B_min 时 → 分解 → 外部存储 + 按需检索。

### 6. 主要结论与发现

1. **压缩悬崖是结构性的**：类型盲压缩在全部4个LLM家族和全部结构基线上一致出现，非某一模型特有问题。
2. **五类型模型覆盖真实知识**：97%的智能体指令可被归类，约束类占12.3%，分类器对约束识别的F1达0.89。
3. **类型化压缩打破悬崖**：TypeCompact在50%/25%/10%压缩率下达100%/95%/80%约束保留率，五轮迭代稳定在96%；相比最强单次压缩器（Sonnet 4.6为53%/39%/24%）提升2-4倍。
4. **分解可保证局部性**：TypeDecompose达到0%违规率（基线最低13%、最高93%），平均开销14.5%（中位数0%），最坏219%。
5. **检索可保证优先级**：TypeRetrieve在recall@50达100%（最强LLM检索器为73%），零LLM token开销。
6. **行为层面验证**：SafetyMed保留率超Sonnet 14.5个百分点（p<10⁻⁸）；零售通过率37.7%优于完整策略28.6%（p=0.003）和分层29.2%（p=0.005）；航空26.5%优于分层15.4%（p=0.024），与完整策略统计持平。
7. **声明式安全文本是分类瓶颈**：真实临床/法律安全文本中声明式占比约50-61%，语法分类器在此类表述上召回率崩溃至0.52-0.62，SafetyMargin恢复至0.90。

### 7. 优点

- **问题定义清晰且量化充分**：以“压缩悬崖”命名并系统性量度一个生产环境中真实存在但此前未被形式化的安全缺陷，采用多模型家族、多压缩率、多轮迭代的严格验证。
- **理论框架严谨**：从信息论的分类型失真度量（subsource-dependent distortion）出发为每个算子给出形式化安全要求和可证明失败模式，让“安全保留”成为可验证的工程属性，而非提示词层面的软约束。
- **确定性代替随机性**：三个算子均为确定性操作，无LLM调用，成本可预测、可复现；将唯一的“智能”集中在一次性分类器上，每项成本恒定且与压缩/查询次数无关。
- **分类器设计有洞察力**：反事实安全评分（SafetyMargin）从语义上识别约束而非语法表面特征，识别出声明式安全文本这一被忽视的关键故障模式。
- **验证链条完整**：从语料归纳 → 分类器 → 构件级算子 → 行为级下游评估 → 人类判断交叉验证，形成闭环；数据、代码、提示词全部开源，可复现性高。
- **语料规模大且面向真实世界**：AgentArtifactCorpus覆盖54,628个真实仓库、8个智能体平台，较以往评估语料更贴近生产环境。

### 8. 不足与局限

- **安全保证完全依赖于分类器召回率**：压缩悬崖被转化为“分类悬崖”——分类器漏掉一个约束即意味着该约束丢失。SafetyMargin的0.93召回率意味着7%的残余错误率（SafetyMed上对应9个漏检项目、4.5个百分点的差距）。缺少低召回高代价场景（如医疗）下的更保守工作点（如更低的θ_C阈值或强制人工审计）的系统性讨论。
- **评估语料的代表性偏差**：AAC仅来自公共GitHub仓库，企业级封闭语料（含大量隐含约束的专有配置）的类型分布可能截然不同；作者承认需要重新拟合分类器，但未提供任何跨环境迁移的量化实验。
- **标注一致性隐患**：五类级别Cohen's κ仅0.45，分歧集中在“程序-信念”边界（代码片段）；唯有“约束-其他”二元分割的κ=0.79可靠。这意味着约束以外的四类细粒度划分的可靠性存疑，间接影响分解与检索的效果评估。
- **MaRS对比的非对称性**：MaRS无公开实现，使用作者自研的MaRS-FL作为对照；作者承认数字可能因参考实现的差异而偏移，仅以“结构性论证不受影响”辩护——这在严格意义上不是对最先进方法的一等公民评测。
- **部分评估依赖LLM自标签**：AAC 200项测试集的参考标签由gpt-5.4-mini生成，gpt-5.4-mini的评估数字本质是“自我一致性”上限而非绝对准确率。所幸对抗性改写测试（标签已知）和人工标注（κ=0.79）部分缓解了此问题。
- **零售基准非等token对比**：TypeCompact的1,136 token明显多于分层截断的669 token，通过率差异可能部分源自保留的总上下文量而非类型化策略本身；航空的647 vs 718反向对照因“模型出错导致大量配对丢失”（gpt-5.4-nano在23/50完整策略单元上出错）而削弱了说服力。
- **下游评估模型覆盖有限**：多轮压缩衰减实验仅覆盖2个模型家族（宣称在全部4个家族有单轮数据），长期行为级验证缺失；航空领域整体通过率偏低，对“域外泛化”结论的支撑有限。
