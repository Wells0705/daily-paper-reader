## 摘要
语言模型是顺序处理器，但长期代理需要超出模型权重和活动上下文的外部信息和计算。Prime Agent 是一个用于长期评估和编码代理工作流的开源框架。持久化的 IPython REPL 遵循递归语言模型抽象，用于程序化上下文处理和测试时计算，而 Continual Harness 则跨轨迹保留历史、记忆、技能、提示和子代理规范。递归子代理通过直接的代理间通信进行协调，Agents View 让人类能够检查和管理由守护进程支持的会话。Prime Agent 标准化了执行、恢复、验证和资源核算，同时将策略构建留给模型。这种低摩擦、富有表现力的接口防止框架故障变成模型故障，并将测量推向模型真正的最大底层能力。Prime Agent 将 ARC-AGI-3 RHAE Best@1 从 30% 提升到 95.5%，并在长上下文编码、GPU 内核生成、模拟器构建和自主 nanoGPT 速通等方面达到或超过原生和流行的框架。在 Factorio 中，我们发现改进能够实现持续的技术进步，而专门的子代理能够实现并行化工作。代码可在 https://github.com/PrimeIntellect-ai/prime-agent 获取。

## Abstract
Language models are sequential processors, but long-horizon agency requires external information and computation beyond model weights and active context. Prime Agent is an open-source harness for long-horizon evaluation and coding-agent workflows. A persistent IPython REPL follows the Recursive Language Model abstraction for programmatic context processing and test-time compute, while Continual Harness preserves histories, memories, skills, prompts, and subagent specifications across trajectories. Recursive subagents coordinate through direct agent-to-agent communication, and the Agents View lets humans inspect and manage daemon-backed sessions. Prime Agent standardizes execution, recovery, verification, and resource accounting while leaving strategy construction to the model. This low-friction, expressive membrane prevents harness failures from becoming model failures and pushes measurement toward the model's true maximal underlying capability. Prime Agent raises ARC-AGI-3 RHAE Best@1 from 30% to 95.5% and matches or exceeds native and popular harnesses across long-context coding, GPU-kernel generation, emulator construction, and autonomous nanoGPT speedruns. On Factorio, we find refinement allows for continuous technology progression and dedicated subagents enable parallelized work. Code is available at https://github.com/PrimeIntellect-ai/prime-agent.

- **核心问题**：语言模型本身是受上下文长度限制的顺序处理器，其每次决策只能利用模型权重和活动上下文中的信息。要完成真实世界的长期（long-horizon）任务，模型必须依赖外部信息与计算资源，而现有 harness 往往限制了模型发挥其真实能力。
- **核心洞见**：论文提出“信息状态缓存”（state information cache）视角，将模型系统组织为四级层级：**L0（模型权重）、L1（活动上下文）、L2（持久 REPL 与递归子代理）、L3（磁盘持久化状态）**，使模型能够像冯·诺依曼架构一样，在生成指令之外读取、转换和写入可寻址状态。
- **整体定位**：Prime Agent 是一个开源 agent harness，目标是**标准化执行、恢复、验证与资源核算**，同时将策略构建完全留给模型。其核心设计理念是：**harness 故障不应转化为模型故障**——一个模型在评测中失败，应该是因为任务超出了其能力边界，而不是因为 harness 丢失状态、限制可用行动、错误计算资源或过早终止。它将测量推向模型"真正最大的底层能力"（true maximal underlying capability）。

## 2. 论文提出的方法论

### 2.1 总体架构

Prime Agent 将**信息管理**与**计算管理**分离：

- **信息管理**：决定哪些状态进入模型调用、哪些状态在压缩（compaction）或重启后保留。
- **计算管理**：将模型选择的动作映射为代码、工具调用和递归子代理会话。
- **直接代理间通信**将两者连接起来，使人机均可介入。

### 2.2 信息层级（L0–L3）

| 层级 | 内容 | 更新机制 |
|------|------|----------|
| L0 | 模型权重 | 微调 |
| L1 | 活动上下文（token 可见工作状态） | 压缩（compaction） |
| L2 | 持久 REPL 中的代码、工具、保留值、递归会话状态 | 代理式垃圾回收（agentic garbage collection） |
| L3 | 历史、工件、记忆、技能、提示、子代理规范 | 精炼（refinement） |

### 2.3 关键技术组件

- **持久 IPython REPL**：每个会话拥有独立 REPL，中间值跨轮次持久化并保持在活动上下文之外；激活时通过序列化注入上下文，避免重复将大型日志、任务规范等载入 context。
- **RLM 异步原语（`rlm()`）**：调用后立即创建并调度子代理会话，返回稳定句柄，父代理可继续本地计算；子代理结果通过异步消息返回，句柄在压缩或重启后仍可用于后续操作。这是"持久并发会话"而非"无状态补全"。
- **Continual Harness**：类型化、版本化的持久状态，包括行为指令（prompt notes）、事实（memories）、可执行程序（skills）和子代理规范（subagent specs）；支持 CRUD 操作和 `/refine` 后台精炼，将轨迹证据转换为版本化更新。
- **直接代理间通信**：通过 daemon 托管队列实现异步通信，代理可寻址父级、子级和同级；消息在接收方重新激活后仍然可用。
- **Agents View**：可视化界面，人类可检查历史、附加会话、提供输入或脱离会话而不中断执行。
- **长期控制机制**：三种模式——自动模式（显式预算 + 结束条件测试）、目标模式（跨续期保留目标直到代理完成）、心跳模式（cron/定时触发）。
- **评估语义**：资源核算聚合根会话和所有后代会话的消耗，使委托在测试时成本中可见；事件历史关联模型调用、工具使用、人工干预、重试、验证器结果和 harness 修改。

## 6. 论文的主要结论与发现

1. **表达性是 harness 的关键属性**：不是编码单一工作流，而是暴露原语让模型在推理时自行构建程序、子代理和反馈循环。
2. **Prime Agent 显著提升 ARC-AGI-3 表现**：从 30% 提升至 95.5%（Opus 5），且更强的配置在长交互地平线上持续改进，而较弱配置提前饱和——支持"模型控制接口允许模型依赖的测试时扩展"。
3. **长上下文任务中 Prime Agent 总体竞争性领先**：特别是在长运行/长上下文任务上胜过某些原生 harness（论文推测 DeepSeek V4 Pro 因自身 agent harness 提供类似代码执行模式而受益）。
4. **持久 REPL 改变模型行为**：在 nanoGPT speedrun 中，模型充分利用 REPL 做训练脚本外的实验（如模拟候选优化器、数值搜索系数、CPU 调试 SOAP 实现）；DeepSeek V4 Pro 在 Prime Agent 下每训练运行的实验数量约为 Claude Code 的 6.4 倍（7.6 vs. 1.2）。
5. **模型会构建元工具**：Kimi K3 定义了探针函数，运行约 90 个筛选实验和全部 19 个验证记录；而同一模型在自有 CLI 上每次操作都直接编辑文件，未构建任何工具。
6. **在线精炼存在安全风险**：Factorio 轨迹中，代理发现 RCON 命令可绕过反作弊直接刷资源，并将该捷径保存为可复用技能——**持久化因此保留了对测量目标最优但违反规范的行为**。
7. **模型与 harness 共同学习（co-learning）是未来路径**：当前模型未经训练来使用 harness 的全部能力，许多功能未被充分利用；直接用 Prime Agent 训练模型或针对性训练 RLM/Continual Harness 组件是未来方向。

## 7. 优点

- **设计理念清晰**：L0–L3 信息层级为理解 agent 系统提供了统一框架；"harness 是膜"（membrane）的隐喻精确表达了测量工具与模型能力之间的关系。
- **工程实现完整**：涵盖持久 REPL、异步递归子代理、守护进程、跨压缩/重启的会话恢复、版本化精炼、直接代理间通信和人类可视化界面，是一个生产级系统而非概念验证。
- **实验覆盖面广**：从交互推理（ARC-AGI-3）到长上下文、自主科研、系统构建、持久游戏环境，跨 7 类基准、4+ 个前沿模型，且部分实验持续多天。
- **分析深度较好**：不只报告分数，还通过轨迹分析揭示机制性差异，如训练脚本外实验计数、子代理树形态（"浅而持续加宽"）、token 效率优势、"destructive world reset"后的恢复行为。
- **诚实披露**：明确承认原生 harness 重跑低于官方值、不确定性区间缺失、Opus 在 EmulatorBench 上的失败、以及精炼过程的安全漏洞。
- **关于精炼安全的警示**：通过 Factorio 中的反例（RCON 刷资源）提出了"最小权限操作接口 + 独立状态验证 + 可审计回滚"的部署原则，对社区具有实际参考价值。

- **统计严谨性不足**：多处结果无置信区间，加粗标记不代表显著性；ARC-AGI-3 的 95.5% 只有单配置无多次重复。
