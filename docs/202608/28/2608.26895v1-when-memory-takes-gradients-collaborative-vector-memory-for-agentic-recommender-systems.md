## 摘要
智能体推荐系统将大型语言模型（LLM）的每个决策基于用户的持久记忆，而在现有智能体中，这种记忆是文本：由进一步的LLM调用编写和维护的叙述。文本以两种方式限制了这种记忆。它一次只能重写一个，因此利用完整的交互历史代价高昂；而协同证据——整个目录上的分级相似性——在转换为句子时无法保留。我们提出CoVeMem（协同向量记忆），将智能体记忆的协同核心向量化。冻结的LightGCN用户和物品状态构成记忆库；在每个决策时，候选集本身检索最相关的历史状态，这些状态作为软标记连同轻量级文本简介进入LLM的上下文。对比对齐到物品语义锚点，随后与掩码候选进行列表式协同训练，教会模型读取这些状态并通过它们进行排序；逐点的“是/否”读出对每个候选进行评分。在四个基于指令的推荐基准上，CoVeMem在20个指标单元中的19个上达到或超过最强的协同文本记忆智能体，同时除了共享静态简介外，记忆维护不需要额外的LLM调用，而文本记忆则需要每次交互调用。记忆现在获取梯度：完整的交互历史（文本难以企及）成为训练数据，用于智能体记住什么以及如何读取所记住的内容。

## Abstract
Agentic recommender systems ground each decision of a large language model (LLM) in a persistent memory of the user, and in existing agents that memory is text: a narrative written and maintained by further LLM calls. Text limits this memory in two ways. It is updated one rewrite at a time, so exploiting the full interaction history is prohibitively expensive; and collaborative evidence, graded similarity over an entire catalog, does not survive translation into sentences. We propose CoVeMem (Collaborative Vector Memory), which vectorizes the collaborative core of the agent's memory. Frozen LightGCN user and item states form the memory bank; at each decision, the candidate set itself retrieves the most relevant historical states, which enter the LLM's context as soft tokens alongside a light textual profile. Contrastive alignment to item-semantic anchors, followed by listwise co-training with masked candidates, teaches the model to read these states and to rank through them; a pointwise yes/no readout scores each candidate. Across four instruction-grounded recommendation benchmarks, CoVeMem matches or exceeds the strongest collaborative text-memory agent on 19 of 20 metric cells while requiring zero additional LLM calls for memory maintenance beyond the shared static profile, against per-interaction calls for text memory. The memory now takes gradients: the full interaction history, out of reach for text, becomes available as training data for what the agent remembers and for how it reads what it remembers.

## 1. 核心问题与整体含义（研究动机与背景）

智能体推荐系统（Agentic Recommender Systems）让 LLM 充当用户与推荐平台之间的决策代理，并依赖**持久记忆**来承载跨会话的用户偏好。然而，现有智能体的记忆几乎全部以**文本形式**存在——由 LLM 通过串行重写不断更新用户叙述。论文指出这种文本记忆存在两个根本局限：

- **维护成本高**：文本记忆是"一次一次重写"的，吸收每条新交互都需要一次额外的 LLM 调用，利用完整交互历史在计算上极其昂贵。
- **协作结构丢失**：协同过滤的核心是覆盖整个目录的**分级相似性关系**（graded relations spanning an entire catalog），这种几何结构在序列化为句子时几乎必然被压缩和损失——文本只能表达它"指名道姓"的内容。

此外，文本记忆无法直接被排序梯度更新：即使推荐模型可以从反馈中学习，梯度也无法反向传播去修改已存储的文本。这使得记忆系统无法端到端地由推荐目标进行训练，完整交互历史中的数据无法被充分利用。

论文的总体含义：**记忆的载体（carrier）本身是一个独立的设计维度**——它决定了哪些证据能够进入决策。CoVeMem 将记忆的协同核心向量化，使记忆"可被梯度训练"，让完整交互历史首次成为可用的训练信号。

## 2. 方法论：核心思想、关键技术细节

### 2.1 总体架构：混合记忆系统

CoVeMem 采用**混合记忆**设计：
- **协同向量记忆**（Collaborative Vector Memory）：存储证据，由冻结的 LightGCN 用户/物品状态构成，维度 d=64，基于训练交互的二部图训练后冻结。
- **参数化记忆读取器**（Parametric Memory Reader）：学习如何使用这些证据，由门控投影器（gated projector）和 LoRA 适配器组成，跨用户共享。

### 2.2 记忆库与目标感知检索（Target-aware Retrieval）

- 记忆库：LightGCN 在**仅训练交互图**上学习得到的用户状态 {s_u} 和物品状态 {v_i}，训练后冻结；验证/测试信号不会泄漏到状态中。
- 检索机制：对于候选集 C_u，计算候选质心 c̄ = (1/|C_u|)Σv_c，用它查询用户可用历史，返回 **K=5 个与当前选择最相关的历史物品状态**（内积相似度），而非最近的历史。检索只需点积运算，不需要 LLM 调用。
- 因果保证：训练时使用严格因果前缀，评分目标物品不在检索范围内，防止泄漏。

### 2.3 记忆注入与提示结构

- 门控投影器 φ（两模块门控 MLP）将状态向量映射到 LLM 输入嵌入空间，每个状态占据一个**软 token** 位置。
- 提示包含固定记忆结构：用户文本画像、K 个 token-history 槽（φ(v_i)）、同名文本标题行、用户软 token φ(s_u)、候选行（标题+物品软 token φ(v_c)）。
- 投影器是状态向量进入模型的唯一路径，LoRA 适配器（rank r=4，约 6.8M 参数，不到模型的 0.1%）适应注意力如何读取这些软 token。

### 2.4 两阶段训练

**阶段 1：语义锚点对齐（Semantic-anchor Alignment）**

用物品标题和类别的 LLM 嵌入均值构造语义锚点 y_i，通过对称的批内对比损失训练投影器：
- L_align = ½ [CE(φ(v)ŷᵀ/τ) + CE(ŷφ(v)ᵀ/τ)]，使用 ℓ2 归一化、温度 τ=0.07

**阶段 2：列表式协同训练（Listwise Co-training）**

- 每个训练交互（从第 4 条起）构成一个排序事件：前缀为历史，交互物品为正样本，N−1 个负样本从用户完整序列之外均匀采样。
- 使用边际损失（margin loss）：L_rank = (1/(|P|−1)) Σ max(0, m − (z_y − z_j))，m=1.0。
- **候选掩码**：以概率 p=0.5 隐藏候选标题，被掩码的候选只保留物品软 token 作为身份。
- **门控退火**：软 token 的缩放门在前 T_g=60 步从 0 退火到 1，逐渐打开记忆通道。
- 引入 drop-out 防止过拟合固定布局位置。
- **训练中刻意不包含用户指令**：InstructRec 的指令由留出目标物品推导而来，属于目标条件信息，在训练中使用会造成泄漏；指令仅在推理时进入。

### 2.5 推理：逐点判断（Pointwise Yes/No Readout）

- 每个候选获得独立的紧凑提示，其中协同 token 保持显著性；同一用户的 token-history 槽在候选间共享。
- 得分为答案位置 "Yes" token 的 logit：s_c = M[T_u ∥π M_text_u ∥ Φ(Ĥ_u) ∥ t(Ĥ_u) ∥ φ(s_u) ∥ (c, φ(v_c)) ∥ P_judge]("Yes")
- 指令位置 π 通过零样本规则卡选择（早期/中期/晚期），根据训练集统计特征（交互密度 d、集中度 q）预测，不使用任何测试反馈。

## 6. 主要结论与发现

- **性能**：CoVeMem 在 20 个指标单元中的 **19 个上匹配或超过最强文本记忆基线 MemRec**。Goodreads 增益最大（H@1 从 0.3087 提升到 0.7730），MovieTV 全指标方向一致但幅度较小，Yelp 全面领先，Books 上几乎持平。
- **消融结论**：
  - 注入的向量状态是增益的主要来源（即使选择规则不同，H@1 优势大部分保留）。
  - 目标感知选择优于最近选择（Text-TA 优于 Text-Recent），说明**候选条件检索**本身就有价值。
  - 移除 LoRA 后性能跌至 Vanilla LLM 甚至概率水平——证明 **LoRA 适配器是模型读取向量记忆的必要条件**，没有它注入的状态反而干扰文本证据。
- **记忆效率**：CoVeMem 记忆维护**零额外 LLM 调用**（对比文本智能体每次交互或决策都要维护性调用），决策时间 token 成本也是四个智能体系统中最低的。
- **骨干可迁移**：向量记忆的有效性取决于协同骨干的质量——SVD++ 最强（超越默认 LightGCN），而 SASRec 最弱，几乎不优于纯文本变体。

## 7. 优点（亮点）

- **概念创新**：首次将"记忆载体"作为独立设计维度提出，用向量状态替代文本叙述承载协作信息，使记忆可被梯度端到端训练，突破了文本记忆的维护瓶颈和信息瓶颈。
- **因果严谨性**：训练事件的严格前缀因果设计、指令排除、测试目标从图和画像中隔离，显著降低了评估作弊风险。
- **设计精巧**：候选掩码机制创造了标题无法解决的比较，迫使模型学会通过协作 token 排序；门控退火在投影器尚未可靠时安全地打开记忆通道；逐点 yes/no 读取避免了生成排序器的解析失败。
- **模块化架构**：记忆库与读取器解耦，任何传统推荐器（MF、图传播、序列模型）都能提供记忆库，管线可端到端重训。
- **资源高效**：总训练参数约 6.8M（<0.1% 模型），单 GPU 可运行。

## 8. 不足与局限

- **实验覆盖**：仅在 InstructRec 的 4 个域上评估，未在更广泛的推荐场景（如短会话、冷启动用户、大规模实时流）中验证。
- **候选规模有限**：固定 N=10 的排序任务弱化了真实场景中候选集规模（数百到数千）时的检索压力。
- **未报告时间成本**：论文未给出训练总时长、推理延迟、吞吐量等工程指标，只报告了 token 计数。
- **记忆维护边界界定**：声称"零维护成本"时排除了共享静态画像的一次性构建；在需要频繁更新用户偏好的真实动态场景中，静态画像可能过时。
- **骨干质量依赖**：实验证明模型上限受限于协同骨干的质量（SASRec 几乎无优势），选择/调优骨干本身构成新的负担。
- **训练偏差风险**：事件采样上限 25,000/轮可能导致活跃用户的样本重复，长尾用户覆盖不足；指令位置仅按数据集选择一个固定槽位，未探索每实例动态位置。
- **应用限制**：需要额外的向量检索基础设施（虽然有 LightGCN 状态表和点积检索），对部署方有工程要求；soft token 的可解释性低于文本，调试困难。
