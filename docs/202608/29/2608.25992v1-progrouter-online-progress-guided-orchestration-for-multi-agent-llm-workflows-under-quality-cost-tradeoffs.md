## 摘要
多智能体大语言模型（LLM）工作流已成为一种强大的范式，通过专门化LLM智能体之间的协作推理来解决复杂、开放式的任务，但由于重复的LLM调用和长时间跨度的上下文积累，它们会产生巨大的运营成本。现有的级联路由方法做出一次性、查询级别的决策，无法适应多步骤工作流的动态、状态依赖特性，在这些工作流中，每一步选择合适的LLM取决于不断变化的任务进度、剩余任务难度和成本效率要求。我们提出了ProgRouter，一种在线进度引导的路由框架，它在工作流步骤之间自适应地选择LLM智能体，以在遵守时间和成本预算的同时保持任务解决质量。ProgRouter引入了一个多视图任务进度评分器，将粗略的工作流结果状态与子任务完成度、进度趋势和工作流状态质量的细粒度信号相结合。然后，一个双路径任务进度预测器和一个自适应元门控机制估计每个候选路由LLM的进度增益。ProgRouter做出在线逐步路由决策，平衡进度增益、任务时间预算和长期运营成本效率。在HumanEval Plus、MBPP、MATH-500和ASQA上的实验，涵盖代理代码生成、数学推理和检索增强的长格式问答，表明ProgRouter相对于关键基线降低了运营成本，同时保持了强大的任务解决性能。

## Abstract
Multi-agent large language model (LLM) workflows have emerged as a powerful paradigm for solving complex, open-ended tasks through collaborative reasoning among specialized LLM agents, but they incur substantial operating costs due to repeated LLM invocations and long-horizon context accumulation. Existing cascade routing methods make one-shot, query-level decisions and cannot adapt to the dynamic, state-dependent nature of multi-step workflows, in which the right LLM at each step depends on evolving task progress, remaining task difficulty, and cost-efficiency requirements. We present ProgRouter, an online progress-guided routing framework that adaptively selects LLM agents across workflow steps to preserve task-solving quality while adhering to time and cost budgets. ProgRouter introduces a multi-view task progress scorer that combines coarse workflow outcome regimes with fine-grained signals on subtask completion, progress trends, and workflow state quality. Then, a dual-path task progress predictor and an adaptive meta-gating mechanism estimate the progress gain for each candidate routed LLM. ProgRouter makes online step-wise routing decisions that balance progress gain, task time budgets, and long-term operating cost efficiency. Experiments on HumanEval Plus, MBPP, MATH-500, and ASQA, spanning agentic code generation, mathematical reasoning, and retrieval-augmented long-form question answering, demonstrate that ProgRouter reduces the operating cost relative to key baselines while maintaining strong task-solving performance.

- **背景**：多智能体 LLM 工作流通过多个专门化智能体（如编码、分析、检索）协作解决开放式复杂任务，但反复调用 LLM 和长跨度上下文累积导致高能耗、高时间和高成本。
- **现有方法不足**：级联 LLM 路由（如 Cascade）只做一次性、查询级决策，无法适应多步工作流中状态依赖的智能体选择；静态基准或离线偏好数据也无法满足在线、上下文内的路由需求。
- **核心研究问题**：如何在运营成本预算约束下，动态地为多智能体工作流中的每一步选择最合适的 LLM 智能体，从而在保持任务完成质量的同时控制成本？
- **整体含义**：本文提出在线逐步路由框架 ProgRouter，将任务进度感知引入路由决策，实现质量、时间和成本三方权衡，为可持续、经济的大规模多智能体 LLM 服务提供新方案。

## 2. 方法论

### 2.1 问题建模
- 将 LLM 智能体编排建模为**在线约束优化问题**：
  - 最大化任务成功率（或 ASQA 中的引用精度）；
  - 约束条件包括：每个任务的时间预算 Γw、运营成本预算 Ew，以及长期平均运营成本约束 Ē。
- 策略 π(s_t, r_t) → m_t 根据当前工作流状态选择该步骤的 LLM 实例。

### 2.2 多视图任务进度评分器
- 将中间工作流状态编码为归一化进度分数 g(s_t) ∈ [0,1]。
- 结合四个互补视角：
  - **整体结果状态**：分为 invalid / recoverable / partial / complete 四类粗粒度状态，提供基础分数 b(c_t)；
  - **子任务完成度**：统计满足需求的比例 r_t；
  - **进度趋势**：最近几步平均进度变化 d_t；
  - **状态质量**：语义/结构合理性，如嵌入相似性和新解决子任务 e_t。
- 聚合公式：`g(s_t) = b(c_t) + α_{c_t} r_t + β_{c_t} d_t + γ_{c_t} e_t`。
- 该评分器是“轻量领域适配器”，新领域只需调整里程碑定义和粗粒度状态。

### 2.3 双路径任务进度预测器
- 学习函数 ŷ_t = PΘ(s_t, m_t)，估计调用候选 LLM m_t 后可能获得的进度增益。
- **结构化路径**：使用表格特征（进度分数、子任务状态、历史路由决策等），由树模型（随机森林/XGBoost）回归，得到 ŷ^{str}_t。
- **语义路径**：将工作流状态和候选路由决策生成自然语言摘要，经 MiniLM 嵌入后由树模型回归，得到 ŷ^{sem}_t。
- **元门控融合**：XGBoost 元学习器根据工作流状态自适应组合两条路径的估计，得到最终 ŷ_t。

### 2.4 在线决策算法
- 受 Lyapunov 漂移-惩罚框架启发，维护**虚拟成本队列** Q 跟踪长期平均成本约束的违规累积：
  `Q_{w+1} = max{0, Q_w + Σ_t E(m_t) − Ē}`
- 定义**进度缺口感知收益**：`eP = V·(1 − g(s_t))·ŷ_t`，剩余进度越大，强模型价值越高。
- 定义**预算感知成本惩罚**：指数系数 c^Γ_t、c^E_t 随累计时间/成本使用增加而增大。
- 最终路由分数：
  `score(m_t) = eP(m_t) − Q_w·(E(m_t) − Ē) − c^Γ_t·Γ(m_t) − c^E_t·E(m_t)`
- 每一步选择分数最高的 LLM。
- **在线学习**：采用 ε-greedy 探索随机候选模型，收集真实进度增益 Δ = g(s_{t+1}) − g(s_t) 作为训练样本；预测器定期更新，ε 随经验积累逐渐衰减，从探索过渡到利用。无需离线训练数据。

## 6. 主要结论与发现

- **单模型策略全部违反预算约束**：无论小模型（重复调用导致高累计能耗）还是大模型（单次调用能耗过高）都不能在同时满足质量与预算。
- **ProgRouter 在满足长期预算的方法中取得最佳质量-成本权衡**：
  - HumanEval Plus：pass rate 93.0%，能量 4796 J，优于 MasRouter（90.9%）和 CASCADIA（84.8%）；
  - MBPP：pass rate 79.4%，能量 3376 J，时间 10.3s，全面优于所有满足预算的基线；
  - MATH-500：能量 6112 J，时间 19.0s 最低，pass rate 84.3%（比 CASCADIA 低 3.5%，但成本显著降低）；
  - ASQA：citation precision 92.1%，在所有方法中最高，同时满足 19000 J 预算。
- **自适应路由呈专业化模式**：ProgRouter 多数步骤选择小模型，仅当进度预测显示强模型可带来显著增益时才调用大模型，有效分配预算。
- **消融证明各组件均有贡献**：双路径元门控预测器最佳；多视图评分器优于单一测试结果；预算惩罚和虚拟队列对长期成本控制重要；单纯“进度/成本”贪心策略会导致失败（pass rate 仅 17.7%），说明完整目标函数不可替代。

## 7. 优点

- **方法创新**：将任务进度估计与在线路由控制有效结合，能处理多步、状态依赖的动态路由问题，而非固定查询级路由。
- **轻量适配**：多视图进度评分器作为轻量领域适配器，迁移新任务只需调整里程碑定义，核心算法与领域无关。
- **无监督在线学习**：无需离线标注数据，通过 ε-greedy 在线探索学习，适应不同任务流。
- **能量测量严谨**：使用物理 GPU 功耗进行积分测量，比 token 估算更可信。
- **实验覆盖多样**：涵盖代码生成、数学推理和开放式检索问答，验证了方法的通用性。
- **消融分析全面**：对预测器设计、在线路由组件和朴素策略均有对比，清晰展示每个组件的贡献。

## 8. 不足与局限

- **评估范围有限**：仅覆盖四个基准，未覆盖网页导航、工具调用等更开放的 agentic 场景，泛化性尚待验证。
- **进度评分器需手工适配**：多视图评分器依赖人工定义可观察里程碑和粗粒度状态，未实现端到端自动学习进度表示。
- **实验重复性不足**：抽样数据集未报告方差/置信区间；任务流随机种子固定，不能完全反映不同顺序下的稳定性。
- **模型库和协调器特定性**：实验限定于特定模型族和单一协调器（Qwen3-Coder-Next），对于其他模型族或开源/闭源混合环境可能需重新校准。
- **能耗边界有限**：只统计 GPU 能耗，未包含 CPU、内存、存储、网络等，真实运营成本可能被低估。

- **可能存在路由偏差**：在线学习过程中早期探索可能导致对特定模型的过度依赖，需人工监控路由模式。
