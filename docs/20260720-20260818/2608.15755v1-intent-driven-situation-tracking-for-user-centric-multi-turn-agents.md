## 摘要
用户中心的多轮代理必须根据不断变化的用户意图、累积的工具事实、缺失信息和执行约束来行动于不断演变的任务情境。现有的上下文管理方法改善了对过去交互历史的使用，但很少维护一个将事实与任务状态判断分离的显式情境状态。因此，代理往往需要从对话痕迹中隐式推断细粒度的属性、任务依赖性和约束满足情况。我们提出了意图驱动情境状态（IDSS），这是一种无需训练的框架，在对话之外维护显式的情境状态。IDSS将工具返回解析为具有来源意识的实体和属性，跟踪用户意图、所需变量、约束和执行状态，并将新事实传播到任务约束以更新动作的可执行性。这使得代理能够避免不可行的动作，推进依赖目标，并在不反复搜索原始历史的情况下重用相关信息。在跨越八个LLM的三个交互基准测试上的实验表明，IDSS提高了任务完成度、偏好引导和交互效率，在多实体协调、演化用户约束和约束感知重新规划的任务上取得了明显收益。消融和错误分析表明，这些改进来自于事实持久性、意图中心的状态跟踪和约束建模之间的交互。这些结果表明，显式情境跟踪为可靠的用户中心多轮代理提供了一种有效的替代历史中心上下文管理的方法。

## Abstract
User-centric multi-turn agents must act on an evolving task situation shaped by changing user intents, accumulated tool-grounded facts, missing information, and execution constraints. Existing context-management methods improve the use of past interaction history, but rarely maintain an explicit situation state that separates grounded facts from task-state judgments. As a result, agents often need to infer fine-grained attributes, task dependencies, and constraint satisfaction implicitly from dialogue traces. We propose Intent-Driven Situation States (IDSS), a training-free framework that maintains an explicit situation state alongside the dialogue. IDSS parses tool returns into provenance-aware entities and attributes, tracks user intents, required variables, constraints, and execution status, and propagates new facts to task constraints to update action executability. This allows agents to avoid infeasible actions, advance dependent goals, and reuse relevant information without repeatedly searching raw history. Experiments on three interactive benchmarks across eight LLMs show that IDSS improves task completion, preference elicitation, and interaction efficiency, with clear gains on tasks involving multi-entity coordination, evolving user constraints, and constraint-aware replanning. Ablations and error analyses show that these improvements come from the interaction between fact persistence, intent-centered state tracking, and constraint modeling. These results suggest that explicit situation tracking offers an effective alternative to history-centric context management for reliable user-centric multi-turn agents.

- **背景**：在客服、旅行规划、生活服务等用户中心的多轮交互场景中，LLM Agent 需要持续理解用户演化中的目标、调用外部工具、遵循规则，并在“询问、检索、执行、结束”之间做决策。与单轮工具调用或单目标长程规划相比，多轮用户交互对**状态维护**提出了更高要求。
- **核心问题**：现有上下文管理方法（如外部记忆、摘要压缩、上下文折叠）虽然能改善历史信息的存取或压缩，但**很少维护一个显式的、分离“工具事实”与“任务状态判断”的情境状态**。agent 需要从越来越长的对话历史中隐式推断细粒度属性、意图依赖、缺失变量和约束满足情况，容易导致事实遗漏、意图漂移、过早执行、约束违反等问题。
- **整体含义**：论文提出**意图驱动情境状态（IDSS, Intent-Driven Situation States）**，一种免训练框架，在对话历史之外维护结构化、面向决策的显式情境状态，让 agent 直接基于“当前任务情境”行动，而不是反复搜索原始历史。作者希望通过这种范式转变，替代以历史为中心的上下文管理，提升多轮 agent 的可靠性和效率。

## 2. 方法论

- **核心思想**：将多轮交互组织为“意图驱动的情境跟踪”，形式化地将历史驱动的策略 `a_t = π(H_t, A)` 替换为情境增强策略：
  `a_t = π(D_t, H_comp_t, A)`
  其中 `D_t = (F_t, S_t)` 是显式情境状态，`F_t` 为事实层，`S_t` 为状态层，`H_comp_t` 为去除状态覆盖内容后的压缩残差历史。

- **事实层（Fact Layer）**：
  - 将工具返回结果通过**确定性解析器**转换为结构化实体：`F_t = {e_i = (type_i, id_i, attrs_i, src_i)}`。
  - 更新操作为原子操作序列 `Δ_t = Parse(o_t)`，逐轮增量应用 `F_t = F_{t-1} ⊕ Δ_t`，支持 ADD、UPDATE、DELETE、MERGE。
  - 冲突解决依赖来源可信度：工具观测优先于 agent 推断，同一来源中较新覆盖较旧。
  - 已解析的工具返回在历史中被替换为事实层引用，压缩 prompt 同时保留可查询的事实。

- **状态层（State Layer）**：
  - 围绕用户意图构建，包含三部分：**意图集 I_t**、**变量集 V_t**、**约束集 C_t**。
  - 意图状态包括 ACTIVE、PENDING、COMPLETED、BLOCKED，并记录意图间依赖。
  - 变量标注为 ASKABLE / RETRIEVABLE / DERIVABLE，并标记已知/未知，支持 agent 决定是询问、检索还是推导。
  - 约束表示为带证据的规则，状态为 SATISFIED、UNSATISFIED 或 VIOLATED。
  - agent 被要求在每个响应前输出 `<state>` 块，该块被解析、从用户可见回复中移除，并在下一轮重新注入 prompt，**不需要额外 LLM 调用**。

- **跨层约束传播（Cross-Layer Constraint Propagation）**：
  - 事实层更新后，自动重新评估约束状态。
  - 若约束被违反，则阻塞相关意图并记录事实依据和约束链；同时可激活替代意图（如“不能改签 → 取消并重新预订”）。
  - 该机制让 agent 理解“为什么不可行”，而不是盲目重试。

- **完成判定**：当所有意图均为 COMPLETED 或 BLOCKED，且可执行意图所需变量均已已知时，判定任务完成；否则由未解决的意图或变量引导下一轮动作。

## 6. 主要结论与发现

- IDSS 在三个 benchmark 上整体最佳，且对多种 LLM 均带来一致收益；雷达图显示其在多个评估维度上覆盖更均衡。
- τ-bench 中，对更复杂的 Airline 任务提升更显著：相比最强 baseline U-Fold，Airline 平均提升 1.5 Avg@4、2.0 pass@4；Retail 提升较小但正向。
- VitaBench 中，IDSS 在需要多实体协调、跨服务组合和状态继承的 OTA、Cross-domain 上优势最明显，分别比 U-Fold 提升约 1.7 和 2.1 点。
- UserBench 中，IDSS 在 Score 和 CER 上均优于所有对比方法，相对 U-Fold 约提升 4.6% Score 和 4.0% CER；PE 提升相对较小。
- 消融显示：事实层对 τ-bench 贡献最大；状态层对 UserBench 贡献最大；VitaBench 需要两者共同作用；约束建模带来一致小幅增益。
- 错误分析显示，IDSS 将事实遗漏从 14% 降到 8%，缺信息错误从 8% 降到 5%；但约束违反率的降低有限，说明仍有模型理解不足导致的规则问题。
- 效率方面，IDSS 在零额外 LLM 调用的情况下，达到最高平均性能（50.5%）和最少平均交互轮数（7.8）。

## 7. 优点

- **免训练**：不依赖任务特定微调或强化学习，可直接应用于不同 LLM。
- **零额外 LLM 调用**：事实层用确定性解析，状态层通过 prompt 内 `<state>` 块维护，不增加推理调用次数。
- **双层分离的设计清晰**：将“工具事实”与“任务状态判断”解耦，避免把用户偏好、约束满足和事实混在历史文本中。
- **可解释的状态更新**：约束传播记录证据链，agent 能说明为何阻塞某个意图、为何激活替代意图。
- **prompt 压缩与决策对齐**：用事实层引用替换工具返回，压缩上下文，同时让 agent 直接基于决策所需信息行动。
- **实验覆盖面广**：8 个模型、3 个 benchmark、多个子域、消融、错误分析、效率分析和 case study 相结合，支撑主要结论。

## 8. 不足与局限

- **输入格式限制**：IDSS 依赖工具返回为可解析的文本字段；对多模态观测、非结构化富文本或更复杂工具环境的适用性尚未验证。
- **模拟用户局限**：实验全程使用 GPT-4.1 模拟用户，缺少真实用户交互验证，自然表达、纠正和偏好演化可能与模拟不同。
- **统计稳健性不足**：只报告 4 次试验平均，没有方差、置信区间或显著性检验，部分小幅度提升可能不具统计意义。
- **约束违反改善有限**：错误分析显示约束违反率在方法间差异不大，说明 IDSS 不能弥补模型本身规则理解能力不足。
- **无算力/成本详细报告**：未提供 GPU/推理成本等细节，难以评估大规模部署时的资源开销。
- **方法复杂度**：需要为每个任务维护实体 schema、状态块格式和约束传播逻辑，应用门槛较高；在某些简单场景中增益有限。
- **安全边界**：作者指出 IDSS 不能消除工具输出错误、模型幻觉或高风险场景中的部署风险，仍需要人工监督和任务级防护。
