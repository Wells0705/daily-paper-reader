## 摘要
智能体任务本质上是长时程、多轮次的，在与环境交互过程中会不断积累上下文。现有的上下文压缩方法不可避免地会造成信息丢失，并且由僵化的启发式规则触发，与智能体不断演变的推理焦点不一致。我们提出了智能体上下文管理（ACM），这是一个为智能体配备专用上下文编辑工具以实现无损上下文管理的框架。受人类短时与长时记忆交互的启发，智能体自主决定何时压缩其上下文，将丢弃的内容卸载到外部记忆系统，并在后续需要时按需查询。在此框架基础上，我们进一步开发了一个后训练流程，构建高质量的上下文管理演示，并在智能体搜索和编码任务上提升模型性能。进一步分析表明，有效的上下文管理能够降低峰值令牌压力，支持更长时间探索，并在独立试验中产生更一致的解决方案。代码、数据和模型检查点可在 https://github.com/lixiaochuan2020/agentic-context-management 获取。

## Abstract
Agentic tasks are inherently long-horizon and multi-turn, constantly accumulating context through interactions with the environment. Existing context compression methods inevitably incur information loss and are triggered by rigid heuristic rules, leaving them misaligned with the agent's evolving reasoning focus. We propose Agentic Context Management (ACM), a framework that equips agents with purpose-built context editing tools for lossless context management. Inspired by the interaction between short-term and long-term human memory, the agent autonomously decides when to compress its context, offloads discarded content to an external memory system, and queries it on demand for later retrieval. Building on this framework, we further develop a post-training pipeline that constructs high-quality demonstrations of context management and improves model performance on both agentic search and coding tasks. Further analysis reveals that effective context management reduces peak token pressure, enables extended explorations, and yields more consistent solutions across independent trials. Code, data, and model checkpoints are available at https://github.com/lixiaochuan2020/agentic-context-management.

- **现有方法的不足**：
  - 长上下文预训练虽有帮助，但存在性能退化；混合注意力只能降低处理成本，本质上仍受窗口限制。
  - 现有上下文压缩方法（如 ReSum、ACON、DeepSeek-V3.2 的固定策略）依赖**外部监控器**以**僵化的启发式规则**（如上下文使用率达 90%）触发压缩，与智能体自身的推理状态和任务进度不对齐。
  - 压缩过程往往**有信息损失**：原始消息被丢弃，无法在后续按需恢复。
- **论文的含义**：提出让智能体**自主管理自身上下文**的新范式——将上下文管理视为智能体推理过程中的显式动作，而非外部干预。受人类短时记忆与长时记忆分离的认知机制启发，实现**无损**、**智能体自主发起**的上下文管理，并配套后训练流程使模型内化该能力。

### 2. 论文提出的方法论：核心思想、关键技术细节、算法流程

#### 2.1 框架核心思想

ACM 框架模拟人类记忆机制，引入两种工具：

- **manage_context**（上下文管理工具）：智能体自主决定何时调用，将自上次压缩边界以来的所有消息压缩为一份摘要，并**保留原始消息到外部磁盘存储**（长时记忆）。摘要带唯一标识符（summary_id）映射到原始消息。
- **query_memory**（记忆查询工具）：智能体在后续推理中若需要回顾已压缩的原始内容，可携带 summary_id 和查询语句调用此工具，系统从外部存储加载原始消息并用 LLM 提取相关信息返回。

这两个工具使得：
1. **无损压缩**：工作上下文保持简洁，但被压缩内容不丢失，可随时按需检索。
2. **智能体自主决定**：压缩时机由智能体自身的推理状态驱动，而非外部固定阈值触发，可在上下文达到峰值之前主动压缩。

#### 2.2 后训练数据生成流程（双约束 teacher–student 框架）

- **阶段一：学生轨迹采集（Student Rollout）**。学生模型（Qwen3.5-9B）在两种条件下完成任务：① 无 ACM 工具（H⁻）；② 有 ACM 工具（H⁺）。前者捕获普通探索行为，后者捕获未经训练的上下文管理工具使用行为。
- **阶段二：教师标注（Teacher Annotation）**。教师模型（Qwen3.5-397B-A17B）基于参考答案和黄金证据审查学生轨迹，产生两种互补的约束信号：
  - **注入约束（对 H⁻）**：教师识别学生轨迹中本应调用上下文管理工具的位置（如冗余查询、死循环、上下文积累过多），注入带有合理解释的 manage_context 或 query_memory 调用。
  - **修正约束（对 H⁺）**：教师识别学生不恰当调用上下文管理工具的位置（如证据已充分却未提交答案、遗漏了检索结果中的关键证据），将压缩调用替换为更有效的动作（进一步搜索、打开文档、提交答案），并附上推理过程。
- **训练目标**：采用 **on-policy distillation**，学生在教师标注后的轨迹上继续执行，教师对学生所有 assistant token 位置提供 top-K（K=20）软标签分布，学生优化交叉熵损失：
  \[
  \mathcal{L}_{ACM}(\theta) = - \mathbb{E}_{\tau \sim \pi_\theta} \left[ \sum_{t \in T_a(\tau)} \sum_{v \in V} p_T(v \mid s; h_{<t}) \log \pi_\theta(v \mid s; h_{<t}) \right]
  \]
  其中 \(\tau\) 为学生采样轨迹，\(T_a(\tau)\) 为 assistant token 位置，\(V\) 为教师 top-K 候选词表，\(p_T\) 为教师在 \(V\) 上归一化的概率分布，\(h_{<t}\) 为历史交互序列。

- **质量过滤**：① 拒绝采样——仅保留学生未能成功完成的轨迹，确保学习的是真正有挑战性的问题；② 内容过滤——检查教师推理不泄露参考答案信息，避免模型依赖答案线索；③ 混合学生原始轨迹进行自蒸馏以稳定训练。

### 6. 论文的主要结论与发现

- **ACM 框架显著提升长时程智能体性能**：基于 Qwen3.5-9B，仅装备 ACM 工具（不训练）即可超过所有基线；配合后训练进一步将 BrowseComp-Plus 准确率从 57.0% 提升至 72.7%（相对提升 27%），在 DeepSearchQA 提升 16%，SWE-Bench Verified 提升 8%，接近比其大 40 倍的开源模型。
- **ACM 减少峰值 token 压力**：相比 ReAct 和 Summary Agent，峰值 token 使用量显著下降（约 20%），降低推理负担和服务器 KV-cache 开销。
- **ACM 延长有效探索**：上下文被压缩后智能体可以执行更多工具调用（如 ACM-Post-Trained 平均 46.2 次工具调用 vs ReAct 19.5 次），支持更长时间的多步探索。
- **上下文管理带来更一致的解决方案**：Pass K 指标大幅提升，说明干净的上下文使模型在独立试验中更稳定地得到正确答案，而不仅限于扩大能力边界。
- **强模型也缺乏主动上下文管理行为**：GPT-5.5 在 ACM 框架下几乎不调用上下文管理工具，验证了为模型提供上下文管理数据训练的必要性。
- **小模型无法受益**：Qwen3-4B-thinking 因推理能力不足，轨迹过短（平均 2 回合）而无法进入需要上下文压缩的场景。

### 7. 优点

- **创新范式**：将上下文管理从外部启发式规则转变为智能体自主决策的显式动作，与人类记忆机制类比清晰、直觉合理。
- **无损管理**：不同于有损压缩方法，ACM 保存原始消息到外部存储并支持按需查询，兼顾上下文简洁性与信息可恢复性。
- **数据管线开源且高效**：双约束的 teacher–student 蒸馏管线无需繁重的强化学习，数据生成过程高效、易扩展，且代码、数据和模型全部开源——这在同类工作中（如 AgentFold）是显著补充。

- **实际收益明确**：不仅提升准确率，还降低峰值 token 压力、支持更长探索，对部署成本友好。

### 8. 不足与局限

- **对基础模型能力有前提要求**：ACM 只有在模型能够持续进行长时程多步探索时才有意义。弱模型（如 4B 级）轨迹过短，无法触发上下文管理行为，因此该方法不适用于能力不足的小模型。
