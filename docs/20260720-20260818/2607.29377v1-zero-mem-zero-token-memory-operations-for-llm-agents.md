## 摘要
LLM智能体需要内存以在长时间交互中保持一致的行为，然而许多系统使用额外的LLM调用来操作该内存。生成中间记录并调节其检索会增加周期性的令牌和时间成本，而省略或合并的细节可能掩盖原始证据。我们质疑结构化内存访问是否完全需要生成。Zero-Mem引入了“零令牌内存操作”：在最终问答之外的任何步骤都不调用LLM或消耗LLM的输入或输出令牌；编码器计算单独核算。Zero-Mem保留原始交互轨迹作为其记录来源。它以两种互补的方式组织这些轨迹。实体-上下文图展示了跨交互的连接，而时间层次结构则保留了对话的局部性和会话状态。对于每个查询，Zero-Mem权衡这两种视图，从两者中检索，并遵循它们的结构来恢复支持性关系或周围上下文。确定性校准首先丢弃冲突证据，然后使读者的答案基于检索到的轨迹。只有最终问答的读者才调用LLM。在长内存和长上下文问答基准测试中，Zero-Mem在消除内存操作中的LLM调用和LLM令牌消耗的同时，实现了具有竞争力的性能。在相同的最终问答读者和上下文预算下，相对于最快的对比基线，它将内存操作的时间成本降低了57.6%。消融研究支持了这两种视图及其查询依赖协调的贡献。总体而言，结果表明结构化智能体内存不必生成过去的中间表示。在同行评审后，代码和实现细节将在 https://github.com/TheMoon0815/Zero-mem 上提供。

## Abstract
LLM agents need memory to act consistently over long interactions, yet many systems use additional LLM calls to operate that memory. Generating intermediate records and mediating their retrieval adds recurring token and time costs, while omitted or merged details can obscure the original evidence. We ask whether structured memory access requires generation at all. Zero-Mem introduces \emph{zero-token memory operations}: no step outside final question answering invokes an LLM or consumes LLM input or output tokens; encoder computation is accounted for separately. Zero-Mem preserves original interaction traces as its source of record. It organizes the traces in two complementary ways. An entity--context graph exposes connections across interactions, while a temporal hierarchy preserves conversational locality and session state. For each query, Zero-Mem weighs the two views, retrieves from both, and follows their structure to recover supporting relations or surrounding context. Deterministic calibration first discards conflicting evidence and then keeps the reader's answer grounded in the retrieved traces. Only the final-QA reader invokes an LLM. Across long-memory and long-context question-answering benchmarks, Zero-Mem achieves competitive performance while eliminating LLM calls and LLM-token consumption from memory operations. With the same final-QA reader and context budget, it reduces memory-operation time cost by 57.6\% relative to the fastest compared baseline. Ablations support the contribution of the two views and their query-dependent coordination. Overall, the results show that structured agent memory need not generate an intermediate representation of the past. After peer review, the code and implementation details will be available at \textcolor{blue}{https://github.com/TheMoon0815/Zero-mem}.

## 2. 方法论：核心思想与技术细节

### 2.1 核心思想

Zero-Mem将记忆操作重构为**带来源追踪的交互轨迹上的结构化证据选择**。它保留原始轨迹作为记录来源，通过两种互补的非生成视图组织它们：

- **实体-上下文图**（Entity-Context Graph）：捕获跨交互的连接关系，用于关系型访问。
- **时间层次结构**（Temporal Hierarchy）：保留对话局部性和会话级状态。

两条视图最终都溯源到相同的带来源的原始单元，查询时通过轻量级画像协调两个视图的权重。

### 2.2 关键技术细节

**（1）保留来源的零令牌记忆基座**

- 使用非生成式命名实体识别（NER，如spaCy）检测实体，构建实体-上下文图：
  - 实体-上下文共现边权重：`w(di, e) = c(e, di) / Σ_{e'∈E(di)} c(e', di)`
  - 相邻上下文单元之间添加邻接边以保持局部连续性。
- 层次化轨迹单元：`T(H) = Uturn ∪ Uwindow ∪ Uepisode ∪ Ulocal`，分别对应对话轮次、窗口、事件片段和局部跨度，多粒度保留上下文。
- 索引信号：BM25（词汇统计）和BGE-M3（稠密嵌入）仅用于索引、播种和打分，不生成或改写记忆内容。

**（2）查询条件证据路由**

构建轻量级查询画像 `φ(q) = {subject, keywords, answer-type, temporal-cues, boundary}`，基于确定性的查询结构信号决定主视图权重 ρ：
- 关系型查询（relational）：图视图为主，权重 ρ；层次视图为次，权重 1−ρ。
- 局部型查询（local）：权重反转。

**（3）双视图证据检索**

- **图视图**：通过实体对齐、激活传播（式9）、个性化PageRank（式10）在图上分布证据，对上下文节点排序，最后用词法和短语匹配精化排名。
- **层次视图**：从粗到细检索：`Uepisode → Uwindow → Uturn → Ulocal`，评估语义相关性与结构兼容性（主题一致性、时间有效性、边界一致性、答案类型匹配等）。

**（4）双视图证据闭包**

- 对两视图得分做查询级归一化，按路由系数融合：
  `S_fuse(d) = ρ·S_primary(d) + (1−ρ)·S_secondary(d)`
- 融合后再补充图桥接证据和局部邻居：`C(q) = Dedup(M(q) ∪ Ng(M(q)) ∪ Nh(M(q)))`。

**（5）确定性证据校准**

- **证据级**：过滤违反来源或查询边界约束的候选，按主题、时间、答案类型兼容性排序。
- **答案级**：对初始答案进行支持性检查、类型与格式检查、列表修剪/归一化；标量答案仅在存在唯一类型兼容候选时才替换，否则保留原始答案。

**（6）唯一LLM调用点**

最终问答读取器（Reader）是唯一的LLM调用阶段，使用检索到的证据集 `R(q)` 生成答案。

## 6. 主要结论与发现

1. **性能具备竞争力**：
   - LoCoMo上，Zero-Mem在GPT-4o-mini下平均F1=59.15、BLEU-1=52.96，超过最强基线GAM达5.40/5.45点；在Qwen2.5-14B下平均F1=57.57、BLEU-1=51.41，所有问题类型均排名第一。
   - HotpotQA上，在所有读取器和上下文长度下均取得最高F1，448K最困难设置下平均超越最强基线5.52点。
   - 长上下文访问（LONG-LLM）或扁平相似检索（RAG）单纯使用不足以处理状态与边界敏感的回忆任务。

2. **效率提升显著**：
   - 记忆操作LLM调用和令牌消耗降为**零**；
   - 在相同最终QA读取器和上下文预算下，记忆操作时间成本比最快的效率基线（LightMem）降低**57.6%**（0.22秒/查询 vs 0.51秒/查询）；
   - 零令牌操作不意味着零计算（编码器推理、检索、确定性校准仍有开销），但确实避免了生成式管线的慢速步骤。

3. **双视图互补**：
   - 仅图视图：F1=62.50；仅层次视图：F1=54.88；全模型：F1=72.07——两者互补性显著，图连接跨文档信息，层次保留解释连接所需的局部上下文。

4. **证据闭包和校准均有增益**：去除证据闭包后F1下降4.17点；去除校准后下降1.94点。

5. **检索预算稳定性**：Top-1到Top-5提升明显，Top-10最优，更大预算表现平稳；Top-5（主实验设置）距Top-10仅差0.65 F1，同时保留更少候选。

## 7. 优点

1. **概念创新性强**：提出"零令牌内存操作"这一新运行范式，将记忆操作成本与最终推理成本彻底解耦，为智能体记忆系统提供了全新的设计维度。

2. **来源可溯源性**：所有检索单元保留原始文本+源标识符，证据可追溯至真实交互而非模型生成语句，从根本上解决了生成式记忆的"不可信压缩"问题。

3. **非生成的结构化设计**：实体提取用非生成NER（spaCy），图构建记录观测到的共现而非推断关系，层次划分沿用会话/时间边界；检索端用确定性算法（PageRank、BM25 + 稠密向量）——所有这些都不需要LLM参与。

4. **双视图互补机制**：关系视图+时间层次视图的协同设计兼顾了"实体关联"和"会话状态"两类不同的记忆需求，查询条件路由使二者按需协调，灵活性高。

5. **确定性校准保障可靠性**：证据级和答案级双重校准在不引入额外LLM调用的前提下过滤冲突证据、检查格式和类型，确保最终答案有据可依。

6. **实验验证全面**：覆盖长对话记忆与长上下文多跳推理两个互补基准，使用闭源与开源LLM交叉验证，跨多个检索预算和消融设置展示稳健性。

7. **应用价值明确**：57.6%的延迟降低和零记忆令牌消耗对于生产环境中的LLM智能体有直接吸引力，且性能不减反增。

## 8. 不足与局限

1. **对"零令牌"假设的边界依赖**：论文将编码器计算和最终QA推理单独核算，但编码器（BGE-M3、spaCy NER）本身也是计算成本，若在极端资源受限场景中，这部分成本不可忽视。

2. **生成式记忆的优势未充分对撞**：生成式摘要可以压缩和提炼高频/陈旧信息，而Zero-Mem始终保留原始轨迹，在历史无限增长时的存储成本和检索延迟可能随规模上升，长尾场景下的扩展性未充分讨论。

3. **基准覆盖有限**：未在真实的智能体交互环境（如带工具调用的多步骤任务、多智能体协作等）中评测；LoCoMo和HotpotQA均为问答类基准，对"行动一致性"类任务的支撑未验证。

4. **效率对比的完整度**：效率实验仅排除了3个代表基线，未覆盖所有内存基线（如CompassMem、Mem0等），读者难以全面比较Zero-Mem在所有方法中的效率定位。

5. **资源细节披露不足**：GPU数量、批次大小、内存占用、端到端总运行时间等未说明，可复现性有一定影响。

6. **统计稳健性**：未报告多次运行的方差或置信区间，单次运行的结果可能存在波动。

7. **手动/确定性信号依赖**：查询画像（subject、answer-type、temporal-cues等）和路由决策依赖确定性信号和元数据质量；在开放式、无明确实体和边界的查询上，性能表现未得到验证。
