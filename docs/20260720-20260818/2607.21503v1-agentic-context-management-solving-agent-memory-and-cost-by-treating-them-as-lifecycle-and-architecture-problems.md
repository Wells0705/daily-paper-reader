## 摘要
生产环境中的AI智能体失败往往不是因为推理能力不足，而是因为它们无法管理推理上下文中的内容：对话历史、大型提示、大型工具定义以及不断膨胀的工具输出。智能体淹没在自己不断累积的历史中，同时支付的令牌成本每轮都在增长，导致在对话内和跨对话中产生召回缺失。现有的应对方式将这一问题视为存储与检索问题。我们认为这种框架过于狭隘。主动管理智能体所持有的信息是一个生命周期，而不仅仅是存储：它涵盖了决定记住什么、提取并结构化信息、根据数据类型选择合适的存储、在保留溯源的情况下进行整合与遗忘、判断当前相关信息、预测下一步所需，以及在不丢失重要内容的情况下将上下文压缩到预算范围内。在严肃的生产环境中，这不仅仅针对单个用户，而是跨组织范围层级运作。我们将这一学科命名为“智能体上下文管理”（Agentic Context Management, ACM），并将其分解为五个原语：架构（architecting）、摄取（ingesting）、范围界定（scoping）、预判（anticipating）以及压缩与整合（compacting & consolidation）。随后我们进行经济性论证：朴素的上下文累积使令牌成本随对话长度呈二次方增长，粗糙的摘要以准确性悬崖为代价换取线性成本，只有经过验证的压缩才能在线性成本下保持保真度。我们描述了一个参考实现Maximem Synap，该实现将五个原语作为多租户服务落地，并在第6节详述的配置下，在LongMemEval上达到92%，在LoCoMo上达到93.2%。最后，我们指出了现有基准尚未覆盖的维度——延迟、令牌效率和上下文腐化抵抗能力，以及该范畴所指向的决策级和组织级上下文前沿。

## Abstract
Production AI agents' failures are less often due to an inability to reason well and more often because they cannot manage what is in their reasoning context: conversation histories, large prompts, large tool definitions, and ballooning tool outputs. Agents drown in their own accumulating history while paying a token cost that grows every turn, producing missing recalls within and across conversations. The incumbent response treats this as a storage-and-retrieval problem. We argue that framing is too narrow. Actively managing what an agent holds in mind is a lifecycle, not merely a store: it spans deciding what to remember, extracting and structuring it, choosing the right store per data type, consolidating and forgetting while preserving provenance, deciding what is relevant now, anticipating what is needed next, and compacting context to a budget without losing what matters. In serious production this operates not over a single user but across an organizational scope hierarchy. We name this discipline Agentic Context Management (ACM) and decompose it into five primitives: architecting, ingesting, scoping, anticipating, and compacting & consolidation. We then make the economic case: naive context accumulation grows token cost quadratically in conversation length, crude summarization buys linear cost at the price of an accuracy cliff, and only validated compaction achieves linear cost with preserved fidelity. We describe a reference implementation, Maximem Synap, that realizes the five primitives as a multi-tenant service and reports 92% on LongMemEval and 93.2% on LoCoMo under the configuration detailed in Section 6. We close with dimensions existing benchmarks do not yet capture, latency, token efficiency, and context-rot resistance, and the frontier of decision-level and organization-level context the category points toward.

  1. 刚说过的话中，哪些值得保留？
  2. 应该以什么结构保留？
  3. 当前这轮上下文中应该放入哪一小部分？
  4. 下一轮可能需要什么？
  5. 当相关上下文超过预算时该怎么办？
- **现实意义**：据 McKinsey 2025 年调查，多数企业正在尝试 AI 智能体，但只有约四分之一报告规模化成功，不到 10% 在单一业务职能中实现规模化。作者认为核心瓶颈正是上下文管理能力。

## 2. 方法论

### 2.1 核心思想：将记忆问题重构为生命周期与架构问题

论文提出 **智能体上下文管理（Agentic Context Management, ACM）** 这一学科，定义为"决定智能体应该在上下文中持有什么、何时持有、持有多久、以何种成本持有"的完整生命周期纪律。

### 2.2 五个原语（Primitives）

| 原语 | 内涵 |
|------|------|
| **架构（Architecting）** | 在存储任何记忆之前，为每个智能体生成量身定制的记忆架构：哪些类别重要、如何提取、存在哪里、保留多久、如何检索与压缩。强调架构本身是一等公民，而非固定通用模式 |
| **摄取（Ingesting）** | 将原始信号（对话轮次、多模态文档、工具调用及结果）转化为结构化、可检索的记忆。关键观察：检索质量受摄取质量约束（"用户提到某个套餐"永远无法检索出"用户4月3日从Starter升级到Pro"） |
| **范围界定（Scoping）** | 在摄取和检索时决定"哪部分已知信息与此相关、属于哪个范围"。采用层级隔离：用户（User）→ 客户（Customer）→ 客户平台方（Client），检索时由窄到宽（narrowest-first），严格隔离防止数据泄漏 |
| **预判（Anticipating）** | 类似计算机系统中的预取（prefetching）：观察智能体行为，在显式请求到来之前预取下一轮可能需要的上下文，将检索移出关键路径。论文报告的命中率超过 60% |
| **压缩与整合（Compacting & Consolidation）** | 当相关上下文超出模型可用预算时，进行**可验证的压缩**：检查关键信息是否可恢复，输出验证分数和压缩比，验证不通过时自动降档重试 |

### 2.3 经济性论证（关键公式）

- **朴素全量追加（full-append）**：每轮重发全部历史，第 k 轮输入约 k·t 个 token，累计输入量为：

  `C_append = Σ(k·t) = t·n(n+1)/2 ≈ (t/2)·n² = O(n²)`（二次方增长）

- **固定预算（bounded）**：每轮保持在 W token 内，累计为 `C_bounded = n·W = O(n)`（线性增长）
- **成本倍数**：`R(n) = C_append / C_bounded = t(n+1)/(2W)`，随对话长度线性增长
- **三种方案对比**：
  - 全量追加：保真度完整，但成本二次方，且长上下文出现"上下文腐化"（lost in the middle）
  - 粗糙摘要：线性成本，但存在准确性悬崖（引文案例：18,282 token 压缩到 122 token，准确率从 66.7% 跌至 57.1%，低于无上下文基线）
  - **经验证的压缩**：线性成本 + 保真度保持，是论文目标路径

### 2.4 检索充分性论证

- 提出不等式：`答案质量 ≤ min(提取质量, 检索质量, 推理充分性)`
- 关键论点：检索命中 ≠ 检索充分。多数基准只测"相关文档是否出现"，几乎不测"推理所需的全部材料是否出现"
- 论文进行了 5 个领域的检索动机研究（非严格基准），发现：向量检索在语义跨度大的场景胜出（如自然语言→代码，MRR 0.91 vs 0.29），关键词检索在实体明确的场景胜出（如科学问答 0.81 vs 0.61）；两者各有盲区，需要**混合（词法+语义+图）**检索

### 2.5 参考实现：Maximem Synap

多租户托管式上下文管理服务，架构包括：异步优先 SDK、五原语对应模块、多语言持久化存储（向量 ChromaDB、图 Neo4j、关系型 Postgres、对象存储、时序、Redis）。产品化集成简化为三调用模式：范围感知检索 → 验证压缩 → 异步摄取。

## 6. 主要结论与发现

1. **框架结论**：智能体上下文管理应被视为生命周期与架构问题（五原语：架构、摄取、范围界定、预判、压缩与整合），而非单纯的存储检索问题；一个系统需要在用户→客户→客户平台方的组织层级上运作。
2. **经济结论**：全量追加带来 O(n²) 成本；粗糙摘要以准确性悬崖换线性成本；只有**经验证的压缩**才能到达"线性成本 + 保持保真度"的高效前沿。
3. **检索结论**：不存在单一万能检索方法——需要词法 + 语义 + 图结构混合；检索命中不等于推理充分，行业需开发直接度量"充分性"的基准。
4. **实证结论**：参考实现 Maximem Synap 在 LongMemEval 获 92.0%、LoCoMo（类别 1–4）获 93.2%，且是用比最强竞品更小的回答模型（gpt-5-mini）取得的，表明增益来自上下文层而非模型层。
5. **方向结论**：现有基准未覆盖延迟、token 效率与上下文腐化抵抗，这些正是生产部署最看重的维度；未来前沿是决策级与组织级上下文管理（作者承认大多尚未解决）。

## 7. 优点

- **原创性重构**：将"记忆"问题重新定义为"上下文生命周期管理"，五原语分解清晰且有生产失败模式逐一对应（表 1 的 failure mode 映射非常扎实）
- **定量论证有力**：O(n²) vs O(n) 的数学推导简洁清晰，成本倍率公式附敏感度表；"准确性悬崖"有文献实证支撑
- **验证式压缩理念**：提出压缩必须携带"信息丢失检查 + 验证分数 + 自动重试"的质量契约，直接对标"自信的错答比不答更糟"这一生产痛点
- **透明性实践**：评测配置全量公开（数据集、模型、工具、运行标签）、逐类别报告弱项、明确声明竞品数据不具可比性——在自报分数的生态中属于高标准的诚实度
- **范围层级设计**：用户→客户→客户平台方的多租户隔离设计，兼顾组织上下文的网络效应与数据隔离安全性，超越了常见的单用户记忆工具
- **综合检索路线**：词法 + 向量 + 图的多通道混合，并指出向量检索在索引延迟上的显著代价（60–97 倍）
- **异步非阻塞设计**：摄取异步化与"读多写少"的权衡分析合理，且解释了会话内读己之写不因异步受损

## 8. 不足与局限

- **机制不透明**：参考实现的关键机制（架构生成、验证压缩算法、预判预测器）均为专有、未披露，第三方无法复现其内部工作原理，只能复现接口行为

- **消融缺失**：五原语各自的独立贡献未被量化；无法判断是哪一个原语贡献了 92% 的主要部分
- **预判环节证据薄弱**：60% 以上的命中率仅在文中一句带过，未说明评估方法、场景覆盖或误判代价
- **检索研究偏差风险**：无分块导致长文档仅嵌入头部、偏向向量一侧；单金标评分无法测多跳充分性（作者承认其局限，但这也意味着该研究只能视为动机参考，不能作为检索结论的严格证据）

- **竞品对比不可比**：表 3 明确为各厂商自我报告（自我声称），回答模型各不相同（Gemini-3 Pro / gpt-5 / gpt-4o 等），严格说不足以支撑"系统优于竞品"的结论——作者自己也作了限定
- **数据与隐私**：论文讨论了租户隔离策略，但未涉及合规细节（如 GDPR 删除义务、审计日志等），组织级共享的安全性验证缺实证
