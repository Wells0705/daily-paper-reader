## 摘要
近期研究赋予大语言模型（LLMs）作为多轮搜索智能体的能力，使其能够迭代检索并生成输出，直到解决复杂任务。然而，多轮搜索智能体的上下文冗长且复杂。例如，每一轮检索到的文档集合不可避免地会引入干扰LLMs的无关信息，即所谓的“上下文干扰”，这可能阻碍搜索智能体的可靠性和效率。因此，我们对多轮搜索智能体中的上下文干扰进行了系统性研究，重点探讨：i）搜索智能体上下文的哪些部分会导致上下文干扰，ii）如何优化搜索智能体的上下文以缓解干扰，以及iii）将上下文优化纳入搜索智能体训练是否能带来进一步改进。我们发现干扰主要源于最新检索到的文档。基于这些发现，我们引入了一种基于蒸馏的上下文优化器，以动态缓解多轮搜索智能体的上下文干扰。最后，我们验证了将上下文优化纳入搜索智能体的强化学习训练流程中，可以显著提升其可靠性和效率。本研究强调了缓解搜索智能体上下文干扰的重要性，为AI智能体提出了一种“先优化上下文，再生成”的新范式。

## Abstract
Recent research empowers Large Language Models (LLMs) as multi-turn search agents to iteratively retrieve and generate outputs until complex tasks are solved. However, the contexts of multi-turn search agents are lengthy and complex. For example, the retrieved set of documents in each turn would inevitably introduce irrelevant information that distracts LLMs, referring to \textit{context interference}, potentially hindering the reliability and efficiency of search agents. Therefore, we conduct a systematic study on context interference in multi-turn search agents, focusing on investigating i) which parts of the context of search agents will contribute to the context interference, ii) how to refine the contexts of search agents to mitigate the interference, and iii) can incorporating context refinement into search agent training yield further improvements. We reveal that interference primarily arises from the latest retrieved documents. Based on the explored findings, we then introduce a distill-based context refiner to dynamically mitigate context interference for multi-turn search agents. Finally, we validate that incorporating context refinement into RL training pipelines of search agents can significantly enhance both reliability and efficiency. This study highlights the importance of mitigating context interference of search agents, inspiring a novel paradigm of ``refine context and then generate'' for AI agents.

### 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：大语言模型（LLMs）已被广泛用于构建多轮搜索智能体（multi-turn search agents），此类智能体通过迭代执行"思考→检索→生成"的循环来求解复杂知识密集型任务。
- **核心问题**：多轮搜索智能体的上下文随时间推移变得冗长复杂，包含历史问题、多轮搜索查询、检索文档和推理步骤等。每一轮检索器返回的 Top-K 文档中不可避免地混入噪声或无关信息，这些无关内容会"干扰" LLM 的注意力与判断，使模型无法在包含正确答案的文档中正确提取和利用信息。本文将该现象称为**上下文干扰（Context Interference）**。
- **关键现象**：论文用三个指标揭示了干扰的影响——"recall rate"（检索文档包含正确答案的比例）与"recall accuracy"（检索到正确答案后能正确作答的比例）之间存在显著差距，说明智能体**"能检索到但答不对"**，这正是上下文干扰的直接体现。
- **研究意义**：上下文干扰不仅降低搜索智能体的可靠性，还因其导致额外检索和推理而损害效率。该问题在之前的 RAG 和对话系统研究中未得到充分重视，本文是首次对多轮搜索智能体场景下的上下文干扰进行系统性研究。

### 2. 方法论：核心思想、技术细节与算法流程

#### 2.1 整体框架

论文围绕三个研究问题（RQ）展开：
- **RQ i**：上下文中的哪些部分会导致干扰？
- **RQ ii**：如何精炼上下文以缓解干扰？
- **RQ iii**：将上下文精炼融入强化学习训练能否进一步提升性能？

#### 2.2 干扰来源分析（RQ i）

- 设计了基于 IRCoT 的三种掩码变体来定位干扰来源：
  - **IRCoT-o**：移除历史轮次（第 i 轮之前）的检索文档，只保留最新观测。
  - **IRCoT-oq**：进一步移除历史搜索查询。
  - **IRCoT-oqp**：只保留最新的思考步骤、搜索查询和观测。
- **发现**：移除历史文档和查询可获得小幅提升；但"recall rate"与"recall accuracy"之间的显著差距仍然存在，表明**干扰主要来自最新一轮检索到的文档**，而非历史上下文。

#### 2.3 基于蒸馏的上下文精炼器（RQ ii）

- **核心思想**：训练一个小型 LLM（如 Qwen2.5-3b/7b）作为"上下文精炼器"（Context Refiner），使其能够从最新检索到的 Top-K 文档中提取与搜索查询最相关的关键信息，过滤噪声。
- **蒸馏数据构造流程**：
  1. 使用高级教师模型（GPT-4）在 IRCoT 流程中推理每个查询；
  2. 每轮检索后，指示教师模型仅抽取与当前查询 `q_{i-1}` 最相关的文档片段；
  3. 保留最终答案正确的轨迹；
  4. 用 entailment 模型验证精炼后的文本未引入额外知识；
  5. 整理为上下文精炼数据集 `D_c = {d̃_i, d_i, q_i}`。
- **训练目标**：通过监督微调（SFT）让基础模型学会生成精炼文本：
  - `π* = arg min_π L_SFT(π)`
  - `L_SFT(π) = −(1/M) Σ log M_π(d̃_i | d_i, q_i)`
- **效果**：精炼后的文档 `d̃_i` 替换 `d_i` 作为观测，显著降低上下文长度与干扰。

#### 2.4 上下文精炼强化学习（CRRL，RQ iii）

- **核心思想**：在搜索智能体的 GRPO 强化学习训练过程中，利用上下文精炼器动态压缩每轮检索到的文档，保证 rollout 轨迹更干净、质量更高。
- **流程**：rollout 时的上下文为 `s_i = [x, p_{0:i-1}, q_{i-1}, d̃_i]`，其中 `d̃_i = F(d_i)`，智能体只基于精炼后的观测生成思考和查询。
- **优化目标**：基于 GRPO 的损失函数，包含组内相对优势（group-relative advantage）计算、PPO 式裁剪（clip）和 KL 正则化：
  - `L_CRRL(M_π) = −E[G_π − β KL]`
  - 其中 `G_π` 为组内多轨迹归一化回报，`A_j = (r_j − μ_j)/σ_j` 为优势估计。

### 3. 实验设计：数据集、基准与对比方法

- **数据集（7 个闭卷 QA 基准）**：
  - **单跳问答**：Natural Questions (NQ)、TriviaQA、PopQA。
  - **多跳问答**：HotpotQA、2WikiMultiHopQA、MuSiQue、Bamboogle。
  - 问题规模从 125 到 14267 条不等。
- **基础模型与检索配置**：
  - 基础 LLM：Qwen2.5-7b-Instruct 和 Qwen2.5-3b-Instruct；
  - 检索器：E5 嵌入模型 + 2018 Wikipedia dump；每轮返回 Top-3 文档。
- **评估指标**：
  - **可靠性**：Exact Match (EM)。
  - **效率**：平均检索次数 (ART)、平均上下文长度 (Len.)、平均推理时间 (AIT)。
- **对比方法**：
  - 检索无关基线：Direct、CoT（思维链）。
  - 检索增强基线：IRCoT 及其变体（IRCoT-o / IRCoT-oq / IRCoT-oqp）。
  - 上下文精炼基线：GPT-Compress（GPT-4 压缩全文）、GPT-Refine（GPT-4 动态精炼最新文档）、Self-Refine（基础模型自精炼）、Ranking 阈值过滤（附录）。

- **训练数据**：从 NQ 和 HotpotQA 训练集中采样 40k 条合并为 `D_t`，与蒸馏数据 `D_d` 不相交，用于评估域内与跨域泛化。

### 6. 主要结论与发现

1. **干扰来源定位**：多轮搜索智能体的上下文干扰主要来自**最新一轮检索到的文档**，而非历史轮次的文档或查询；历史文档和查询只产生轻微干扰。
2. **上下文精炼器有效性**：基于蒸馏训练得到的上下文精炼器能显著缓解干扰，将 EM 平均提升约 5 个百分点，并大幅降低平均检索次数和上下文长度，效果接近使用 GPT-4 直接精炼的教师模型。
3. **训练阶段融入精炼的价值**：将上下文精炼器融入 GRPO 训练（CRRL）后，智能体在可靠性（EM）与效率（ART、Len.、AIT）两方面均优于现有 RL 基线（Search-GRPO、Search-o1），且这一优势在 3B 和 7B 模型上都成立。
4. **范式启示**：研究为 AI 智能体提出了一种"**先精炼上下文，再生成**"（refine context and then generate）的新设计范式。

### 7. 优点

- **问题切入精准**：针对多轮搜索智能体独有的"上下文过长 + 噪声累积"痛点，首次系统性地分析并量化了上下文干扰的来源与影响。
- **方法设计巧妙**：
  - 用掩码变体优雅地定位干扰源；
  - 用 GPT-4 蒸馏 + entailment 验证构造高质量精炼数据，成本可控且可复现；

- **实验全面**：覆盖 7 个 VQA 数据集、2 种模型规模、多类基线（提示式、压缩式、自精炼式、RL式），并同时评测准确率与效率（EM/ART/Len./AIT）。

### 8. 不足与局限

- **任务覆盖有限**：论文关注搜索智能体场景，但上下文干扰同样存在于工具调用、代码生成、多智能体协作等领域，其干扰机制与缓解策略可能不同，结论的外部效度有限。
- **精炼器为外部模块**：上下文精炼器是独立于智能体之外的辅助模块，没有完全内化到智能体本身的参数中，增加了推理时的额外开销与架构复杂度。
- **数据污染风险关注不足**：论文简单讨论了知识库与内部知识的时间一致性，但对测试集与预训练语料的潜在重叠未做深入检测。

- **基准与泛化局限**：全部实验基于英文维基百科语料和 QA 任务，未覆盖多语言、开放域对话、工具使用等更广泛的搜索智能体业务形态。
- **缺少更深层分析**：未分析"精炼"过程中的信息损失问题——虽然精炼提取了关键信息，但可能丢失上下文中的微妙线索（如否定句、条件句），在复杂推理场景下可能造成新型偏差。
