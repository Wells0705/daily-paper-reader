## 摘要
长时间运行的助手和智能体所消费的交互流最终会超出上下文范围。现有的上下文保留、摘要和检索方法虽能保留对所选历史的访问，但在工作上下文变化时，并未提供覆盖完整生命周期的持久状态。我们将这一缺失的推理能力定义为“上下文更替下的状态连续性”：通过一个固定容量的记忆状态向前推进计算，该状态的寿命独立于当前活动上下文。我们提出了一种内在记忆方法——**LiveMem**，它为预训练的全注意力LLM增加了一个记忆状态，在完整生命周期内保留历史信息，同时主注意力路径维持一个有界的KV窗口。上下文更替与记忆状态维护、面向记忆的后训练以及状态感知的服务共同使得该记忆状态在其源令牌被释放后仍能承担负载。我们的实验表明，LiveMem在评估系统及其他内在记忆方法中取得了领先的整体性能。在LongMemEval上的实验显示，即使支持证据已从当前上下文中移除，LiveMem仍能基于记忆状态回答问题，并且证据距离分析表明有用信息在活动窗口之外依然持续存在。因此，LiveMem将状态连续性确立为持续LLM推理的一种独特且互补的抽象。

## Abstract
Long-running assistants and agents consume interaction streams that eventually outgrow the context. Existing context retention, summarization, and retrieval preserve access to selected history, but do not provide a persistent state over the full lifecycle when working context changes. We formulate this missing inference capability as \emph{state continuity under context turnover}: carrying computation forward through a fixed-capacity memory state whose lifetime is independent of the active context. We introduce an intrinsic memory method, \textbf{LiveMem}, which augments a pretrained full-attention LLM with a memory state that preserves the historical information over the whole lifecycle while the main attention path retains a bounded KV window. Context turnover and memory state maintaining, memory-oriented post-training, and state-aware serving jointly make this memory state load bearing after its originating tokens are released. Our experiments show that LiveMem achieves leading overall performance among evaluated systems and other intrinsic memory methods. Experiments on LongMemEval show that LiveMem is able to answer the question based on the memory state, even when the supporting evidence has been removed from the current context, and evidence-distance analysis shows that useful information persists beyond the active window. LiveMem thus establishes state continuity as a distinct and complementary abstraction for continual LLM inference.

### 2. 方法论：核心思想与关键技术

**核心思想**：在预训练全注意力 LLM 上增加并行的 GDN2 递归记忆分支，注意力主路径维持有界 KV 窗口，记忆分支维持固定容量的记忆状态；通过上下文更替、记忆导向后训练和状态感知服务三者结合，使记忆状态在源 token 被释放后仍承担实际功能。

**关键架构**：
- 在每个解码层，注意力输出 `a_t` 与 GDN2 分支输出 `r_t` 直接相加：`o_t = a_t + r_t`
- 记忆分支使用 Gated DeltaNet-2，支持学习型遗忘（decay）、擦除（erase）和写入门控
- 状态更新公式：`S_t = Diag(exp(g_t)) · S_{t-1} + k_t (w_t ⊙ v_t − S^T_t (b_t ⊙ k_t))^T`
- 分支的 q/k/v 初始化自注意力主干，输出投影零初始化（初始等价原模型）

**上下文更替机制**：
- 系统提示保留为注意力锚点；其他内容以 chunk 为单位 FIFO 淘汰
- 淘汰只发生在 chunk 边界，且仅作用于注意力路径；记忆分支扫描完整序列
- 训练与推理使用相同更替策略，保证一致性

**后训练方案**（记忆导向）：
- **SFT 阶段 1**（激活记忆分支）：在长文本数据上训练 100 步
- **SFT 阶段 2**（建立记忆保持）：在重平衡 QA/分类/多查询混合数据上训练 500 步
- **RL 阶段**：使用 GRPO（融合 DAPO 策略：clip-higher、token 级损失、动态采样、去 KL），奖励为多问题准确率+格式惩罚，负例通过 LLM judge 兜底

### 6. 主要结论与发现

1. **整体性能领先**：LiveMem-RL 在总体表现上显著超越所有基线（0.519 vs 次优 0.458），是唯一在各任务套件上表现均衡的系统。
2. **记忆状态真正"负载"**：LongMemEval 上，证据完全被逐出窗口时，LiveMem 准确率达 16.5%，远超 Qwen3-4B（3.1%）和 δ-Mem（3.6%），证明记忆状态在证据离开注意力后仍携带有效信息。
3. **证据距离有一定影响但可保持**：随着被驱逐证据距当前窗口越来越远，准确率虽轻微下降但保持稳定性，说明 GDN2 的遗忘机制在长距离下仍能保留关键信息。
4. **多查询任务优势显著**：在 2Wiki-MQ / Hotpot-MQ / MuSiQue-MQ 上，基线方法大幅下降，LiveMem 仍保持领先，表明跨上下文多逻辑链推理是状态连续性的突出优势。
5. **检索记忆和参数记忆各有擅长领域**（RAG 在对话、Context2LoRA 在 TTL），但任务专用性强，过拟合特定套件，LiveMem 是唯一全面均衡的方案。
6. **训练策略启示**：长文本预热 → 重平衡混合数据的两阶段课程有效；全参数训练记忆分支优于 LoRA；增加主路径 LoRA 无显著增益。

### 7. 优点

- **问题定义清晰**：将"状态连续性"与"历史访问""短时精确访问"区分开，为持续推理提供了独立的概念框架。
- **方案完整闭环**：不只加一个记忆模块，而是从架构设计、上下文更替、后训练到 serving 端到端统一设计，训练/推理保持一致性。
- **架构设计精巧**：零初始化输出投影保证初始不干扰原模型；动态注意力掩码实现训练时上下文更替模拟；GDN2 的忘却+擦除机制适应持续在线更新。
- **验证方法论扎实**：不仅报告总准率，还专门设计"证据驱逐"分析（完全移出/部分移出/距离控制），直接回答"记忆状态是否真正有效"这一核心问题。
- **SFT+RL 双层后训练**：先用长文本数据激活记忆分支，再用 RL 强化记忆利用率，逻辑合理。
- **诚实报告缺陷**：明确承认记忆是有损压缩，不适用于 NIAH 精确回忆任务，给出适用边界。

### 8. 不足与局限

- **实验规模局限**：仅使用 Qwen3-4B 一个骨干模型，结论在更大模型或其他架构上的泛化性未验证。
- **NIAH 失败是硬性短板**：在有界上下文中无法恢复任意 token 级"针"，说明当前记忆状态不具备精确回忆能力，对有精确事实检索需求的应用需要额外配检索系统。
- **位置编码限制**：使用 RoPE（最大 262k），未真正实现"无限上下文"，需要借助 NoPE 或 KDA 类架构来解除该上限。
- **对比公平性风险**：Context2LoRA 在 TTL 场景上按其原始假设将文本-标签对直接作为 LoRA 训练数据，可能对其有利；RAG 在 MQ 任务上的缺失也减少了可对比维度。
- **训练复杂度较高**：记忆状态需 FP32、两阶段 SFT + 多节点 RL，工程成本较高，部署和训练的实用性尚需更大规模验证。
- **记忆质量未与上游效果关联分析**：未分析不同 GDN2 初始化和超参选择对记忆容量的影响细节。
- **评估使用 2026 年参考的时间设定**（如 Qwen3.6-35B judge），外部复现时相关模型版本可能已变化。
