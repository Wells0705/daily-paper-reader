## 摘要
基于大型语言模型（LLM）的搜索智能体通过与外部环境的多步交互来回答问题。然而，向LLM提供完整的执行轨迹会导致上下文无限增长并引入噪声。现有压缩方法以牺牲重要细节为代价来减少上下文，并且常常在不修复由错误事实推导出的下游推理的情况下替换错误事实。为解决这一问题，我们提出ReTree，一种用于搜索智能体的自纠正树状结构记忆机制。ReTree在保留来源链接证据的同时，构建有界的逐步推理上下文。它将搜索建模为证据树，其节点存储有界摘要、证据和修订历史。当新检索到的证据与较早的声明冲突时，ReTree回溯到引入该声明的节点，替换过时证据，重新生成摘要，修剪受影响的枝干，并恢复搜索。基于来源的证据溯源支持可靠的冲突定位，并确保最终声明可追溯至检索到的段落。在四个公开的问答和搜索基准上的实验表明，ReTree始终优于完整轨迹ReAct，将答案准确率最高提升25.6个百分点（pp）；完整轨迹ReAct的平均最大每步推理上下文是ReTree的$1.27$--$1.51$倍。这些结果确立了ReTree作为长时程搜索中有效的自纠正记忆抽象。

## Abstract
Large language model (LLM)-based search agents answer questions through multi-step interactions with external environments. However, providing complete execution trajectories to the LLM causes unbounded context growth and introduces noise. Existing compression methods reduce context at the cost of important details and often replace erroneous facts without repairing downstream reasoning derived from them. To address this problem, we propose ReTree, a self-correcting tree-structured memory mechanism for search agents. ReTree constructs a bounded per-step reasoning context while preserving source-linked evidence. It models search as an evidence tree whose nodes store bounded summaries, evidence, and revision histories. When newly retrieved evidence contradicts an earlier claim, ReTree traces back to the node where the claim was introduced, replaces outdated evidence, regenerates summaries, prunes affected branches, and resumes search. Source-grounded evidence provenance supports reliable conflict localization and keeps final claims traceable to retrieved passages. Experiments on four public question-answering and search benchmarks show that ReTree consistently outperforms Full-Trajectory ReAct, improving answer accuracy by up to 25.6 percentage points (pp); the average maximum per-step reasoning context of Full-Trajectory ReAct is $1.27$--$1.51\times$ that of ReTree. These results establish ReTree as an effective self-correcting memory abstraction for long-horizon search.

## 1. 论文的核心问题与整体含义

- **背景**：基于大语言模型（LLM）的搜索智能体通过与外部环境（如搜索引擎）的多步交互来回答复杂问题。然而，将完整执行轨迹直接输入 LLM 会导致上下文随搜索步数无限增长，同时累积无关或过时信息带来的噪声。
- **现有方法的不足**：
  - 轨迹压缩（如摘要、报告）虽能限制上下文长度，但会丢失事实级细节，尤其是“哪条证据支持哪个结论”的溯源关系。
  - 当检索到与早期前提矛盾的新证据时，简单替换错误事实并不能自动修复基于该事实推导出的下游推理，从而产生错误级联。
- **ReTree 的定位**：提出一种自纠正的树状结构工作记忆，用于长时程搜索。它在保持每步推理上下文有界的同时，保留证据到来源的可追溯性，并通过“定位引入节点 → 替换证据 → 重新生成摘要 → 修剪依赖后代”的方式实现依赖一致的修订。
- **整体含义**：搜索智能体的记忆不应只是“更短的转录”，而应是一个可编辑、可追溯、可修复依赖关系的状态表示，这是提升长时程搜索可靠性的关键。

## 2. 论文提出的方法论

- **核心思想**：将搜索过程建模为“证据树”（evidence tree），树中的边表示“子搜索状态由父节点的活动证据推导而来”。每个节点保存有界摘要、本地证据、修订历史与父指针。
- **证据树状态**：
  - 节点表示为 \( n = (s_n, E_n, H_n, p_n) \)：
    - \( s_n \)：最多 140 词的紧凑任务状态摘要；
    - \( E_n \)：该节点本地引入的原子证据（事实 + 来源 URL + 稳定标识符）；
    - \( H_n \)：修订历史；
    - \( p_n \)：父节点指针。
  - 节点可用的累积证据为根到该节点路径上所有证据的并集：\( A(n) = \bigcup_{v \in path(r,n)} E_v \)。
- **有界上下文构造**：
  - 策略每步看到的上下文为 \( C_k(M_t, q) = s_{n_t} \parallel \text{TopK}_k(A(n_t), q \parallel s_{n_t}) \)，其中 \( k=5 \)，基于词汇相关度选择。
  - 摘要和少量证据使每步推理上下文复杂度为 \( O(1) \)，与轨迹长度无关；外部存储仍随证据数量增长。
- **扩展与来源绑定**：
  - 每次检索最多返回 5 个段落，提取器生成至多 6 条问题相关的原子事实，并按段落索引绑定来源（而非让模型生成 URL，避免不可验证引用）。
  - 若新事实与当前路径兼容，则创建子节点，并更新摘要。
- **冲突触发回溯**：
  - 先通过“冲突提议”判断新事实是否与已有事实在**同一实体、属性、范围和时间内给出不相容的值**；若不是，则作为候选扩展树。
  - 二次“修订确认”结合分支摘要、目标事实历史，减少重复反转和歧义导致的误修。
  - 确认冲突后：
    1. 找到引入被反驳事实的节点 \( \iota(j) \)；
    2. 在节点内替换事实文本和来源，并在 \( H \) 中追加修订记录；
    3. 仅基于修正后的累积证据重新生成该节点摘要；
    4. 删除该节点所有后代（硬剪枝）；
    5. 搜索从修复后的节点继续。
  - 形式化依赖一致性：若新证据将 \( e_j \) 修正为 \( e'_j \)，则所有依赖 \( e_j \) 的状态必须被失效或在新证据下重新生成，即 \( Dep_{t-1}(j) \subseteq I_t \cup G_t(e'_j) \)。
- **算法流程**（Algorithm 1）：
  - 初始化根节点；循环：构建上下文 → 策略决定搜索或停止 → 检索并提取证据 → 检测冲突 → 若确认则回溯修复，否则扩展子节点；达到步数或满足停止条件后生成带引用的答案。
- **声明级溯源**：
  - 最终生成器将答案拆分为原子声明，每个声明关联证据标识符，再通过运行级映射解析到当前证据文本和 URL，并可进一步映射到原始检索段落；最后用 NLI 判断段落是否蕴含声明。

## 3. 实验设计

- **数据集**：
  - Bamboogle（125 问，全量）
  - HotpotQA（600 问，固定子集）
  - 2WikiMultiHopQA（600 问，固定子集）
  - FRAMES（824 问，全量）
  - 合计 2,149 个问题，覆盖多跳组合推理、显式推理路径和真实事实查找等场景。
- **对比方法**：
  - **Full-Trajectory ReAct**：标准 ReAct，保留完整未压缩观察轨迹（无界上下文）。
  - **FlatUpdate**：与 ReTree 共享同样的摘要和 TopK 证据预算，但证据存储在扁平列表中，冲突时只替换事实，不定位引入节点、不重建依赖摘要、不剪枝（隔离“依赖结构修订”的贡献）。
  - **ReportMemory**：将检索结果折叠为单一演进报告（≤200 词）+ 无序 URL 集合，代表纯摘要/报告式压缩方法。
- **评估指标**：
  - 答案质量：GPT-5 判断准确率（judge accuracy）与归一化精确匹配（EM）；
  - 溯源质量：引用精度（CitePrec）、引用召回（CiteRec）、CiteF1、未引用率（Uncited），基于 NLI 的段落蕴含验证（仅在 FRAMES 600 问子集上做诊断）；
  - 上下文与计算：平均最大每步策略上下文（字符数）、总模型调用数、token 使用量。

## 6. 论文的主要结论与发现

- **答案质量提升**：
  - ReTree 在所有 4 个数据集上均优于 Full-Trajectory ReAct，判断准确率提升幅度为 8.3–25.6 个百分点；
  - 整体池化结果：准确率 44.0% vs Full ReAct 30.1%，EM 28.0% vs 20.6%。
  - 相比 FlatUpdate，ReTree 在每个数据集上高出 2.2–4.7 pp；相比 ReportMemory，除 2Wiki 外高出 1.7–7.2 pp（整体高出 3.0 pp）。
- **上下文效率**：
  - Full-Trajectory ReAct 的平均最大每步上下文是 ReTree 的 1.27–1.51 倍；ReportMemory 上下文最小，但准确率显著低于 ReTree，说明“仅压缩不够”。
  - ReTree 在保留有界上下文的同时，通过结构化修复保持了更高的答案质量。
- **溯源质量**：
  - 在 FRAMES 600 问诊断中，ReTree 的 CitePrec/CiteRec 最高（44.5/41.3），显著优于 Full ReAct（37.7/27.1）和 ReportMemory（16.8/21.4）；
  - ReportMemory 的未引用率最低（5.9%），但其引用段落更可能不支持对应声明，说明报告式压缩损害了归因保真度。
- **实际修复触发**：自然检索中 9.6%–17.5% 的 ReTree 运行触发了回溯，证明冲突驱动修复在真实搜索中是常见需求。

## 7. 优点

- **方法创新**：将真值维护系统（TMS）的依赖导向回溯思想引入 LLM 搜索智能体记忆，把“错误级联”形式化为结构化的状态修复问题，概念清晰且有理论支撑。
- **工程精巧性**：
  - 用稳定证据标识符 + 来源 URL 绑定，避免模型捏造 URL；
  - 二次冲突确认机制降低修复振荡；
  - 每步上下文严格有界，并给出形式化依赖一致性定义。
- **实验对照设计**：FlatUpdate 与 ReportMemory 分别隔离“结构修复”和“压缩策略”的影响，使结论更有说服力。
- **真实的评估设置**：使用实时网络搜索，而非静态检索库，更贴近实际应用。
- **归因评估可靠**：用 NLI 将声明验证到原始段落而非模型自报引用，提高了评价的可信度。

## 8. 不足与局限

- **硬剪枝的过度失效**：当前以“祖先 – 后代”关系作为依赖的保守代理，会删除可能实际上独立的后续证据，导致过度回溯和冗余检索。
- **冲突检测准确率是瓶颈**：假阴性会保留污染证据，假阳性会误剪有用状态；同范围规则与历史确认只能缓解，不能消除。
- **计算开销增加**：相比 FlatUpdate，ReTree 多使用 7–11% 的模型调用和 10–13% 的 token，主要来自冲突确认、摘要重建和恢复搜索。
- **外部存储持续增长**：上下文有界不等于总内存有界，极长时程下线性证据选择和树遍历会变慢。
- **泛化性验证不足**：
  - 仅使用 Qwen3-8B，未测试其他模型；
  - 未报告多次运行的标准差，统计可靠性有限；
  - 属性诊断仅覆盖 FRAMES 子集，其他基准缺乏溯源评估。
- **实际可用性局限**：未报告端到端延迟，且依赖线上搜索 API 和 GPT-5 评估，复现成本较高。
- **范围限定**：ReTree 是面向单次搜索任务的工作记忆，不是通用长期记忆系统；对需要无条件回忆所有历史信息的任务不适用。
