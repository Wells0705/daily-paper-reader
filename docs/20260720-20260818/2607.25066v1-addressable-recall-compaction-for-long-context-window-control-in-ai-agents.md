## 摘要
长时程LLM代理会积累推理轨迹、操作和工具观察结果，最终可能超出模型的固定上下文窗口。现有的压缩方法通过丢弃、总结或检索早期信息来解决此限制，但可能移除任务关键细节或无法可靠恢复。我们提出ARC（可寻址召回压缩），一种将存档存储与活动上下文呈现分离的上下文管理框架。ARC以仅追加、ID可寻址的日志存储工具观察结果，并在需要压缩时用紧凑引用替换较旧的观察结果。代理随后可以使用这些标识符请求存储的内容，而无需重新执行相应工具或仅依赖基于相似性的检索。我们使用具有16k上下文窗口的Qwen3-8B和具有32k上下文窗口的Qwen3-32B评估ARC。在“大海捞针”评估中，ARC的平均精确答案准确率为99.40%，而我们的评估中最佳基线为88.12%。在我们的硬件成本模型下，ARC还减少了估计的服务时间和HBM流量。在LongBench-v2 Hard子集上，ARC的平均准确率为29.97%，而最佳基线为28.25%。这些结果表明，显式的基于地址的召回可以在测试设置下相对于所评估的上下文管理基线提高信息保留和服务效率。

## Abstract
Long-horizon LLM agents accumulate reasoning traces, actions, and tool observations that can eventually exceed a model's fixed context window. Existing compaction methods address this limitation by discarding, summarizing, or retrieving earlier information, but they may remove task-critical details or fail to recover them reliably. We propose ARC (Addressable Recall Compaction), a context-management framework that separates archival storage from active-context presentation. ARC stores tool observations in an append-only, ID-addressable log and replaces older observations with compact citations when compaction is required. The agent can subsequently use these identifiers to request stored content without re-executing the corresponding tools or depending solely on similarity-based retrieval. We evaluate ARC using Qwen3-8B with a 16k context window and Qwen3-32B with a 32k context window. On the Needle-in-a-Haystack evaluation, ARC achieves an average exact-answer accuracy of 99.40%, compared with 88.12% for the best-performing baseline in our evaluation. ARC also reduces estimated serving time and HBM traffic under our hardware-cost model. On the LongBench-v2 Hard subset, ARC obtains an average accuracy of 29.97%, compared with 28.25% for the best-performing baseline. These results indicate that explicit, address-based recall can improve information retention and serving efficiency relative to the evaluated context-management baselines under the tested settings.

### 1. 核心问题与整体含义（研究动机和背景）

- 长期运行的 LLM 智能体（Agent）在执行多轮任务时，会不断累积推理轨迹、动作记录和工具观测结果。由于模型是无状态的，这些累积的转录（Transcript）被当作唯一的“工作记忆”，每次调用都要整体输入模型。
- 这导致一个不可避免的瓶颈：**上下文窗口有硬性上限**。当转录长度超过上限时，模型调用直接失败，智能体瘫痪。对长期规划、复杂软件工程、开放式网页浏览等任务而言，溢出只是时间问题。
- 现有主流压缩/上下文管理方法大致分四类：朴素截断（Naive Truncation）、层次摘要（Hierarchical Summarization）、状态折叠（State Folding）、检索增强生成（RAG）。它们的共同缺陷是**有损**：一旦历史被丢弃、改写或向量化，任务关键细节（变量名、错误串、用户约束）可能永远无法恢复，或只能靠不可靠的相似性检索。
- 论文的核心主张是：压缩不必然是“有损的”。通过将“保留什么”和“当前向模型展示什么”两个决策解耦，可以让压缩变得“可逆”，同时维持活动上下文的有界性。这为长时程智能体上下文管理提供了新的设计思路。

### 2. 提出的方法论：ARC（Addressable Recall Compaction）

#### 核心思想
- **分离归档存储与活动上下文呈现**：ARC 维护一个**只追加（append-only）的地址化存储**（ObsStore），保存所有工具观测的逐字原文；同时维护一个**有界大小的活动视图**，用紧凑的引用（Citation）替代旧内容。
- 每次压缩只改变“模型能看到的”，不改变“系统保留的”；任何被移出活动视图的观测都留下一个显式、可解引用的指针，恢复是“智能体的主动决策”，而非检索器的概率命中。

#### 关键技术细节
- **观测存储与 ID**：每个动作 A 产生观测 O 后，立即计算稳定 ID：
  `id = SHA1(signature(A) || 0x1F || O)`，取前 8 个十六进制字符作可见 ID，碰撞时按 4 字符递增扩展。ObsStore 记录完整内容、命令签名、头/尾预览、长度元数据、返回码、创建步骤等。该存储**只追加、不删除**。
- **压缩例程**：
  - 压缩是确定性的，不调用 LLM，因此无额外推理延迟。
  - 截断较旧的思维链；短观测（长度低于阈值 ρ）保持逐字保留；长观测替换为引用节（`§id`），引用节包含头尾预览、元数据和 `_recall §id` 提示。
  - 维护“已引用集合”（Cited），保证已作召回句柄的 ID 不会被后续压缩重命名或重新摘要。
  - 若摘要仍超出预算 M，将已引用条目从完整引用节折叠为裸 `§id`。
- **召回动作**：`_recall §id` 由框架拦截，直接从 ObsStore 注入原文；无效 ID 返回最近匹配建议。为防活动视图再次膨胀，设置每步召回上限 r（默认 2）、总物化召回预算和单次召回最大长度；超预算时按 LRU 将已展开内容逐出回引用节。轻量版 `_recall_meta §id` 仅恢复元数据。
- **触发机制**：支持主动（预估长度后提前压缩）和被动（溢出错误后压缩）两种模式；实验采用被动模式并固定调用索引以隔离随机溢出时机的影响。
- **形式化保证**：论文给出非正式定理和附录中的完整证明，核心保证包括：
  - 活动视图每轮不超过 K ≤ L，K 与轮次数无关；
  - 每个有效 ID 对应的观测可从外部存储精确重建（长观测按 ≤q token 的非重叠分块返回），无需重执行原动作；
  - 这种设计接近信息论下界：支持任意历史精确恢复且活动状态有界，外部存储最坏情况下必须线性增长，ARC 的负载增长与下界首阶一致。

### 3. 实验设计

#### 模型配置
- Qwen3-8B（16k 上下文窗口）与 Qwen3-32B（32k 上下文窗口），均使用 vLLM 服务，4k 完成长度上限。
- 溢出由 vLLM 上下文错误触发压缩路径。

#### 基准与指标
- **Needle-in-a-Haystack (NIH)**：在早期注入一个 24 字符、不可伪造的“针”，强制经历一次或多次压缩，然后测试能否精确提交 `NEEDLE=<value>`。用横幅指令标记针，将干扰项标记为噪声，降低自我怀疑干扰。3000 次尝试（3 种子 × 1000 任务）。
- **LongBench-v2 Hard subset**：311 个任务，覆盖单/多文档 QA、长上下文学习、结构化数据理解、长对话历史理解、代码仓库理解等，测试多步推理能力。933 次尝试（3 种子 × 311）。
- **HBM 带宽/roofline 模型**：将记录的提示/完成轨迹重放到单 NVIDIA H200 143GB GPU 的硬件模型上，估计 prefill 时间、decode 时间、总时间、HBM 流量，并计算可达批大小；也用于 AMD MI300X 跨平台验证。

#### 对比方法
- Full_context（不压缩）、Sliding_window（滑动窗口）、LLM_summary（LLM 摘要）、Structured_state（JSON 状态折叠）、RAG_memory（向量检索记忆），以及 ARC。所有方法使用相同种子任务/针，配对比较。

#### 统计检验
- 对 ARC 与每个基线用 McNemar 检验，报告连续性校正 χ²、精确二项 p 值和优势比（Odds Ratio）。

#### 额外消融与验证
- 召回预算消融（RECALL_BUDGET_CHARS / RECALL_MAX_CHARS，多档位）。
- 强制压缩调度消融（FORCE_AT_CALLS）。
- 噪声行数消融（NOISE_LINES_PER_SIDE）。
- HBM 分析在不同预算/调度/噪声下的对比。
- AMD MI300X 跨平台验证。

### 6. 主要结论与发现

- **NIH 上近完美召回**：ARC 在 Qwen3-8B 达 99.00%、Qwen3-32B 达 99.80%，显著高于最佳基线 RAG_memory（79.57% / 96.67%）；平均 99.40% vs 88.12%；几乎消除未答情况。
- **LongBench-Hard 上一致提升**：ARC 在 8B 上 27.47%、32B 上 32.47%，分别比最强基线高 1.64 和 1.80 个百分点；同时显著降低 No-Answer 率（16.33 / 7.33 vs 基线 23–74）。
- **统计显著性**：所有配对比较均显著，优势比高达 2.22–10.48（LongBench）和 18.5–∞（NIH）。
- **效率优势**：ARC 同时缩短服务时间和 HBM 流量。LongBench H200 上，8B 带宽节省 38.8%，32B 节省 73.5%；NIH 上 8B 节省 80.3%、32B 节省 59.3%。AMD MI300X 上也有类似收益（8B 79.6%，32B 73.8%）。ARC 是唯一“提高任务成功率同时降低内存流量和推理成本”的方法。
- **机制级保证**：给定有效 ID，任何历史观测都可精确恢复，活动视图大小与轮数无关，且外部存储增长接近信息论下界。

### 7. 优点

- 概念清晰：将“保留什么”与“展示什么”解耦，直接把压缩从不可逆变为可逆，是框架性创新。
- 设计实用：压缩例程确定性、无额外 LLM 调用；引用节成本固定；召回有预算控制和 LRU 逐出，避免扩张失稳。
- 实验严谨：配对任务、多种子、McNemar 检验、显式区分“答错”和“未完成”，并使用硬件成本模型量化效率，而非只报准确率。
- 跨平台验证：H200 与 MI300X 结果一致，表明方法不依赖特定硬件或数值栈。
- 理论与实验结合：形式化定理（有界活动视图、精确分块重建、外部存储下界）为方法提供了机制级保证，且明确区分“机制可恢复”与“语言模型能做对”的边界。

### 8. 不足与局限

- **模型覆盖狭窄**：仅评估 Qwen3-8B / 32B 两种模型，未验证其他流行模型族（如 Llama、GPT 等）或不同的分词器、推理风格、指令遵循能力。
- **上下文配置不完整**：只测了 16k/32k 窗口和 4k 完成上限，未覆盖更大上下文窗口（如 128k）和其他 Max-T 组合。
- **性能优势边际**：LongBench-v2 Hard 上 ARC 相对最强基线仅提升约 1.6–2.3 个百分点，说明在需要跨长文档综合推理的任务上，精确召回只是部分瓶颈，推理能力不足仍会限制最终收益。
- **特定任务弱点**：作者指出在长对话历史理解任务上隐式检索仍占优，表明显式与隐式召回是互补而非替代，ARC 并非普适最优。
- **额外 token 开销**：每个引用节（头尾预览、召回提示）相对“直接丢弃”有固定 token 开销，论文仅在补充材料中说明需量化其影响，未给出精确数值。
- **无端到端可靠性保证**：ARC 只保证“地址条件可恢复”，不保证模型会选择正确地址或正确推理；错误的召回策略仍会导致任务失败。
- **外部存储增长**：尽管接近理论最优，但外部存储仍随观测总量线性增长，长期大规模部署中归档存储成本不可忽视。
