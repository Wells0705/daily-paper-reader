## 摘要
大型语言模型（LLMs）具有有界的上下文窗口。上下文窗口是LLM在单次推理中能够处理的最大输入规模。AI智能体在调用LLM时，依赖一种称为上下文压缩的过程，将其状态适应于上下文窗口内。尽管上下文压缩无处不在，但基本上没有对其进行过正式分析。在本文中，我们首次对上下文压缩进行正式研究。我们首先引入一个由两个博弈组成的框架，这两个博弈捕捉了当代AI智能体在实践中使用的两种上下文压缩算法策略。上下文选择博弈对上下文压缩算法进行建模，这些算法从智能体累积的状态中选择一个子集予以保留。上下文生成博弈对上下文压缩算法进行建模，这些算法通过有界长度的任意消息来概括智能体的状态。然后，我们证明了上下文生成博弈与单向通信复杂性之间的等价性。在目标误差内回答一组查询所需的最小上下文压缩预算，等于相同误差下所诱导的通信问题的单向通信复杂性。因此，通信复杂性中的已知界限可直接迁移到上下文压缩。我们还表明，上下文选择博弈对应于受限类别的单向通信协议。因此，选择与生成之间的任何差距都是两类通信协议之间的差距。我们证明了存在一组查询，对于这些查询，生成所需的预算严格少于选择。上下文生成博弈与单向通信之间的等价性还使我们能够衡量已部署的上下文压缩算法在某个查询上的表现相对于最优策略的优劣。作为示例，我们呈现了一个案例研究，该研究在集合成员查询上评估了Anthropic的上下文压缩端点。

## Abstract
Large Language Models (LLMs) have a bounded context window. The context window is the maximum input size an LLM can consume for a single inference. AI agents rely on a process called context compaction to fit their state within the context window when calling an LLM. Despite its ubiquity, context compaction has received essentially no formal analysis. In this paper, we initiate a formal study of context compaction. We first introduce a framework consisting of two games that capture the two algorithmic strategies for context compaction used by contemporary AI agents in practice. The Context Selection Game models context compaction algorithms that select a subset of an agent's accumulated state to retain. The Context Generation Game models context compaction algorithms that summarize an agent's state by an arbitrary message of bounded length. We then prove an equivalence between the Context Generation Game and one-way communication complexity. The minimum context compaction budget for answering a set of queries within a target error is equal to the one-way communication complexity of the induced communication problem at the same error. Known bounds from communication complexity therefore transfer directly to context compaction. We also show that the Context Selection Game corresponds to a restricted class of one-way communication protocols. Any gap between selection and generation is therefore a gap between two classes of communication protocols. We prove that there exists a set of queries for which generation needs strictly less budget than selection. The equivalence between the Context Generation Game and one-way communication also lets us measure how well a deployed context compaction algorithm performs on a query relative to the optimal strategy. As an example, we present a case study that evaluates Anthropic's context compaction endpoint on set membership queries.

## 2. 论文提出的方法论

### 2.1 两个博弈框架

论文将上下文压缩建模为压缩算法与"代表未来信息需求的对手"之间的两玩家博弈，把智能体的上下文视为离散**条目**（items）的集合（如变量名、错误消息、设计决策等原子信息单元）。

**（1）上下文选择博弈（Context Selection Game）**
- 实例由条目宇宙 X、尺寸函数 s、预算 B、查询空间 Q、查询制度（query regime）组成。
- 流程：对手先固定条目宇宙 X → 选择器（压缩算法）观察 X 并选择一个子集 S ⊆ X（满足 Σs(xᵢ) ≤ B）→ 按查询制度产生查询 q → 选择器根据值函数 vq(S) 获得分数，误差为 1 − val(S,q)。
- **两种查询制度**：
  - **随机制度**：条目宇宙和查询按已知分布 μ 联合抽取，最小化期望误差。
  - ** oblivious 对手制度**：对手固定条目宇宙，在无法看到选择器所选子集的情况下选择查询，最小化最坏情况误差。

**（2）上下文生成博弈（Context Generation Game）**
- 生成器使用**冷凝器–解释器对**（condenser–interpreter pair）：冷凝器 Cond 将条目宇宙映射为长度至多 B 的消息 Cond(X) ∈ Σ≤B；解释器 Int 根据消息和查询输出答案 â = Int(Cond(X), q)。
- 在 LLM 摘要场景中，冷凝器对应摘要调用，解释器对应未来读取压缩上下文的 LLM 调用。
- **SELECT 与 GEN 的关系**：选择算法是生成算法的受限特例（SELECT ⊆ GEN）。生成算法可以：①输出 X 中不存在的全新 token；②通过重新排列条目传递信息；③以低于条目尺寸之和的方式整体编码。

### 2.2 核心理论结果（与通信复杂度的等价性）

- **定理 1（生成 ≡ 单向通信）**：上下文生成博弈与单向通信问题在结构上是同一对函数（冷凝器=Alice，解释器=Bob）。由此得到：
  - 随机制度下，最小压缩预算 = R→(μ,ε)(Π_G)（μ-分布单向随机通信复杂度）；
  - oblivious 制度下，最小压缩预算 = R→ε(Π_G)（最坏情况单向随机通信复杂度）。
- **推论 2（选择 = 受限通信）**：SELECT 算法恰好对应子集编码协议（Alice 的消息标识一个满足预算的子集，Bob 的输出仅依赖于该子集和查询）。因此 SELECT 与 GEN 的任何差距都是两类通信协议之间的差距。
- **定理 3（选择 ⊊ 生成）**：存在一个含 n 个条目的集合 Y 和单个查询 q，使得 GEN 算法只需 n 比特预算即可零误差回答，而任何 SELECT 算法需要至少 n log₂n 比特。差距为 Θ(log n) 因子。证明思路：SELECT 算法在低于 n log₂n 比特时无法覆盖 Y 的所有子集，因而不可能完美编码任意子集。

### 2.3 应用示例：集合不相交查询
- 若智能体需回答"依赖集合 S 是否与已知 CVE 包集合 T 相交"，由通信复杂度可知，正确回答所有查询需要 Ω(Nm) 比特（N 为依赖数，m 为包标识长度），与直接存储依赖集合同阶。
- 使用 Bloom filter 的近似方案同样无法显著降低：当 |T| 可达到 2ᵐ 时，仍需 Ω(Nm) 比特。

### 2.4 范围说明（两个注意事项）
- **信息论而非计算论**：等价性给出的是信息量下界/上界，不保证特定压缩算法（如 LLM 摘要器）在计算上能达到该预算；但下界对所有算法都成立。
- **仅适用于随机和 oblivious 制度**：adaptive adversary（观察到压缩输出后再选查询）的情况不在定理适用范围，留作开放问题。

## 3. 实验设计

论文主体为理论推导，实证部分（附录 A）是一个**案例研究**，用于展示如何用理论衡量部署算法的实际性能。

### 实验场景与数据集
- **基准查询类型**：集合成员查询（set membership query），因其最优压缩预算已知（任意近似成员测试器至少需要 N log₂(1/ε) 比特，Bloom filter 在 1.44 常数因子内达到该界）。
- **数据集**：Malicious URLs 数据集（Kaggle）。选择该数据集的原因：URL 具有共享结构（公共域名、路径模式），是可压缩的"友好"场景，对压缩端点有利。
- **被测对象**：Anthropic 的 Claude API 上下文压缩端点（使用 Claude Opus 4.8），压缩提示词明确告知端点"结果仅用于成员查询"。

### 实验流程
1. 从数据集中均匀采样 15,000 个 URL（约占 500,000 token，超过 50,000 token 的压缩触发阈值）。
2. 调用上下文压缩端点进行压缩，记录压缩摘要的比特数。
3. 压缩后提出 200 个成员查询：100 个来自已记录集合（探测假阴性），100 个来自未记录的 URL（探测假阳性）。
4. 每个查询单独发送（仅含压缩上下文），LLM 以结构化 JSON 回答是/否。
5. 用 3 个随机种子（42、43、44）重复实验。

### 对比方法
- **Bloom filter**：使用与压缩摘要相同比特数的理想化 Bloom filter 作为近最优基准（误差率公式为 ½e^(−(ln2)²B/N)）。
- **信息论下界**：½·2^(−B/N)（Carter et al. 1978）。
- **随机猜测基线**：误差率 0.5。
- **控制实验**：不做压缩，将全部 15,000 个 URL 保留在上下文中，回答相同查询。

## 6. 论文的主要结论与发现

1. **形式化框架的建立**：提出上下文选择博弈和上下文生成博弈，覆盖了当代 AI 智能体实际使用的两类压缩策略；现有生产级压缩算法（Codex、Gemini CLI、Claude Code、OpenCode、LangChain、LLMLingua 等）均可归入 SELECT ∪ GEN 分类。
2. **生成与单向通信的等价性**（定理 1）：最小压缩预算 = 诱导通信问题的单向通信复杂度，通信复杂度领域的已知结论可直接迁移。
3. **选择是受限通信**（推论 2 + 定理 3）：生成策略在理论上严格强于选择策略，存在 Θ(log n) 的预算差距。
4. **实际部署算法的性能测量**：Anthropic 的上下文压缩端点在集合成员查询上的误差率（0.505、0.535、0.555）接近随机猜测，而同等大小的 Bloom filter 误差约为 1/3；压缩后信息基本完全丢失。
5. **实用启示**：对集合不相交等查询，任何压缩策略都无法优于直接存储（Ω(Nm) 比特）；上下文压缩有其根本性信息论限制。

## 7. 优点

- **开创性**：首次为普遍存在但缺乏理论分析的上下文压缩提供了严格的形式化框架。
- **理论优雅且有力**：将问题归约到单向通信复杂度，直接借用成熟领域的海量结论，使上下界推导变得简洁而严谨；定理 1 的证明（识别冷凝器/解释器与 Alice/Bob 为同一对函数）简洁清晰。
- **清晰的类划分**：SELECT ⊆ GEN 的包含关系以及对两者差距的刻画（定理 3），为理解选择式与生成式压缩策略的本质差异提供了理论依据。
- **理论与实践结合**：案例研究展示了如何用理论框架量化真实部署算法与最优策略的差距，提供了一种可复用的评测方法。
- **信息论下界的稳健性**：下界对所有算法成立，不受计算实现方式影响，具有普遍约束力。
- **诚实披露**：论文明确声明的计算/范围注意事项（信息论 vs 计算论、不适用于 adaptive adversary）体现了学术严谨性。

## 8. 不足与局限

- **信息论与计算现实的差距**：等价性给出的是信息量界限，并不保证实际的 LLM 压缩器（如 Anthropic 端点）能在计算上达到该界限。事实上案例研究显示真实端点远未达到信息论下界。
- **单次压缩模型**：模型只捕获单次压缩调用，而真实智能体在同一次会话中会多次压缩（每次基于上次压缩结果）。重复压缩的误差累积特性留作开放问题。
- **查询制度覆盖不全**：定理 1 仅覆盖随机和 oblivious 对手制度，**adaptive adversary**（观察到压缩输出后再选查询）不在分析范围内——而这恰恰可能是安全敏感场景下最关键的威胁模型。
- **实证覆盖有限**：仅测了一个厂商的一个端点、一种模型、一个数据集、一种查询类型，结论的普适性受限；对"端点错误率接近随机猜测"这一发现的解释也有待更多验证（不同提示词、批次大小、条目类型等可能有不同表现）。
- **无法模拟解码过程**：论文提出的改进方向（在上下文中放置 sketch 原始状态并让 LLM 解码）仍是一个未验证的开放问题，LLM 能否可靠执行此类解码尚不明确。
- **粒度选择的模糊性**：条目（item）的粒度（token、消息、工具结果等）是一个建模决策，框架本身对此保持中立，但在实际应用中粒度选择会显著影响分析结果。
- **应用门槛**：计算特定问题的单向通信复杂度本身可能并不容易，这限制了该理论框架在工程设计中的直接可用性。
