## 摘要
循环上下文压缩控制长时程智能体中的上下文增长，但其行为影响仍知之甚少。在这项初步实证研究中，我们表明压缩会削弱近期交互的影响，增加阻塞动作、重复探索以及跨运行的不稳定性。基于这些观察，我们引入了TRACE，一个验证器引导的框架，通过来自同一环境状态的成对闭环延续来评估单个压缩事件，并利用摘要偏好优化自然语言压缩提示，同时保持所有模型冻结。在AppWorld上的初步结果显示，在任务性能、多运行可靠性和上下文-执行效率方面，相对于现有压缩基线有所改进。这些发现为边界局部评估作为可靠智能体上下文压缩的一个有前景方向提供了早期证据。

## Abstract
Recurrent context compression controls context growth in long-horizon agents, but its behavioral effects remain poorly understood. In this preliminary empirical study, we show that compression can weaken the influence of recent interactions, increasing blocked actions, repeated exploration, and instability across runs. Motivated by these observations, we introduce TRACE, a verifier-guided framework that evaluates individual compaction events through paired closed-loop continuations from the same environment state and uses summary preferences to optimize a natural-language compression prompt while keeping all models frozen. Initial results on AppWorld show improvements over existing compression baselines in task performance, multi-run reliability, and context--execution efficiency. These findings provide early evidence for boundary-local evaluation as a promising direction for reliable agent context compression.

# 论文总结

## 1. 核心问题与整体含义
- **研究背景**：长时程智能体（如交互式 agent）需要在持续推理、行动、观察和计划修订中处理不断增长的上下文，但完整历史会导致推理成本上升和关键信息难以定位，因此上下文压缩必不可少。
- **核心问题**：现有压缩方法通常隐含一个“替代假设”——只要摘要保留了任务相关内容，就能替代原始交互历史。但原始轨迹不仅是信息记录，还承载着“已完成什么、当前进行到哪一步、是否应终止”的定向执行状态。压缩可能使智能体失去本地位置感，导致阻塞动作、重复探索和跨运行不稳定性。
- **整体含义**：压缩不应只追求信息保留，更关键的是保留能支撑智能体持续正确执行的状态表征。本文通过实证诊断和提出的 TRACE 框架，论证了“边界局部评估”（boundary-local evaluation）是可靠上下文压缩的可行方向。

## 2. 方法论
- **核心思想**：在每次压缩事件发生的边界处评估压缩质量，而不是用最终任务结果来推断。通过同一环境状态下成对闭环延续（PRE 与 POST）测量压缩引入的执行回退。
- **关键技术细节**：
  - **边界局部执行验证器**：设压缩边界 b，PRE 用压缩前上下文，POST 用候选摘要替代压缩历史后继续闭环执行；每步标记是否为阻塞（触发环境错误）或重复（与边界前或同次延续中已执行的工具调用签名相同）。
  - **执行负担**：对固定长度 K 的延续，G(τ) = Σ z_j(τ)，z_j 为阻塞或重复的指示函数；压缩诱导负担 ΔG = E[G(POST)] − E[G(PRE)]；评分 Q = −ΔG。PRE 作为配对控制，用于剔除智能体自身随机性和固有错误。
  - **提示优化流程**：先收集训练边界的 PRE/POST 延续，按错误类型分层选出 12 个边界；用冻结压缩机为每个边界生成 3 个候选摘要，通过验证器评分选出最好和最差，形成对比对；冻结的 proposer（LLM）只看到压缩机输入、好/差摘要对和下游系统提示（防止生成的压缩策略与系统提示矛盾），输出 5 个候选压缩模板；最终在开发集上用完整执行的 Pass 2 指标从 5 个候选中选出最优模板，再在测试集上评估。
- **特点**：所有模型参数冻结，只优化自然语言压缩模板；后续 rollouts、错误信号、验证器分解均不暴露给 proposer。

## 6. 主要结论与发现
- 压缩会削弱近期交互对后续决策的影响，使智能体更难识别当前执行状态，表现为阻塞动作增加和重复探索，且跨运行成功率（Pass 2）下降比平均成功率更明显。
- 这种退化在更长全上下文执行的任务中更严重，说明压缩的效果会随递归替换而累积。
- 提出的 TRACE 框架在 AppWorld 上显著优于所有压缩基线：平均准确率 77.1 vs 最强基线 71.4，Pass 2 67.3 vs 59.5，Pass@2 86.9 vs 83.3；在中等和困难任务上提升尤其明显。
- 效率方面，TRACE 的峰值 token 大幅降低，同时平均步数接近全上下文水平，优于 FIFO 等激进压缩方法。
- 用 MiniMax-M3 优化的压缩模板可迁移到 Kimi-K2.7-Code，且在该模型上整体准确率和 Pass 2 甚至超过全上下文，表明学到的是较通用的压缩策略。

## 7. 优点
- **边界局部评估**：直接测量压缩点处的执行回退，避免了终端结果归因的模糊性。
- **成对闭环控制**：PRE 作为同一状态下的控制，能够分离压缩效应与冻结智能体的固有随机性和错误。
- **冻结模型、仅优化提示**：无需更新任何模型参数，成本低且适用范围广。
- **系统感知的提示提议**：明确将下游系统提示纳入 proposer 的审计输入，防止压缩规则与系统约束矛盾。
- **偏好仅使用顺序信息**：proposer 看不到动作、观察和错误细节，减少过拟合具体失败案例的风险。
- **跨模型迁移结果**：为策略的可迁移性提供了初步证据。

## 8. 不足与局限
- **仅一个 benchmark**：只在 AppWorld 上评估，未覆盖 WebArena、τ-bench 等其他长时程环境，通用性尚不确定。
- **验证器信号受限**：只捕获阻塞和重复动作，无法检测“静默状态损坏”（如错误但无报错的信息、被扭曲的进度），可能低估压缩危害。
- **无消融实验**：无法确定系统提示注入、对比对数量、分层边界选择等组件的具体贡献。
- **跨模型迁移测试仅一个目标模型**：对更广泛模型的泛化不能确认。
- **训练边界选择依赖初始基线的失败边界**：可能使优化偏向特定错误类型。
- **资源信息缺失**：未报告算力用量，影响可重复性和成本评估。
- **初步研究性质**：作者明确标注为工作进展，结论需进一步验证。
