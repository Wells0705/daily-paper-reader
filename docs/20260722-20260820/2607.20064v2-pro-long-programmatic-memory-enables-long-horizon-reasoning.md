## 摘要
长时程任务需要持续的感知、推理和探索，对大型语言模型（LLM）智能体而言始终是一个挑战。这一差距体现在它们在持续学习基准（如ARC-AGI-3）上的有限表现，尤其是在模型未经调整直接评估时。为缩小这一差距，人们提出了各种智能体框架，每种框架都采用了处理长观察序列的策略，即从环境中保存哪些信息以及如何将其加载到模型上下文中，我们认为这一选择至关重要。现有的上下文管理方法面临显著的权衡，因为保留更多信息会使检索相关细节变得更为困难。我们提出PRO-LONG，一个围绕程序化记忆构建的极简上下文管理框架，适用于长时程、探索性场景中的LLM智能体。PRO-LONG通过保留完整、结构化的交互日志，并利用编码智能体的最新进展来高效搜索这段历史，从而解决了上述权衡问题。在完整的ARC-AGI-3公共游戏集上，PRO-LONG相比基础编码智能体在前沿模型上平均提升18.0个百分点，并匹配或超越了最先进的专用框架（最高达76.1% pass@1），同时使用的token减少4.2至5.8倍。使用Fable 5时，PRO-LONG在总成本为1750美元的情况下达到了97.4%的best@2。相关代码和日志见 https://github.com/alexisfox7/PRO-LONG。

## Abstract
Long-horizon tasks require sustained perception, reasoning, and exploration, and are a persistent challenge for large language model (LLM) agents. This gap is reflected in their limited performance on continual learning benchmarks such as ARC-AGI-3, especially when models are evaluated out of the box. Various agent harnesses have been proposed to close this gap, and each commits to a strategy for handling long sequences of observations, i.e., what information to save from the environment and how to load it into model context, a choice we argue is particularly consequential. Existing methods for context management face a significant tradeoff, as preserving more information makes retrieving relevant details less tractable. We propose PRO-LONG, a minimal context management framework built around programmatic memory for LLM agents in long-horizon, exploratory settings. PRO-LONG addresses the tradeoff by keeping a complete, structured interaction log and capitalizing on recent progress in coding agents to search this history efficiently. On the full ARC-AGI-3 public game set, PRO-LONG improves over a base coding agent by an average of 18.0 percentage points across frontier models, and matches or exceeds state-of-the-art specialized harnesses (up to 76.1% pass@1) while using 4.2-5.8x fewer tokens. With Fable 5, PRO-LONG achieves 97.4% best@2 at a total cost of \$1,750. Relevant code and logs are available at https://github.com/alexisfox7/PRO-LONG.

## 1. 核心问题与研究动机

**背景与问题**：
- 长时程任务（Long-horizon tasks）要求 LLM 智能体进行持续的感知、推理与探索，是当前 AI 智能体面临的核心挑战之一。
- 在持续学习基准（如 ARC-AGI-3、NetHack）上，"开箱即用"的前沿 LLM 表现极差——在 ARC-AGI-3 上得分接近零，在 NetHack 上进展有限。
- 现有智能体框架（harness）普遍面临一个根本性权衡——**保真度-可处理性权衡（fidelity–tractability tradeoff）**：
  - 写入（write）阶段保存的信息越多，读取（read）阶段检索相关细节就越困难；
  - 而过度压缩/摘要又可能丢弃在当时看似无关、事后却至关重要的信息。
- 作者将智能体上下文管理划分为两个关键概念：
  - **accessed context（已访问上下文）**：当前处于模型上下文窗口内的信息；
  - **accessible context（可访问上下文）**：可通过工具访问的外部记忆（日志文件、笔记、向量库等）。
- 现代 LLM 虽有近百万 token 的上下文窗口，但性能随轨迹增长而显著退化（"上下文腐烂"，context rot），因此需要有效的记忆管理机制。

**核心主张**：现有上下文管理方法在"保留什么"和"如何检索"之间存在不可避免的矛盾，而**编码智能体（coding agents）**的最新进展（如程序化工具、结构化日志搜索）为打破这一权衡提供了新路径。

## 2. 方法论：PRO-LONG 框架

### 2.1 核心思想：程序化记忆（Programmatic Memory）

PRO-LONG 重新定义了智能体记忆的读写操作：

| 操作 | 传统方法 | PRO-LONG |
|------|----------|----------|
| **Write（写入）** | 启发式筛选、摘要、向量化存储、技能蒸馏 | **追加一切（append-all）**：将每个动作、观测、结果、分数变化完整追加到 `logs.txt` |
| **Read（读取）** | 嵌入检索、关键词搜索、加载记忆块 | **程序化搜索**：通过 grep、正则表达式、Python 脚本对日志进行结构化查询与推理 |

### 2.2 三大设计原则

1. **简单性（Simplicity）**：
   - 写入阶段无需任何学习或启发式决策，环境输出什么就记录什么；
   - 读取阶段无需专用向量数据库、索引或检索器；
   - 系统提示词仅约 30 行，无子智能体（subagent）。

2. **无损性（Losslessness）**：
   - 日志是环境状态的忠实、Ground-Truth 完整记录，不做任何压缩或摘要；
   - 避免"写入时决策"造成的不可逆信息损失。

3. **与编码智能体的兼容性（Coding-agent Compatibility）**：
   - 程序化搜索（正则表达式、代码查询）是编码智能体的原生能力；
   - 实际验证：PRO-LONG 的检索在超过 **10 万行**的日志上依然保持可处理性。

### 2.3 技术实现细节

- **日志结构**：每次动作追加一个结构化条目，包含：动作编号、关卡、尝试次数、得分、智能体计划摘要、所选动作、结果棋盘状态。
- **工具空间**：read / write / edit / grep / bash / python3（仅标准库），运行于沙箱容器。
- **棋盘表示**：64×64 文本网格，16 种颜色映射为 ASCII 符号（不使用视觉输入）。
- **动作空间**：四个方向移动（ACTION1-4）、空格交互（ACTION5）、点击指定单元格（ACTION6）、撤销（ACTION7）、重置（RESET）。
- **运行循环**：智能体每次调用读取日志尾部新增内容 → 分析 → 写入 `actions.json`（含 1–20 个待执行动作）→ 环境执行后返回更新日志。
- **评价指标**：RHAE（Relative Human Action Efficiency，相对人类动作效率），按关卡加权（越靠后的关卡权重越高），得分上限 115%。

## 3. 实验设计

### 3.1 基准（Benchmark）

- 游戏规则完全不予披露，智能体必须通过探索推断环境动力学；
- 示例游戏：`tu93`（迷宫+炮塔拆除）、`g50t`（"倒带"机制产生幽灵克隆体）、`m0r0`（双方块迷宫控制）；
- 默认配置：每游戏 **500 动作**上限，每回合最多 **20 动作**；另设 2,000 动作的高预算实验。

### 3.2 对比方法

| 方法 | 基础模型 | 核心特点 |
|------|----------|----------|
| **No-Log（基线）** | GPT-5.5 等 | 基础编码智能体，无外部日志记忆，靠自写笔记/文件 |
| **WorldModeler** | GPT-5.5（Codex） | 约 600 行提示词，引导智能体编写 Python 世界模型模拟器，使用视觉，定义两个子智能体 |
| **Arcgentica** | Opus 4.6（自定义 SDK） | Orchestrator 主智能体 + 四个子智能体（探索/理论/测试/求解者），共享假设记忆数据库 |
| **Schema** | Opus 4.8 / Fable 5（Claude Code） | 通过 MCP 服务器替换为 12 个自定义工具，更新 step(grid, action) 函数、回溯测试、BFS 规划 |

- 模型：**GPT-5.5**、**Opus 4.6**、**Fable 5**（其中两个模型发布于基准之后）；

## 6. 主要结论与发现

1. **显著提升**：相比基础编码智能体（no-log），PRO-LONG 在前沿模型上**平均提升 18.0 个百分点**（幅度 15.7–21.0pp，pass@1），且是"最小化"添加（约 30 行提示词，无子智能体）。

2. **媲美或超越专用框架，且大幅省 token**：
   - **Opus 4.6**：42.4% pass@1，为该模型公开最佳结果（超越 Arcgentica 约 3pp）；
   - **GPT-5.5**：41.2% pass@1、60.1% best@5，对比 WorldModeler 45.1% pass@1，token 少 5.8×（best@5 时仍少 1.2×）；
   - **Claude Code**：82.1% best@2，对比 Schema 84.4%，token 少 4.2×；
   - **Fable 5（2,000 动作）**：97.4% best@2，总成本仅 $1,750（Schema 为 $6,447+）。

3. **日志完整度是关键驱动因素**：
   - best@k 分析显示，完整日志与截断日志的差距**随 k 增大而扩大**——完整记忆覆盖了更多"本不可解"的游戏；
   - 即：长时程推理要求更高的游戏难度更高、方差更大，完整历史是解决这类游戏的前提。

4. **程序化工具 > 其他记忆形式**：
   - 工具阶梯消融：仅读 23.1% → +grep 27.2% → +Python 38.3% → +写/编辑 41.2%；
   - Python 贡献了超 10 个百分点的增益；写/编辑工具仅贡献 2.9pp；
   - 无日志基线的工具调用 59.2% 花在工作区管理/写笔记上，而 PRO-LONG 有 60.6% 花在 Python 程序化分析上（日志解析占 20.3%）。

5. **鲁棒性**：清空工作区（消除笔记等辅助记忆）对 PRO
