## 摘要
生产环境中的AI代理在其上下文来源——系统提示、知识库、工具描述和程序性技能——包含错误或缺口时会出现故障。当前的维护依赖于人工日志审查和临时调试，随着交互量的增长，这造成了可扩展性瓶颈。我们提出了TRACE（面向自动化上下文工程的任务轨迹归因），这是一种自动化反馈循环，通过挖掘历史代理轨迹来诊断和修复上下文故障。我们的核心见解是，轨迹中蕴含着丰富的隐含不满信号——用户纠正、重新表述、放弃线索——这些信号能够精确揭示上下文来源在何处失效，而无需显式收集反馈。与模型微调不同，TRACE在上下文层运作，无需重新训练即可快速迭代。我们做出四项贡献：（1）一个轨迹挖掘框架，系统性地从历史代理执行中提取诊断信息；（2）多组件因果归因，将文本梯度从单体提示优化扩展到异构上下文来源（技能、知识库、工具、提示）；（3）探索性验证，其中代理主动读取上下文来源，以区分需要CREATE的内容缺口与需要UPDATE的陈旧内容，达到96%的操作准确率；（4）一套可复用的模拟方法和可验证基准，解决了上下文调试缺乏开放数据集的问题，包含六类故障分类、真实标注和跨层验证协议。在涵盖三个复杂度层级（最多16个执行节点）的60条不满轨迹上，TRACE实现了72.7%的根因归因准确率和82%的端到端修复有效性，表明通过挖掘历史轨迹（生产系统中一个被忽视的资源），超过80%的上下文层故障可以被自动诊断和修复。

## Abstract
Production AI agents fail when their context sources -- system prompts, knowledge bases, tool descriptions, and procedural skills -- contain errors or gaps. Current maintenance relies on manual log review and ad-hoc debugging, creating a scalability bottleneck as interaction volume grows.   We present TRACE (TRajectory Attribution for Automated Context Engineering), an automated feedback loop that mines historical agent trajectories to diagnose and remediate context failures. Our key insight is that trajectories are rich with implicit dissatisfaction signals -- user corrections, rephrasing, abandonment cues -- that reveal precisely where context sources failed, without explicit feedback collection. Unlike model fine-tuning, TRACE operates on the context layer, enabling rapid iteration without retraining.   We make four contributions: (1) a trajectory mining framework that systematically extracts diagnostic information from historical agent executions; (2) multi-component causal attribution that extends textual gradients from monolithic prompt optimization to heterogeneous context sources (skills, knowledge bases, tools, prompts); (3) exploratory verification, where agents actively read context sources to distinguish content gaps requiring CREATE from stale content requiring UPDATE, achieving 96% operation accuracy; and (4) a reusable simulation methodology and verifiable benchmark addressing the absence of open datasets for context debugging, with a six-category fault taxonomy, ground truth annotations, and a cross-layer verification protocol.   On 60 dissatisfaction traces spanning three complexity tiers (up to 16 execution nodes), TRACE achieves 72.7% root cause attribution and 82% end-to-end fix effectiveness, showing that over 80% of context-layer failures can be automatically diagnosed and remediated by mining historical trajectories, an overlooked resource in production systems.

## 2. 论文提出的方法论

- **核心思想**：把 Agent 对话轨迹视为可“反向传播”的计算图，将用户纠正与 Agent 输出之间的差异视为“损失信号（delta）”，通过文本梯度方式从响应端向输入端回溯，定位最早引入错误的节点。
- **系统架构**：由三个 Agent 组成反馈闭环：
  - Detector Agent：识别轨迹中的显式信号（工具报错、差评等）和隐含信号（用户纠正、重复、负向情绪、语义漂移等），判断会话是否属于 DSAT（dissatisfaction）会话。
  - Root Cause Agent：接收 DSAT 会话，对完整轨迹进行整体归因，输出根因节点、故障类型、归因分数和“文本梯度”描述。
  - Recommender Agent：主动探索上下文来源（读取 Knowledge Base、Skill 文件、系统提示等），验证 Root Cause 的假设，并输出 CRUD 修复建议（CREATE / UPDATE / DELETE / NO_ACTION）。
- **关键技术细节**：
  - **Delta-Guided Holistic Attribution**：使用单次 LLM 调用，将轨迹按逆时间顺序整体呈现，让模型从最终响应回溯至初始查询，找到“输出中包含错误但输入不包含错误”的最早节点；相比逐节点迭代，显式利用全局比较信号来区分根因与级联传播节点。
  - **轨迹节点建模**：将查询、系统提示、工具选择、知识检索、技能查找、响应生成等建模为上下文图节点，每个节点有输入内容和输出结果。
  - **探索性验证**：Recommender 不只是接受 Root Cause 结论，而是主动读文件、搜索知识库、交叉验证权威来源；该能力对区分“内容缺失”（GAP→CREATE）与“内容过时”（STALE→UPDATE）至关重要。
  - **故障分类**：六类故障——SKILL_FILE_STALE、KB_CONTENT_STALE、KB_CONTENT_GAP、TOOL_PROMPT_ERROR、SYSTEM_PROMPT_GAP、RETRIEVAL_FAILURE。
  - **模拟数据方法**：提出三层仿真架构（Context Sources → Fault Definitions → Execution Traces），生成带完全真实标注的合成轨迹，并提供跨层验证协议保证数据完整性。
- **论文核心算法/流程**（文字描述）：
  1. 从用户纠正和 Agent 响应中提取 delta：期望输出与实际输出的差异。
  2. 将轨迹按逆时间顺序组织成 evidence bundle。
  3. LLM 从响应节点反向遍历，寻找“最早引入 delta”的节点，作为根因。
  4. Recommender 对候选根因进行主动文件验证，最终生成 CRUD 建议。

- **Benchmark 贡献**：在缺少公开上下文调试数据集的情况下，给出了可复用的三层模拟数据生成方法和验证协议，便于社区扩展到其他领域。
- **消融实验设计**：验证了 holistic vs iterative、active exploration vs passive acceptance，提供了较清晰的因果证据。
- **复杂案例说明**：附录给出的 Finance Operations 完整示例，细致展示了级联失败、误检信号、根因与症状区分等关键过程，有助于理解方法。

## 8. 不足与局限

- **合成数据依赖**：所有实验基于仿真轨迹，无法证明在真实生产日志和真实用户行为分布上同样有效；现实轨迹的多变性、噪声和长尾分布未被覆盖。
- **样本量较小**：60 条 DSAT 轨迹不足以支持高置信度的类别细分分析；置信区间较宽（如 Node Accuracy 95% CI 为 59%–85%）。
- **潜在同源偏差**：故障注入和轨迹生成由同一框架完成，可能使系统检测与故障模式高度契合，导致结果偏乐观。
- **Detector 对比不充分**：简单 vanilla baseline 与 structured prompt 性能相同，说明 binary detection 不是主要难点；但论文未比较不同阈值、不同 LLM 或跨领域会话的检测稳定性。
- **故障范围有限**：六类故障仍不能覆盖所有上下文工程错误，如模型自身幻觉导致的输出错误、嵌入模型退化、动态外部数据源冲突等未纳入。
- **实际部署风险**：系统仍依赖 LLM 的推理质量，生成错误建议时可能引入新问题；目前只输出建议供人工审核，尚未实现完全自动应用的闭环。
- **资源与复现细节不完整**：未公开实际计算量、模型版本、推理成本、多次随机试验的稳定性，复现门槛较高。
- **路径准确率瓶颈**：当多个 KB 文档相似时，Recommender 难以精确定位文件（Path Accuracy 82%），在真实大规模知识库中该问题可能更严重。
