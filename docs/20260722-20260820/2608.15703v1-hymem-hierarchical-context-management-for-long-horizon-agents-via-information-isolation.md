## 摘要
大语言模型智能体在复杂的长时间跨度任务上通常表现不佳，因为其上下文会随着时间推移变得越来越杂乱。随着交互的累积，详细的执行轨迹和中间输出主导了上下文，使得模型难以保留和利用高层规划信息。大多数现有方法通过对单一扁平上下文应用压缩或检索来解决此问题，这无法清晰区分不同类型的上下文信息，且常常导致推理能力下降。为应对这一挑战，我们提出了HyMem，一种层次化框架，将智能体的上下文明确划分为不同的功能层。HyMem按功能组织上下文，以将高层规划与执行及复杂分析分离。其隔离的推理模块在处理复杂子任务时，不会将中间推理痕迹添加到持久的规划上下文中；而其记忆管理模块则通过结构化摘要，在上下文刷新时保留任务进度。这些组件减少了冗余上下文积累，保留了任务关键信息，并支持在有限上下文窗口内进行连贯的长时程推理。在GAIA和Browsecomp-plus上的实验表明，使用DeepSeek-V4时，HyMem的平均Pass@1得分分别为66.7%和61.3%，比最强基线分别高出6.1和4.7个百分点。进一步分析表明，HyMem有效控制了推理上下文的增长，使模型能够在复杂的长时程任务中保持专注度和准确性。

## Abstract
Large language model (LLM) agents often perform poorly on complex, long-horizon tasks because their context becomes increasingly cluttered over time. As interactions accumulate, detailed execution traces and intermediate outputs dominate the context, making it difficult for the model to retain and use high-level planning information. Most existing methods address this issue through compression or retrieval applied to a single, flat context, which does not clearly separate different types of context information and often leads to degraded reasoning. To address this challenge, we propose HyMem, a hierarchical framework that explicitly separates the agent's context into distinct functional layers. HyMem organizes context by function to separate high-level planning from execution and complex analysis. Its isolated reasoning module handles complex subtasks without adding intermediate reasoning traces to the persistent planning context, while its memory management module preserves task progress across context refreshes through structured summaries. These components reduce redundant context accumulation, retain task-critical information, and support coherent long-horizon reasoning within a limited context window. Experiments on GAIA and Browsecomp-plus show that, with DeepSeek-V4, HyMem achieves average Pass@1 scores of 66.7% and 61.3%, outperforming the strongest baseline by 6.1 and 4.7 percentage points, respectively. Further analysis indicates that HyMem effectively controls the growth of the reasoning context, allowing the model to maintain focus and accuracy across complex, long-horizon tasks.

# HyMem：基于信息隔离的长时程智能体层次化上下文管理

## 1. 核心问题与研究动机

- **背景**：大语言模型（LLM）智能体在 GUI 操作、深度研究、网络信息检索等长时程任务中能力日益增强，但当任务需要宏观策略规划与微观工具操作的深度融合时，仍面临显著挑战。
- **核心问题**：长时程任务的上下文存在结构失配——高层战略规划（需要稳定与连续性）和低层执行痕迹（往往是噪声性、瞬态的）在标准的扁平上下文架构（如 ReAct）中被交织混合为单一序列。随着执行步骤的冗余信息快速累积，产生"信息洪流"，稀释甚至淹没稀疏的策略规划信号，导致智能体在工具细节中丢失原始目标。作者将这一现象形式化为**上下文稀释（context dilution）**：规划相关信息密度 ρt = |Zt|/|Ct| 随上下文增长而下降。
- **现有方法的不足**：上下文压缩（如 Summarization、ReSum）和外部记忆检索（如 A-MEM）等多在预混合的扁平序列上操作，难以区分推理信号与执行噪声；压缩常丢失关键推理链，外部记忆难以保持时序逻辑，也未能区分高层规划与离散执行步骤。这些方法只解决上下文长度的"症状"，而非不同信息类型混在一起的"病根"。

## 2. 方法论

### 2.1 核心思想：类型化上下文隔离（Typed Context Isolation）

HyMem 是一个**无需训练（training-free）的推理期控制器**，核心设计原则是将规划、工具执行、隔离子任务推理、记忆整合分别置于独立的上下文空间，仅允许受 schema 约束的消息跨越信息边界，从源头阻断冗余执行信息进入决策空间。

### 2.2 架构组成

- **Planner（规划层）**：维护主决策上下文 `C(p)_t = [P(p), q, Mepi_t, Mwm_t, Mtool_t, H(p)_t]`，全程持久化，只接收类型化返回（typed returns）。动作空间包括：
  - `⟨TASK⟩(d)`：委派执行器
  - `⟨ISO REASON⟩(d)`：委派隔离推理
  - `⟨FOLD⟩`：触发记忆压缩
  - `⟨ANSWER⟩(ŷ)`：输出最终答案
- **Executor（执行层）**：按需创建新上下文 `C(e)_t,0 = (P(e), d, Mtool_t)`，执行有界工具调用循环。原始观察经过相关性条件蒸馏操作 `ϕ(·)` 滤除导航文本、重复段落、格式噪声等，保留命名实体、日期、数值、证据片段，最终综合成结构化结果 `R(e)_t = ⟨RESULTS⟩[findings, evidence, sources, status, gaps]⟨/RESULTS⟩`，仅此返回进入规划器，执行层上下文随即丢弃。
- **Isolated Reasoning（隔离推理模块）**：处理多跳分析、假设检验、冲突证据调和等复杂子任务。创建上下文 `C(iso)_t,0 = [P(iso), d, Mepi_t, Mwm_t, Mtool_t, τ(H(p)_t)]`（其中 τ(·) 选择最近规划器状态）。中间推理痕迹保持私有，最终返回 `R(iso)_t = ⟨RETURN⟩[conclusion, supporting facts, sources, confidence κ, assumptions]⟨/RETURN⟩` 后即丢弃。
- **Memory Management（记忆管理模块）**：维护三种可重写记忆——**情景记忆**（记录已完成里程碑、已验证事实、重要决策）、**工作记忆**（当前目标、未解决缺口、下一步计划）、**工具记忆**（有效工具使用模式、失败查询、工具注意事项）。折叠操作 `Mt+1 = Φ(H(p)_t, H(e)_≤t, H(iso)_≤t, Mt)` 联合重写所有记忆，并采用**不对称记忆注入**：规划器获得全部三种记忆（工具记忆为压缩的程序性摘要），隔离推理获得三种记忆，执行器仅获工具记忆。

### 2.3 推理流程与触发条件

- 底层模型 πθ 被冻结包装，在规划器步骤采样动作。
- 折叠（FOLD）在规划器显式发出或满足确定性条件时触发：规划器上下文 token 利用率 >99%、执行器调用 ≥5 次、连续失败 ≥3 次、规划器轮次 ≥8、工具调用 ≥10。
- 信息边界由转换规则保证：原始观察只进入执行器，返回 R(e) 后即删；中间推理 token 只进入隔离空间，返回 R(iso) 后即删；规划器通过有界类型化返回和重写记忆增长，而非完整工具痕迹。

## 6. 主要结论与发现

- **整体性能**：DeepSeek-V4 + HyMem 在 GAIA 平均 Pass@1 达 **66.7%**（超最强基线 ReSum 6.1 个百分点），Browsecomp-plus 达 **61.3%**（超 ReAct 4.7 个百分点）；难点问题上提升显著（Browsecomp-plus 困难题 Pass@1 从 14.0% 升至 30.0%）。
- **机制验证**：上下文增长曲线显示 HyMem 的总上下文（含执行层与隔离层）虽然持续增长，但**持久规划器上下文增长缓慢**——执行细节和中间分析停留在临时上下文空间中，证明信息隔离确实防止了规划上下文按交互痕迹比例膨胀。
- **消融结论**：隔离推理和记忆管理**两者缺一不可**。缺少隔离推理在 GAIA 上导致 18.6 个百分点的巨大性能下降；缺少记忆管理也大幅降低性能并降低置信度，说明仅隔离而无连续性保持是不够的。
- **骨干依赖**：HyMem 的收益依赖模型遵循类型化控制指令和产出可靠结构化返回的能力，跨骨干的增益并不一致。

## 7. 优点与亮点

- **问题形式化清晰**：将上下文稀释定义为规划相关信息密度 ρt = |Zt|/|Ct| 的下降，为长时程上下文问题提供了理论化度量基准。
- **创新性的设计原则**：提出"类型化上下文隔离"而非事后压缩/检索——从源头上限制哪类信息能进入决策上下文，与现有方法形成根本性区别。
- **无需训练、即插即用**：包装冻结的基础 LLM，无额外训练成本，实用性强。
- **记忆设计的精细化**：三种记忆分工明确（情景/工作/工具），不对称注入策略合理——执行器只需要工具记忆，规划层获得完整任务状态。
- **性能-资源权衡优越**：高收益并非来自无限上下文或过度工具调用，实验证明资源消耗在可比范围内。
- **上下文增长分析有说服力**：HyMem-Planner 与 HyMem-Total 曲线分离直观展示了隔离机制的实际效果。

## 8. 不足与局限

- **跨骨干泛化不足**：Qwen3-32B 在 Browsecomp-plus 上 HyMem 未超过 ReAct；作者承认鲁棒性"promising but not uniform"，说明框架对弱指令遵循模型的收益不稳定。
- **评估覆盖有限**：Browsecomp-plus 仅 150 题抽样；GAIA 仅文本类任务，未验证多模态场景；数据集覆盖面限制了结论的一般性。
- **辅助模型引入潜在偏差**：所有辅助语言任务统一用 DeepSeek-V4，辅助模型与骨干 DeepSeek-V4 同源，可能高估在该骨干上的效果，而对 Qwen3-32B 的辅助质量差异未做控制。
- **无算力数据披露**：未给出 GPU 型号/数量/推理耗时等硬件资源细节，无法评估实际部署成本。
